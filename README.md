# 班底

**把活派给 AI 数字员工，看它干，随时接管。**

本仓库正在从「班底方法论 + 编辑器插件」转向「班底平台」——一个可自托管的多 agent 协作产品。
**主体功能以本文件为准**，不走任务卡与版本台账那套重流程。

## 主体功能

只做这四条，做完就能用：

1. **集成 agent CLI** —— 第一版接 **Codex**（`codex exec --json`），dsh 作为第二个适配器并存。
   两个适配器输出**同一套事件词汇**，上层不关心底层是哪个 CLI。
2. **创建数字员工** —— 一个数字员工 = 名字 ＋ 职责指令 ＋ 绑定的 runtime ＋ 权限（沙箱模式）＋ 工作目录。
3. **和数字员工对话** —— 一条消息一次进程调用；从事件流里取回会话 id，下一句带回去就续上了。
4. **会话即工作项** —— 每个会话有标题、状态（待跑／跑中／完成／失败）和完整事件流。这是产品的骨架。

## 这一版不做

移动端、IM 集成、多租户、权限矩阵、成本分析、逐 token 打字机。

**中途递话**这一版也不做——但性质变了：Codex 有 `codex queue --thread <id> --message <text>`，
能给正在跑的会话递话；dsh headless 没这个能力（每次调用只跑一个任务）。
所以这是**排期问题，不是能力问题**，接口先按"排队式"设计，留出递话的位置。

## 怎么算做完了

一条可复现的链路，不靠感觉。两个 runtime 都已实测通过：

```sh
# Codex：新会话 + 续接
codex exec --json -C <项目目录> -s read-only -          # 退出码 0，事件流含 item.completed / turn.completed
codex exec resume <thread_id> --json -                  # 同一 thread，上下文还在

# dsh：同样的两件事
dsh --profile headless --json -                         # session 事件给出 sessionId
dsh --profile headless --json --session-id <id> -       # turn 变成 2
```

**平台的验收 = 在界面上点出同一件事，落进同一份事件流。**

## 统一事件词汇

两个适配器都产出这套，前端只认这一套：

| 事件 | 含义 |
| --- | --- |
| `session` | 本次运行的会话标识（Codex 的 thread_id／dsh 的 sessionId） |
| `status` | `turn_start` / `step_start` / `step_end` / `turn_end`（带 usage） |
| `thinking` | 推理文本 |
| `text` | 助手正式回复 |
| `tool` | 工具动作（命令执行、文件改动、MCP 调用…） |
| `error` | 失败 |
| `final` | 最终答案 |

## 技术选型

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 执行端 | 子进程拉起 `codex exec --json` / `dsh --profile headless --json`，读 stdout 的按行 JSON | 两个 CLI 都自带一次性模式，自行退出 |
| 服务端 | 一个薄 Node 进程：`node:http` ＋ SSE | **零依赖**，一个人能维护 |
| 存储 | `node:sqlite`（Node 22 内置） | 零依赖、零运维；权威进度仍留在各项目仓库。**暂不换库**，但 SQL 要先收口（见 [形态决策](docs/形态决策.md) §十二） |
| 前端 | 一张静态页（先不引构建工具） | 保住零依赖；形态定了之后的结论是**不换框架** —— 真要动就拆 ES 模块，别上打包器（§十二） |
| 数据落点 | `BANDI_DATA`；不设仍是 `<仓库>/data` | **已可指**（2026-10-15）。桌面壳设成用户目录、systemd 设成 `/var/lib/bandi`。刻意**不做**「写不进去就自动换家」的兜底 —— 那会在权限抖动时悄悄换成空库（§十二） |
| 远程访问 | `BANDI_HOST` ＋ `BANDI_ORIGINS`；**默认只听本机** | 监听非回环就**自动开访问令牌**（2026-10-15）；不配来源的话远端浏览器**能看不能动**（§十二） |
| 客户端 | 薄壳：Tauri ＋ 拉起本地控制面，窗口指向它 | **已落地**：`apps/desktop/src/shell.rs` ＋ `apps/desktop/shell.mjs`；**安装包也能出了**（2026-10-15 实测 22 MB、自带 Node 运行时，见 `apps/desktop/README.md`） |

目录：`apps/server`、`apps/web`、`apps/desktop`（Tauri 壳）。

**形态已定（2026-10-15）**：**托管控制面 ＋ 客户端出站节点**。桌面客户端是形态，web 只是界面；单机零外部依赖（控制面就地在本地跑）。"关掉浏览器会不会挂"不成立——干活的是客户端里的节点进程。详见 [形态决策](docs/形态决策.md)。

## 两个适配器的已知不对称

- **Codex**：`exec` 收 `-C <目录>` 与 `-s <沙箱模式>`；但 `exec resume <id>` **两个都不收**，
  续接靠进程 cwd 与会话记录。另外 `-p <name>` 可叠加 `$CODEX_HOME/<name>.config.toml`，
  正好可以当"员工配置层"。`codex queue` 可给运行中的会话递话。会话按 cwd 过滤（`--all` 可关）。
- **dsh**：CLI 不在 PATH 上，真实做法是 `ELECTRON_RUN_AS_NODE=1` 起 Electron 可执行文件再跑
  `app.asar` 里的 `cli.js`；`.cmd` 过 shell 有引号坑，所以直接起 exe ＋ 参数数组。
  班底只把**模型名**用 `--patch` 传下去；走哪条地址、带谁的 Key 由 profile 自己的配置决定
  （凭据由 dsh 从 `$DSH_HOME/.env` 读，班底不注入）。
  ⚠️ 补丁层是**整块替换 `config`**、不是逐字段合并 —— 只写 `model` 会把 profile 里的
  `provider:` 一起冲掉，所以那一行必须原样读回来再写回去。

- **桌面版自己挑端口**（2026-10-15）：命令行的 8787 是**给人用的约定**（他要知道去哪儿开浏览器），
  桌面版没这个约定 —— 它从 8787 往上挑：空着就用、是我们自己的就**复用**、是**别人的程序就跳过**，
  选中的记进数据目录（`port`），下次据此复用**自己**那个。
  硬编码端口的桌面版，在"用户机器上恰好有别的程序占着"时只剩一张错误页。
  实测：占用 8821 → 它跳到 8822 起，**没碰别人的进程**；再开一个壳 → 复用 8822 且退出不停它。
- **暂不动**：旧账本（`.bandi/`、`docs/项目文档-by班底/`）——与现实已不符，等主人拍板。
  ⚠️ `docs/项目文档-by班底/` **未随公开仓库发布**（见 `.gitignore`），所以公开仓库里
  `.bandi/status.yaml` 的 `doc_index` 指向的都是死链 —— 那份账本只对本机有意义。

## 技能与契约（2026-10-14 起，2026-10-16 收拾过一轮）

编排不再是技能——谁上场、下一步去哪、干完停不停，由**流程引擎**做（模板 + 实例）：

- `bandi-flow` 从「总编排」瘦身为**门禁与纪律**：三道门禁的判据、数字纪律、汇报口径，加平台没有的那一维（排期与跨项目优先级）。它**不推流程**；**节点上只有点名（`personaId`），没有"技能"这一维**——引擎不按技能找人，点了名就派给那个人，没点名到站即「已阻塞」等人指派。
- 四个角色技能只做**本步的活**：产出文档、把结论交回会话。**不再改 `status.yaml` 的 `tasks` 状态**（老账本那段作废），路径也从 `doc_index` 读、不再写死。
- 契约**只有一份**（`skills/bandi-flow/references/契约.md`，随平台走）：进度真相 = **流程实例**；`status.yaml` 只留版本台账（`versions`，面板读它）与文档入口（`doc_index`）。`stage` / `tasks` 是历史遗留，不许再维护。**2026-10-16 取消了"一份母本 + 每个项目一份副本"**——那份散在各项目里的 `.bandi/README.md` 不再发，项目里只留 `status.yaml` 与文档本身。

**2026-10-16 收拾的那一轮**（起因：技能与契约都是流程之前写的，分层没跟上）：

- **内建模板改名 `bandi-flow` → `bandi-delivery`**：模板 id 跟技能名撞了，人和模型都分不清。老库里的模板与**实例的 `templateId`** 由 `store.renameWorkflowTemplate` 在启动时一起迁（`smoke-workflows.mjs` ⑧ 钉住）。
- **部署节点补 `manual: true`**：契约一直写着"部署永远要人下令"，代码里五个节点**一个开关都没有**，跑完会自动流转到结束——文档说的和代码做的相反。现在开关在，而且**开关真的管住自动流转**（同冒烟 ⑨⑩）。
- **角色技能的 `description` 不再绑节点名**（原来写"当流程的『写代码』这一步派给你"——用户自定义模板时就不命中了）；**测试的"有权打回"删掉**：引擎里没有给 agent 的 decide 通道，打回是人在实例页点。
- **机器台账收敛**：地址与账号只留平台登记表（`~/.bandi/servers.yaml` ＋ `ssh` 连接器），项目里的机器清单只记"允许谁用 / 能干什么 / 是否已引导"；以前同一台机器三本账各写一遍。
- **契约去掉人名表**（谁挂哪个能力以平台为准；写进文本里就会过期），并标明「三」「四」「五」「六」讲的是**平台行为**、真源在平台，以平台为准。
- **发布记录只有一个落点**：`.bandi/发布记录/v<版本号>.md`；老项目里 `10-需求/30-发布记录/` 是流程之前的位置，历史文件不动、不再新写。
- **契约不再发副本**：那份"一份母本 + 每个项目一份 `.bandi/README.md`"作废——母本只此一份、随平台走，项目里只留 `status.yaml` 与文档。
- 旧参考 `契约详解.md` **删了**：整篇都是历史，而且通篇用**旧五类编号**，留着只会误导。
- **卸载多了「完全卸载」**（`apps/desktop/installer-hooks.nsh`）：卸载时问一句，选「是」就连数据一起清（库、访问令牌、插件与连接器、机器登记表、开机自启项），**默认不删、静默卸载不删**——用来验证"新机安装"时清出一个干净环境。

## 插件机制的一处扩展（2026-10-14）

声明式 `table` 块支持给列写 `width`（如 `"72px"`）：任意一列写了，整张表切
`table-layout: fixed`，没写的列平分剩下的。起因是 `auto` 布局下中文**每个字都能断行**，
「要点」「证据」这种长文本列会把「编号」「状态」压到一两个字宽——`T-001` 断成两行、
`待部署` 竖排。契约写在 `apps/server/src/plugins.mjs` 的块注释里。

## 版本（2026-10-16 重新定位）

**当前版本 `0.9.0`**，真源唯一：[apps/desktop/version.json](apps/desktop/version.json)。
`build.rs` 读它 → 编译进程序（窗口标题「班底 <版本>」）→ 同步写进 `tauri.conf.json`（安装包名）。
**别在别处记第二个号**；`build.rs` 只认三段数字，`0.9.0-rc.1` 这种后缀会让构建直接失败。

**为什么不是 `1.0.0`**：`1.0.0` 是 2026-10-10 给「插件 → 桌面安装程序」那次形变的号，那一版只做
「外壳 + 打包」与「**SSH 服务器登记**」，而 SSH 优先那条路已经停了（见上「现状」）。按语义化版本，
`0.y.z` = 初始开发期、**不承诺兼容** —— 插件格式、流程模板、`status.yaml` 契约都还在动，所以对外
定位 `0.9.0`，`1.0.0` 留给真正承诺兼容的那天。本文件别处出现的 `1.0.0`（窗口标题、安装包名、
`v1.0.0` 的 B2/B5/B6 那些约束编号）都是**那一版当时的记录**，不是当前版本。

**插件与 MCP 身份是另一套号**：`plugins/*/manifest.json` 与 MCP 的 `serverInfo` / `clientInfo`
里写的 `0.1.0` 是**插件 / MCP 协议身份**，不跟产品版本走 —— 问「现在几版」只看上面那个真源。

历史台账（本仓库自己的 `.bandi/status.yaml`）：`0.1.0` ~ `0.7.0` 是**插件时代**的版本
（最后真正发布过的是 `0.7.0`），`0.8.0` 与 `1.0.0` **从未发布**。
