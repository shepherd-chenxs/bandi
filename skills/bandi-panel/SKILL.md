# 班底 · 项目面板

面板是**平台的一个插件**，不再是独立进程：装在平台里，从 **工作台 → 项目面板** 进（平台地址默认 `http://127.0.0.1:8787/`）。

它回答一件事：**平台纳管的这些项目，各自有哪些版本、每版要做什么、发布记录在哪。**

**任务不在这儿。** 要看"这个项目有哪些活、都什么状态"，走平台的 **项目 → 点一行进详情**（任务看板：流程的每一次办理 + 聊天派活 + 手工建的卡；列头「＋」能就地建任务）。任务挂在项目上、是平台的一等功能，不该只长在插件里——2026-10-14 从本插件搬出去了。

## 什么时候上场

- 用户说「把 xxx 加进面板」「这个项目也纳入面板」
- 用户问「面板里有哪些项目」「现在几个项目了」「各版本到哪一步」「0.7.0 那一版做了什么」
- 用户说「打开面板」「看看面板」
- 用户问「有哪些任务」「哪些活卡住了」→ **不是这个面板**，让他去平台的「项目」页点进去看（或直接读 `GET /api/projects/{id}/tasks`）

## 数据从哪来

两处，都是现读，不缓存第二份：

| 界面上的东西 | 来源 |
| --- | --- |
| 左栏项目清单 | **平台的「项目」账本**（`/api/projects`）——面板不另立登记表 |
| 版本与要点 | 该项目根下的 `.bandi/status.yaml` |

项目根下没有进度文件 → 左栏标「**未纳管 · 找不到 .bandi/status.yaml**」，记录**保留不动、不许自动删**。

## 加一个项目

没有 `bandi-panel projects add` 这种命令了。要加，就把目录登记进平台的项目账本：

- 界面上：平台 →「项目」→ 新建，填名字与项目目录；
- 或 `POST /api/projects`，body `{ "name": "显示名", "root": "E:\\path\\to\\project" }`。

登记的是**目录**，不碰目标项目任何文件。

## 面板上有什么

- **左栏**：项目名 + `已纳管 · N 个版本 · K 个已发布 · 更新 <时间>`；未纳管的就写原因。
- **详情 · 纳管情况**：项目名 / 目录 / 进度文件 / 纳管状态 / 更新时间 / 版本数 / 已发布版本数。
- **详情 · 版本表**：版本 / 主题 / 发布（已发布 · 未发布）/ 发布记录路径 / **这一版要做什么**——摘自 `scope` 指向的版本文档：先取开头那段摘要，再补 `- ` 列表项，最多 6 条，Markdown 标记折成纯文本。

版本文档读不到（比如文档已被归档）时，要点那格写「（文档不存在）」这类原因，**不留空、不编**。

## 硬规矩

- **只读。** 插件的 `permissions` 里只有两个 `GET`：`/api/status/projects`、`/api/status/projects/{id}`，**一个写接口都没有**。（任务看板曾短暂装在这里，2026-10-14 已搬回平台的项目页；本插件不再声明 `/tasks` 权限。）
- **没有部署。** 一键部署、登记部署目标、部署单那一套已退役：要发布就让运维数字员工在会话里做，事件流留证（见 `bandi-ops`）。接口也不提供，不是"藏起来"。
- **没有「版本状态」。** 不出 `stage`、`live_version`，也不做版本进展聚合条；版本只呈现**记录**——版本清单与发布记录，加 `released` 这个事实字段。
- **没有卡片。** 2026-10-14 起接口与界面都不再出卡片（`tasks` / `task_count` / 每版卡数全删了）：卡片的 8 个状态和流程节点是同一件事的两种记账，**流程时代里流程才是唯一真相**（谁在办、走到哪一步看流程实例）。要问「某张卡到哪了」就去看那条流程，不要拿 `status.yaml` 里的旧状态当进度。文件里的 `tasks` 段照旧能解析，只是没有出口。
- **不出项目根。** `scope` 只许是相对项目根的路径，绝对路径与越界路径一律拒绝，并把原因写在格子里——只读不等于可以当任意文件读取器。

## 它在代码里长什么样

| 文件 | 作用 |
| --- | --- |
| `apps/server/catalog/plugins/project-panel/manifest.json` | 插件的市场源（界面全靠声明，不跑插件代码） |
| `plugins/project-panel/` | 装完之后的实体；卸载＝删它 + 删 `data/plugins.json` 里那条 |
| `apps/server/src/status.mjs` | 只读的 `status.yaml` 读取器：解析 / 版本聚合 / 版本文档要点 |
| `apps/server/src/server.mjs` | `GET /api/status/projects`、`GET /api/status/projects/{id}` |
| `apps/server/src/smoke-status.mjs` | 面板读取器的验收：`node apps/server/src/smoke-status.mjs` |

任务看板（不在这里，但顺着找的话）：`apps/server/src/project-tasks.mjs` + `GET /api/projects/{id}/tasks` + `apps/web/app.js` 的 `openProjectDetail()`（平台「项目」页点一行进去的看板）。

装 / 停用 / 卸载：平台 →「设置 → 插件 → 界面插件」，或 `POST /api/plugins/project-panel/install`。
改了市场源之后**要重装**（平台没有「升级」语义，`install` 只在没装过时拷贝）。
