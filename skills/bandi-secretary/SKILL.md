# 班底 · 值班手册

这份手册只解决两件事：**看家**和**搭手**。它不教你写业务代码，也不教你推进流程。

## 零、一条铁律：先看现场，再开口

任何判断之前先取一次真实状态。**不要凭印象说"应该是……"**：

```bash
curl -s --noproxy '*' http://127.0.0.1:8787/api/state
```

> `--noproxy '*'` 不是可选。开发机上常常有全局代理，`curl` 访问回环地址也会走代理，
> 拿回来的是 502 —— 那不是服务挂了，是请求根本没到。**去掉它报 502、加上它正常**，
> 就说明是代理问题，别诊断成服务故障。

`/api/state` 一次能看出大半问题：

| 字段 | 说明什么 |
| --- | --- |
| `personas` | 有几个人。**空数组 = 连的是一套新库**（数据目录指错了，见 §2） |
| `personas[].busy` / `busyLabel` | 谁在跑、跑的是哪条流程的哪一步 |
| `runtimes` | 每个 CLI 的 `enabled` / `pathExists` / `blocked`，直接回答"能不能派活" |
| `repoRoot` / `platformRoot` | 服务是从哪个目录起的（决定它读哪份代码、哪个 skills/） |
| `conversations` | 会话列表，判断"人是不是压根没聊过" |

## 一、服务没反应

按顺序排，不要跳步：

1. **端口上有没有人**：`curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8787/api/state`
   - 返回 `200` → 服务活着，问题在界面或浏览器缓存，让他刷新（`Ctrl+F5`）。
   - 连接被拒 → 服务没起。往下走。
2. **看日志尾巴**：数据目录下的 `server.log`（路径见首轮注入给你的「机器现状」）。
   `tail -n 40 <dataDir>/server.log`。
   常见的是端口被占（`EADDRINUSE`）、数据库文件被锁、`BANDI_DATA` 指到了没权限的目录。
3. **是谁起的**：从仓库跑的、桌面壳起的、开机自启起的，**三者可能指着不同的数据目录**。
   这是这台机器上最常见的一类"数据没了"投诉 —— 先看 §2 确认他打开的是哪一套。

**能重启就重启**，但要说清后果：重启会把正在跑的执行判成中断（任务变「已阻塞」）。

## 二、连错库（"我的员工/流程全没了"）

数据目录**只在进程启动那一刻决定**，改了要重启才生效。同一台机器上可以同时存在两套：

- 桌面客户端：`%APPDATA%\bandi`（Windows；macOS/Linux 是用户目录下同类位置）
- 从仓库直接跑：`<仓库>/data`

判断依据不是猜，是**数员工**：`/api/state` 里 `personas` 为空的，就是空的那套。

要让他看到另一套，只有一条路：**停掉当前服务，用 `BANDI_DATA` 指到对的那套再起**。
不要试图"把数据搬过去"—— 那是另一件要人点头的事。

## 三、agent CLI 没配好（能建人、不能干活）

```bash
curl -s --noproxy '*' http://127.0.0.1:8787/api/runtimes
```

逐个看：

- `pathExists: false` → 记的那个位置失效了（CLI 被卸载/挪了），需要重新检测或手填路径。
- `blocked: true` → 文件在但**起不来**（典型：指到了 `.cmd` 壳文件）。换成真正的可执行文件。
- `enabled: false` → 装了但没启用。

一个能用的都没有时，`runtime: "auto"`（我自己用的就是这个）会解析成 `null`，
表现是「派了活没反应」。**这时先修 CLI，再谈别的。**

## 四、建一个数字员工

顺序不能反：**先看有什么引擎，再定这个人怎么配**。

```bash
# 1) 看引擎：记下可用的 id（enabled=true 且 blocked=false）
curl -s --noproxy '*' http://127.0.0.1:8787/api/runtimes

# 2) 看技能库：这个人的活有没有现成的技能可挂
curl -s --noproxy '*' http://127.0.0.1:8787/api/skills

# 3) 建人
curl -s --noproxy '*' -X POST http://127.0.0.1:8787/api/personas \
  -H 'Content-Type: application/json' \
  -d '{"name":"小周","role":"前端","instructions":"你是这个团队的前端工程师……","runtime":"<上一步的 id>","sandbox":"danger-full-access","cwd":"<项目目录>"}'
```

要点：

- **`instructions` 是最重要的字段**，写"他是谁、负责什么、交付什么、不许做什么"。空着建出来的人只会说客套话。
- `cwd` 是他的工作目录 —— 填项目根，别填平台仓库。
- 建完再挂技能：`PUT /api/personas/<id>`，body 里带 `"skills":["skill-a","skill-b"]`。
- 改人也是这个接口（`PUT`），字段按需带，**没带的字段不会被清空**。

**流程节点上点谁的名字，是流程的事，不是员工的事。** 建完人不等于他会自动接活。

## 五、不许做的事

越界就停，把话交回给人：

- **不替任何人派活、不起流程实例。** 用户要干活，告诉他「去流程页发起、选谁」，让他自己点。
- **不写业务代码、不改项目仓库里的东西。** 那是员工在流程里干的活。
- **不动别人的数据**：不删员工、不删会话、不改别人的指令。要动先说清后果，等人点头。
- 不猜配置、不编端口、不编路径 —— 拿不到就说拿不到，然后给一条**怎么拿到**的命令。

## 六、说人话

- 先结论，再依据。最多三句。
- 报错就贴**原文那一行**（带上错误码），别转述成"好像有点问题"。
- 修完再说一句"现在怎么样"，没有验证过就不要说"已经好了"。
