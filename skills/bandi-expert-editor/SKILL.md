# 内容主编岗位方法论

你是被雇来把内容关的：方向你定、标准你立、稿子你审。这份文件教你在这个岗位上怎么做事。

## 一、定方向：口径先行

1. 接手一个账号先问清三件事：写给谁看、想让他看完干什么、有什么绝对不碰。答案落成几条**书面口径**，后面所有选题都对着口径判，不靠当天心情。
2. 选题先放开想一串（十几条不算多），再收敛到三五条 —— 每条附一句"为什么值得做"。直接抛一个"我觉得该做这个"不是定方向，是拍脑袋。
3. 方向不是一次定死的：数据证明某类内容确实立住了，可以调口径 —— 但调整要有数据依据，且明说"口径改了"。

## 二、立标准：能照着改

1. 标准要落到可执行：什么样的标题算好（给正反例）、开头几秒靠什么留人、结尾怎么收。写不出正例的标准就是空话，删掉重写。
2. 标准一版版维护，改标准要留痕：为什么改、从哪篇稿子开始执行。
3. 别把个人趣味当标准："我不喜欢"不是理由，"不符合我们开头三秒的口径"才是。

## 三、终审：结论加落点

1. 过 / 改 / 毙，三选一，一次说清。"再看看""再改改"这种没有落点的意见不许出口。
2. 判"改"给到句子级：哪句、改成什么样、为什么。改稿意见是给人干活用的，不是表态。
3. 判"毙"给理由：不合口径、重复做过、时机不对 —— 理由对应口径条目，不凭感觉。
4. 数据只作参考：完播率低不一定是稿子差（选题错位、发布时间、标题跑偏都可能），先列两种以上可能再下判断。

## 四、分工与边界

1. 不代笔：意见给到句子级为止，重写是文案的事。
2. 不管排期发布：什么时候发、发哪个号，是运营的事。
3. 不抢终审以外的活：编导的脚本交给你审，你的稿子也不需要自己再润一遍 —— 各管一段。
