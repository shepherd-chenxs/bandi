哪部分用 iOS，
哪部分用密排风格 （已作废）

上一页留下的那句「最好的答案不是二选一」，这里把它落到每个页面。 当时的结论是：人和人说话的地方用 iOS，人和系统打交道的地方用密排风格。

本文 2026-10-19 作废。 混用方案做出来（第 3 步：消息 / 通讯录 / 工作台）之后，用户看截图否掉了它 —— 同一个软件里两套圆角、两套分层方式，切页面要重新认一遍“这是什么”，比风格单调更糟。 最终决定：全站统一密排风格。iOS 语汇已全部撤回（彩色气泡 → 无气泡、 浮起卡片 → 同底 + 1px 细线、工作台宫格 → 行式列表）。 下面保留原始论证，只作决策记录，不要照它实现。

对话区走 iOS —— 班底的主界面就是对话，而对话正是 iOS 语汇最成熟的地方： 气泡、头像、时间、输入条。这块照 iOS 做，用户第一天就觉得「顺手」。

所有"干活的地面"走密排风格 —— 看板、列表、设置、运行日志、流程编排。 这些页面要在一屏里塞几十条信息，iOS 那种大留白会把密度吃掉。

两套不是两套代码：共享一份 token 层，只在组件层分家（见第 03 节）。

01 为什么是这个切法

不是喜好问题，是这两个语汇各自被优化过的东西不一样。

iOS 被优化的是「读得下去」

  • 气泡是最省脑的对话形式：一眼看出谁说的、说到哪儿了
  • 大留白 + 少分割线 → 注意力集中在内容本身
  • 圆角、软色块 → 降低长期停留的压迫感
  • 代价：同样一屏，能摆的信息不到密排风格的一半

密排风格 被优化的是「扫得快」

  • 10 档灰阶把层级压平，眼睛靠明度而不是框线定位
  • 1px 细线、几乎无阴影 → 一屏能摆 30 个条目还不乱
  • 只在"当前选中"放一处亮色 → 视线有唯一落点
  • 代价：偏冷、偏紧，长时间读对话会觉得挤
班底的特殊之处：市面上的工具大多是"要么 IM 要么项目管理"，所以只能选一边。 班底是「和数字员工一起干活」—— 四个一级页面里，一个纯对话、三个纯"干活的地面"， 正好各归一边，不用妥协。这也解释了为什么二选一都是错的。

03 一套 token，一个组件层

现有 CSS 已经是变量驱动的，这是最大的资产 —— 改造不用推倒重来。

第 1 层 · token（两套共用）

  • 语义变量名不变：--bg --side --panel --line --text --dim --accent
  • 只换值，不新增第二套命名（--ios-bg 这种一律不要）
  • 深 / 浅各一份 —— 现在 :root + :root[data-theme='light'] 的结构正好
  • 状态色（待办 / 待人确认 / 失败）两套都要，且语义同名同色

第 2 层 · 组件（最终只有密排风格一套）

  • iOS 一套：.ios-row .ios-card .ios-bubble .ios-nav（已撤回）
  • 密排风格一套：.ln-row .ln-card .ln-col .ln-field
  • 页面 div 上挂 data-skin="ios" / data-skin="linear"（未落地）
  • 只覆盖 圆角 / 间距 / 阴影 / 分隔线样式 四样，不覆盖颜色
⚠️ 这一节作废（2026-10-19 用户拍板「全部密排风格」） 下面说的“按页面分皮肤”最终没有落地：先把 iOS 那套做出来（第 3 步）之后， 用户看截图否掉了混用方案，改为全站统一密排风格。实际做法是直接改各组件、 一个组件一个提交（好 revert），并没有 data-skin 这层机制。 iOS 语汇（彩色气泡、浮起卡片、18px 气泡圆角、工作台宫格）已全部撤回。
为什么按"页面"分皮肤，而不是按"主题"分？ 如果做成两套可选主题，等于维护两套完整样式表（现在 1912 行的两倍）， 而且用户切换后还得重新认路。按页面分，每个页面只学到一种形态，认知负担为零。
约 90 行作用域覆盖就能分家： [data-skin="ios"] { --radius-lg: 16px; --gap-row: 10px; --shadow-card: 0 1px 3px rgba(0,0,0,.06); }
[data-skin="linear"] { --radius-lg: 7px; --gap-row: 2px; --shadow-card: none; }
组件的其它规则一行不动 —— 因为它们读的都是变量。

05 只剩三件事要你定

其余我都按上面的切法往下推。这三件会明显改变观感，不替你决定。

实际结论（2026-10-19）：三件都定了 —— 强调色留 iOS 蓝（不是密排风格那种靛蓝，蓝压深底更清晰）； 深色底全部用 #08090a（消息页也放弃了纯黑，纯黑上分层只能靠阴影，而密排风格不靠阴影）； 侧栏留。下面这表只作决策记录。
问题我的建议另一条路
强调色用哪个？ iOS 蓝。浅色用 #0071E3（白字 4.70:1，过 AA），深色用 #0A84FF。 苹果原色 #007AFF 实测只有 4.02:1，白字不够。 密排风格靛蓝 #5E6AD2 —— 更"工具"，但浅色消息页里偏暗，气泡会显旧。
深色底用哪个？ 消息页纯黑 #000（iOS 深色），其它页 #08090a（密排风格）。 全部纯黑 —— 最像手机，但看板在纯黑上卡片分层几乎看不出来。
侧栏留不留？ 留。三栏是班底的信息架构（图标栏 / 会话 / 对话），去掉要重排所有页面。 收成两栏 —— 那是 v1.1 的事，不是这次。
实测数据（写脚本算的，不是估的）： 白字压 #007AFF = 4.02:1（没到 AA），压 #0071E3 = 4.70:1（过了）—— 所以浅色主题的主按钮要用后者，苹果原色只留给图标和小色块（那里不靠对比度辨读）。 深色下 #0A84FF 反而更亮，白字没问题。
一条我不同意自己的地方：这页开头说"对话走 iOS"，但如果深色底用纯黑， 消息页和看板页切换时会有一次明显的底色跳变。所以第 05 节第 2 条给了折中： 消息页纯黑、其余 #08090a —— 两者亮度差约 3%，肉眼几乎看不出跳动，但各有各的好处。
