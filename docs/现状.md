## 二、流程引擎与技能契约

编排不再是技能——谁上场、下一步去哪、干完停不停，由**流程引擎**做（模板 + 实例）：

- `bandi-flow` 从「总编排」瘦身为**门禁与纪律**：三道门禁的判据、数字纪律、汇报口径，加平台没有的那一维（排期与跨项目优先级）。它**不推流程**；**节点上只有点名（`personaId`），没有"技能"这一维**——引擎不按技能找人，点了名就派给那个人，没点名到站即「已阻塞」等人指派。
- 四个角色技能只做**本步的活**：产出文档、把结论交回会话。**不再改 `status.yaml` 的 `tasks` 状态**（老账本那段作废），路径也从 `doc_index` 读、不再写死。
- 契约**只有一份**（`skills/bandi-flow/references/契约.md`，随平台走）：进度真相 = **流程实例**；`status.yaml` 只留版本台账（`versions`，面板读它）与文档入口（`doc_index`）。`stage` / `tasks` 是历史遗留，不许再维护。**2026-10-16 取消了"一份母本 + 每个项目一份副本"**——那份散在各项目里的 `.bandi/README.md` 不再发，项目里只留 `status.yaml` 与文档本身。

**2026-10-16 收拾的那一轮**（起因：技能与契约都是流程之前写的，分层没跟上）：

- **内建模板改名 `bandi-flow` → `bandi-delivery`**：模板 id 跟技能名撞了，人和模型都分不清。老库里的模板与**实例的 `templateId`** 由 `store.renameWorkflowTemplate` 在启动时一起迁（`smoke-workflows.mjs` ⑧ 钉住）。
- **部署节点补 `manual: true`**：契约一直写着"部署永远要人下令"，代码里五个节点**一个开关都没有**，跑完会自动流转到结束——文档说的和代码做的相反。现在开关在，而且**开关真的管住自动流转**（同冒烟 ⑨⑩）。
- **角色技能的 `description` 不再绑节点名**（原来写"当流程的『写代码』这一步派给你"——用户自定义模板时就不命中了）；**测试的"有权打回"删掉**：引擎里没有给 agent 的 decide 通道，打回是人在实例页点。
- **机器台账收敛**：地址与账号只留平台登记表（`~/.bandi/servers.yaml` ＋ `ssh` 连接器），项目里的机器清单只记"允许谁用 / 能干什么 / 是否已引导"；以前同一台机器三本账各写一遍。
- **契约去掉人名表**（谁挂哪个能力以平台为准；写进文本里就会过期），并标明「三」「四」「五」「六」讲的是**平台行为**、真源在平台，以平台为准。
- **发布记录只有一个落点**：`.bandi/发布记录/v<版本号>.md`；老项目里 `10-需求/30-发布记录/` 是流程之前的位置，历史文件不动、不再新写。
- **契约不再发副本**：那份"一份母本 + 每个项目一份 `.bandi/README.md`"作废——母本只此一份、随平台走，项目里只留 `status.yaml` 与文档。
- 旧参考 `契约详解.md` **删了**：整篇都是历史，而且通篇用**旧五类编号**，留着只会误导。

## 三、项目、看板与面板

- **已装插件**：**项目面板**（市场源 `apps/server/catalog/plugins/project-panel/`）。
  只读看多项目的**版本记录**：数据现读各项目根下的 `.bandi/status.yaml`，
  接口是 `/api/status/projects`、`/api/status/projects/{id}`，`permissions` 里只有 GET。
  **卡片已从面板删掉**（2026-10-14）：卡片的 8 个状态与流程节点是同一件事的两种记账，
  以前靠 skill 维护 YAML，现在进度以**流程实例**为准（`workflow_runs` / `workflow_tasks`，
  按 `projectId` 挂项目）——两套并存只会打架。`status.yaml` 的 `tasks` 段照旧可解析，
  但接口与界面都不再输出；面板只剩版本清单、每版要做什么、发布记录。
- **项目页有任务看板**（平台一等功能，不是插件）：**项目 → 点一行进详情**，
  看板列 = 状态，从左到右按生命周期（待办 / 进行中 / 待人确认 / 停下等人 / 失败 / 已完成），
  卡片三种来源：**流程的每一次办理**、**聊天派活**、**手动建的任务**（单独标出来、写明执行人），
  点流程卡进那条实例、点聊天/手工卡进那个会话。
  列头的 **「＋」** 在这一列手工建任务（参照 Multica）：标题/描述/状态/执行人，
  选了执行人可勾「创建后立即开始工作」——那会真的派活（发到他的会话，工作目录是这个项目）。
  手工卡可以**拖到别的列改状态**、点 **×** 删掉；流程与聊天的卡状态归平台管，拖不动。
  头上有**「筛选」**（2026-10-15，形状照 Linear 那张）：先做了**状态**一维 —— 只画勾中的状态，
  整列都不匹配就不显示那一列，列内卡片跟着筛；按钮上带选中的个数、旁边写「显示 N / 共 M」，
  弹层里挂「清除」。**两块看板共用这一套**（筛选状态存在前端 `S.kbFilter`，切页面/刷新重画都不丢；
  状态词从数据里现取，不写死 —— 流程六态 / 聊天四态都在长），纯逻辑能单跑（`tmp/kb-filter-check.mjs`，本地校验脚本，**不入库**）。
  数据 `GET/POST /api/projects/{id}/tasks`、`PATCH/DELETE /api/projects/tasks/{id}`
  （[project-tasks.mjs](../apps/server/src/project-tasks.mjs)，手工卡存在 `project_tasks` 表），
  界面 `openProjectDetail()` / `taskDialog()`。
  聊天没有"选项目"这一步，所以没挂项目的会话按**执行人的工作目录**归属；流程的活也派进
  经办人的 1:1 会话，判定时必须把流程轮次剔掉，否则同一件活会被算两遍。
  旧面板的运维（一键部署、登记部署目标）与「版本状态」**没有搬**，随后跟归档的旧插件一起删掉了（`_archive/` 未随公开仓库发布）——现在是「要发布就让运维在会话里做」。
- **工作台有全局任务看板**（2026-10-15）：入口是**工作台 → 项目**右边那颗「任务看板」。
  它跟项目详情那张看板是**同一个机制**，只换范围：服务端 `projectTasks` 与 `allTasks` 共用
  `board()`（行怎么算、列怎么分、数字怎么数都只有一处），界面共用 `kbColumn` / `kbCard` / `wireBoard`。
  数据 `GET /api/tasks`，界面 `openTaskBoard()`。
  全局比项目看板多两件事：卡片上多一枚**「哪个项目」**的标签；**没挂项目的活也收** ——
  流程实例没挂项目的、会话没挂项目又不在任何项目目录下的，都归到「（未归属）」，
  那些活在项目看板里根本看不见（真实数据里这种活不少）。
  聊天行**按会话算、不按项目算**，所以全局里同一场对话只有一张卡（不会因为归属算两遍而重复）。
  列头的「＋」在全局面板要先选项目（手工卡必须挂在某个项目下），右侧那栏**按项目分堆**
  （件数 + 停/待确认/失败），点一行就钻进那个项目的看板。

## 四、多机器：节点、机器名、自启、鉴权

- **能接别的机器了（第二步：领活）**（2026-10-15）：**多台电脑一起干活**这条通了。
  控制面**不 push、不开端口** —— 节点**长轮询**领活（挂 20 秒，有活立刻回），在本机起 agent CLI
  （复用同一套适配器），事件**批量回传**、最后报回执；界面看到的实时流就是已经做好的 `run_events`。
  派活就是**员工绑那个运行时的 id**（`node-xxx:codex`，下拉里带机器名），不用另造一套"指派机器"。
  **离线排队**是队列的默认状态：那台机器不在线，活就躺着等它上线自己领走。
  **停止**走反向通道：事件批次的响应里带回 `stop`，节点掐子进程；节点每 2 秒发一个**空批次心跳**，
  所以它一声不吭时也掐得掉。节点掉线由清扫判**中断**（没开张的活则放回队列）。
  `node apps/server/src/smoke-node-jobs.mjs`（24 项，真起控制面 + 真起节点 + 一个确定性假 CLI）。
  **实测跨机走通**：控制面在火山那台，节点在我这台 Windows —— 公网派一句话，活在本机跑完、结果回到公网。
  ⚠️ 已知边界：工作目录是**那台机器上的事实**，两边路径不一样就会明确失败（不做悄悄换目录）；
  排队会**一直等**那台机器回来，要撤就点停止。
- **机器名与主机名分开**（2026-10-16）：设备详情页多了「重命名机器」。大标题是**人给它的名字**
  （如「我的笔记本」），下面小字回**真实主机名**（`DESKTOP-XXXXXXX`）—— 两台机器同名时才分得清谁是谁。
  要紧的是这条：**名字能挺住那台机器的下次报到**（它每次报到都会带自己的主机名上来）。
  所以 `nodes` 表把 `hostname` 与 `label` 分开存，`renamed = 1` 时只更新主机名、不动名字；
  本机那份存在 `runtimes.json` 的 `devices.local.label`。传空 = 恢复成主机名。
  连带好处：运行时在员工下拉里的显示名也跟着变（`Codex CLI（备用机·杭州）`）——
  不改名的话两台机器的条目都叫「Codex CLI」，根本分不出活会落到哪台。
  验收：`node apps/server/src/smoke-node.mjs` 的 ②b（8 项，含"重新报到之后名字还在"）。
- **节点页也有「已安装 / 未安装」**（2026-10-16）：远程节点详情页原来只有一句"一个都没探到"，
  等于**把"该怎么办"藏起来**了 —— 现在按**节点自报的清单**分两段：已装的看着能派活，
  没装的一行一条能直接粘的命令（`npm install -g …`）；dsh 那条在 Linux 上明说"这台机器上装不了"
  （它是 Windows 桌面端自带的 —— 摆一条装不了的命令比不摆更糟）。
  ⚠️ 判断依据是**节点自报**，不是控制面本机的探测：那是两台机器（这条踩过 ——
  云端在 Linux 上，看着笔记本报来的 `D:\…` 全被标成"班底起不来"）。
  另一半：**心跳现在捎带运行时清单** —— 在那台机器上装完 CLI，15 秒内页面自己就变、**不用重启节点**
  （原来只有报到时报，用户看到的是"我明明装了还是没有"）。
- **开机自启成了自带功能**（2026-10-16）：`node apps/server/src/autostart.mjs install|remove|status`。
  Linux 走 `systemd --user` ＋ `loginctl enable-linger`（**开机不必先登录**，崩了自动重启 ——
  实测 `kill -9` 之后 12 秒自己回来）；Windows 走 Startup 里的 `.vbs`（**隐藏窗口**）＋ 带循环的 `.cmd`；
  macOS 走 launchd。**四个坑**（一台机器两个数据目录、启动脚本重定向撞 `EBUSY`、
  生成的脚本必须纯 ASCII、别用 `Start-Process` 起）写在 [deploy/README.md](../deploy/README.md) 第五之二节。
- **部署前置已就绪**（2026-10-15）：`BANDI_DATA` 可指（7 处派生路径一起跟着走，启动日志会把
  数据目录与库路径打出来）；`BANDI_HOST` ＋ `BANDI_ORIGINS` 可配（默认只听本机；**不配来源的话
  远端浏览器能看不能动**）；`db` 不再导出，**SQL 只剩 `store.mjs` 一处**。
  产物：`deploy/bandi.service`（systemd）＋ [deploy/README.md](../deploy/README.md)（SSH 隧道访问、
  节点报到、备份与排障）＋ `start-node.cmd`。（**鉴权**见下一条，2026-10-15 已补上。）
- **访问令牌（鉴权）**（2026-10-15）：规则一条 —— **只看监听地址**：
  只监听回环（桌面版/单机）→ **免鉴权**（保住"单机零配置、不要 token"）；监听非回环（服务器）→
  **所有请求都要令牌**。不按"来源是不是回环"判，因为反向代理会把来源变成回环、把闸绕过去。
  令牌首次自动生成在数据目录的 `token` 里（也可用 `BANDI_TOKEN` 指定、不落盘）；
  浏览器填一次记进 HttpOnly Cookie（`EventSource` 没法自己设头，Cookie 是它唯一的活路），
  节点/脚本用 `X-Bandi-Token` 头。**实测已部署到那台火山机器上**：外网不带令牌 401、首页是登录页、
  带令牌 200、令牌错了 401。见 [deploy/README.md](../deploy/README.md) 第六节。

  `frontendDist` 直接指向本地控制面 —— 前端只剩 `apps/web` 一份。
- **桌面薄壳能跑了**（2026-10-15）：`apps/desktop` 从「SSH 服务器登记」重写成薄壳 ——
  **拉起本地控制面 → 窗口指向它 → 退出时收掉"自己起的"那个**（命令行/别人开着的**一个都不动**）。
  那条已停线的五个 Rust 模块（`store`/`guide`/`keys`/`ssh`/`tests`）整体删除，
  顺带卸掉 `russh`/`tokio` 一堆依赖，构建快了一个量级。
  实测：起窗口标题是「班底 <版本>」（当时号 `1.0.0`，见下「七、版本与台账」）、内容就是平台界面；
  **强杀壳进程，它起的控制面自己收掉了**。
- **桌面安装包能出了**（2026-10-15）：`班底_<版本>_x64-setup.exe`（当时号 `1.0.0`，实测 22 MB）。
  **装完即用、自带 Node**（`v1.0.0` 的 B2 满足了）：实测把 `node` 从 PATH 里剥掉再运行装好的应用，
  照样起窗口、控制面用的是**安装目录里那份 `node.exe`**；卸载后目录与注册表都干净。
  **2026-10-16 起卸载器多问一句「要不要连数据一起删」（完全卸载）**——默认不删、静默卸载不删，
  用来清出一个全新环境验证新机安装（见 [apps/desktop/README.md](../apps/desktop/README.md)「卸载」）。
  实现在 [apps/desktop/installer-hooks.nsh](../apps/desktop/installer-hooks.nsh)，选「是」就清掉
  库、访问令牌、插件与连接器、机器登记表、开机自启项（**不动 `~/.ssh` 里的密钥**）。
  **安装包可以从 GitHub Releases 直接下载**：推一个 `v<版本>` tag，Actions 就在 windows runner 上
  打包并把 exe 与 `SHA256SUMS` 挂到 Release（[.github/workflows/release.yml](../.github/workflows/release.yml)；
  tag 必须等于 `apps/desktop/version.json`，不一致 CI 直接失败）。产物**未代码签名**，Windows 会提示
  「未知发布者」，按提示选「仍要运行」。Release 资产名走 ASCII（`bandi_<版本>_x64-setup.exe`）——
  GitHub 会把中文资产名吃掉（实测 `班底_…` 变成 `_…`），装出来的程序仍叫「班底」。
  打包三步（`fetch-node.mjs` → `stage-runtime.mjs` → `npx tauri build`）与几个环境坑
  见 [apps/desktop/README.md](../apps/desktop/README.md)。
- **桌面版自己挑端口**（2026-10-15）：命令行的 8787 是**给人用的约定**（他要知道去哪儿开浏览器），
  桌面版没这个约定 —— 它从 8787 往上挑：空着就用、是我们自己的就**复用**、是**别人的程序就跳过**，
  选中的记进数据目录（`port`），下次据此复用**自己**那个。
  硬编码端口的桌面版，在"用户机器上恰好有别的程序占着"时只剩一张错误页。
  实测：占用 8821 → 它跳到 8822 起，**没碰别人的进程**；再开一个壳 → 复用 8822 且退出不停它。

## 六、插件机制的一处扩展（2026-10-14）

声明式 `table` 块支持给列写 `width`（如 `"72px"`）：任意一列写了，整张表切
`table-layout: fixed`，没写的列平分剩下的。起因是 `auto` 布局下中文**每个字都能断行**，
「要点」「证据」这种长文本列会把「编号」「状态」压到一两个字宽——`T-001` 断成两行、
`待部署` 竖排。契约写在 [apps/server/src/plugins.mjs](../apps/server/src/plugins.mjs) 的块注释里。

## 七、版本与台账

**当前版本 `0.9.0`**，真源唯一：[apps/desktop/version.json](../apps/desktop/version.json)。
`build.rs` 读它 → 编译进程序（窗口标题「班底 <版本>」）→ 同步写进 `tauri.conf.json`（安装包名）。
**别在别处记第二个号**；`build.rs` 只认三段数字，`0.9.0-rc.1` 这种后缀会让构建直接失败。

**为什么不是 `1.0.0`**：`1.0.0` 是 2026-10-10 给「插件 → 桌面安装程序」那次形变的号，那一版只做
「外壳 + 打包」与「**SSH 服务器登记**」，而 SSH 优先那条路已经停了（见上「五、桌面壳与安装包」里的「已停」）。
按语义化版本，`0.y.z` = 初始开发期、**不承诺兼容** —— 插件格式、流程模板、`status.yaml` 契约都还在动，
所以对外定位 `0.9.0`，`1.0.0` 留给真正承诺兼容的那天。本文件别处出现的 `1.0.0`（窗口标题、安装包名、
`v1.0.0` 的 B2/B5/B6 那些约束编号）都是**那一版当时的记录**，不是当前版本。

**插件与 MCP 身份是另一套号**：`plugins/*/manifest.json` 与 MCP 的 `serverInfo` / `clientInfo`
里写的 `0.1.0` 是**插件 / MCP 协议身份**，不跟产品版本走 —— 问「现在几版」只看上面那个真源。

**发版的号从哪来**：改 `apps/desktop/version.json` → 提交 → 打 `v<版本>` tag 推上去，
CI 自动出安装包并挂 Release（tag 与 version.json 不一致会直接失败）。

历史台账（本仓库自己的 `.bandi/status.yaml`）：`0.1.0` ~ `0.7.0` 是**插件时代**的版本
（最后真正发布过的是 `0.7.0`），`0.8.0` 与 `1.0.0` **从未发布**。

## 九、仓库值班（2026-10-17）

外部进来的东西（issue / PR / 评论）要有人看、有人判、有人回。这一版先落**闸门 ＋ 手册 ＋ 台账**三样，
**合并与发布仍然全由人放行**：

- **PR 闸门**（[.github/workflows/pr.yml](../.github/workflows/pr.yml)，windows-latest、只读权限）：
  策略检查 → 语法与配置形状 → 冒烟。**不需要任何凭据、不烧 token、不碰真实数据。**
- **策略检查**（[tools/check-pr.mjs](../tools/check-pr.mjs)）只查机器能一句话判死的四类：
  ① 零依赖铁律（新增 `package.json` / 锁文件 / `node_modules` → 失败）；
  ② 地址白名单（**代码与配置**里新增白名单外域名 → 失败；文档里的只提示）；
  ③ 断言完整性（删整个用例、或删 `check(...)` 断言 → 失败）；
  ④ 需要人看（改 CI 工作流 / 鉴权 / 数据目录 / 打包钩子 → 只标记不拦）。
  "这段逻辑对不对"不在这里判 —— 那留给人和 agent。
- **冒烟清单**（[tools/run-smokes.mjs](../tools/run-smokes.mjs)）：16 个用例共用一份清单，
  **新增了用例却没登记会报错**（不然"新用例从不跑"没人发现）；要真实 CLI / 模型的四个显式排除并写明原因。
- **值班手册**（[skills/bandi-repo/SKILL.md](../skills/bandi-repo/SKILL.md)）：三条铁律、审 PR 五步、
  红线 / 黄线、三类回复模板（值得做 / 不值得做 / 广告）、边界（不改主干、不替人按按钮）。
- **判据台账**（[docs/审阅经验.md](审阅经验.md)）：现象 → 判据 → 处置 → 来源，给下一个 agent 看。
  第一批 9 条，头一条就是下面这个教训。
- **顺带修掉一个真 bug**：`smoke-ssh.mjs` 原来断言本机登记表与 `~/.ssh/*.pub`、还无条件拷贝真账本，
  换台机器必挂（CI 上是在拷贝那步 ENOENT）。现在自带 fixture，真连那半截改成
  `BANDI_SSH_LIVE=<别名>` 显式 opt-in（设了才连真机器）。

- **巡检结果写回看板**（2026-10-17）：`POST /api/projects/{id}/repo-cards`（`key` ＋ `title` ＋ `body`）——
  按 `projectId` ＋ `externalKey` **去重**：同一个 PR 巡检十次只更新标题与描述、**绝不覆盖卡的状态**
  （卡的状态是人给的指令：拖到「已完成」＝ 批准，删掉 ＝ 忽略；把它弹回「待办」是最招人烦的那种 bug）。
  看板上标「仓库值班」（`repo_count` 单列一项），**和手工卡同一族**：能拖、能删。
  本地巡检脚本 [tools/repo-scan.mjs](../tools/repo-scan.mjs)：拉 open PR / issue → 写卡
  （公开仓库不要令牌；`--note` 可以手记一条"卫生"卡）。验收：`smoke-repo-cards.mjs`（18 项）。

**还没做的**（等这版用顺手）：PR 上的自动审查评论（要模型 key 放 GitHub Secrets）；
巡检"自动判断该合该拒"（现在卡上只写"待审 ＋ 该跑什么命令"）；定时（Actions `schedule` 或平台的流程节拍）。

## 十、岗位（2026-10-17）

**一个人"是什么"和"会干什么"是两件事**（用户提的，理由很直给：开发也能挂运维技能、也能干仓库管理员，
但在"写代码"这张卡上，我要找的是**开发**，不该一个个去翻他挂了哪些技能）。

- **数据**：`personas.role`，一个值、可空、自由文本（`ensureColumn`，老库自动补列）。
  **不锁枚举** —— 组织会变（"架构""队长""仓库值班"都可能冒出来），锁死就得改代码。
- **界面**：新建/编辑员工能填（给建议列表 `产品/研发/测试/运维/架构/设计/项目`）；
  通讯录那一行的副标题从 `runtime · sandbox` 换成 `岗位 · runtime`（没填岗位就退回只显示 runtime）；
  员工详情名字旁一枚岗位胶囊；**四处人员下拉**（流程编排节点经办人、实例页改派、任务卡执行人、群助手）
  显示成 `研发 · 波哥`。
- **红线**：**引擎不读岗位** —— 派活仍只认节点上点的名。这条写在契约「十、谁管什么」里，
  并由 [`smoke-personas.mjs`](../apps/server/src/smoke-personas.mjs) 钉住（点名谁就是谁、
  没点名不会按岗位顶人、阻塞原因里也不提岗位）。
- **和技能的分工**：技能＝会干什么（可多、能挂能摘，跟着能力包升级）；岗位＝主职（一个、给人看）。
  两者允许不一致，界面不做校验 —— 不制造第二份真相。


## 十一、代码托管（GitHub 仓库，2026-10-17）

用户：「我想要他这个代码托管的模块，因为我有很多个 git 仓库」。形态**不是**把每个仓库硬变成一个项目，
而是**仓库是一等资源**，项目 / 任务卡引用它。

- **设置 → 代码托管**：填 fine-grained PAT 连接 GitHub（只回显后 4 位）→ 列出账号下的仓库（按最近更新）
  → 挑仓库「接入」＝克隆到 `<数据目录>/repos/<owner>__<name>` → 可「同步」（git pull --ff-only）、
  「建成项目」（项目 root 就是克隆目录）、「移除」（只删记录，本地目录保留）。
- **「怎么拿令牌」这份说明抽成了一份 `GIT_TOKEN_HELP`**，两处共用：没连上时贴在令牌输入框下面，
  连上之后靠「GitHub 连接」标题旁那颗「?」点开（`wireHelpPop`）。
  为什么要那颗「?」（2026-10-17）：连上之后表单就没了 —— 而"给下一个仓库补授权"、
  "令牌 90 天到期要换"恰恰是**连着的时候**才要照着做；没它那段说明就永远看不到了。
  验收：`tools/smoke-help-pop.mjs`（9 项，离线：展开 / 再点收 / 点别处收 / Esc 收 / 点弹出层里不收）。
- **表**：`git_repos`（fullName/owner/name/isPrivate/defaultBranch/localPath/language/addedAt/lastSyncAt）。
  **令牌不进库**：单独一个 `<数据目录>/github-token` 文件（0600 尽力），只在 `git-repos.mjs` 里读写。
- **令牌的用法**：克隆/拉取用 `http.extraheader` 把令牌带在**请求头**里 —— `.git/config` 里不写带令牌的 URL
  （那是最常见的泄漏方式）。
- **agent 的环境隔离**：`git-repos.agentEnv()` 把 `GIT_*` / `GCM_*` / `GH_TOKEN` / `GITHUB_TOKEN` 全删掉，
  强制 `GIT_TERMINAL_PROMPT=0`，三个 adapter（codex / dsh / claude）起进程都改用它。
  说清边界：Windows 凭据管理器是"同用户任何进程都能读"，这只能把最容易的路堵上，**不是完整沙箱**
  （真要隔离得换用户/容器跑）。
- **没做**（第二阶段）：PR 侧栏 / 任务 ↔ PR 自动关联 / 合并后改状态 / Co-authored-by 署名；
  GitHub OAuth 连接（当前用 PAT：多仓库按需授权、权限最小，代价是 90 天要换）。
- 验收：`smoke-git-repos.mjs`（21 项，离线：状态诚实、空令牌 400、令牌不进库不回显、agent 环境被清干净）。

## 十三、数据目录收敛成一个默认（2026-10-18）

复评的起因：命令行默认落 `<仓库>/data`、桌面壳默认落 `%APPDATA%\bandi` —— 同一台机器两个库，
而「开发版别碰真实数据」这条并没有成立（开发壳连的就是真实库）。两个默认是不同时间点各定的，
没有统一原则，只剩「看错库」这一类问题。

- **默认收敛成一个**：`apps/server/src/data-dir.mjs` 的 `userDataDir()`（Windows `%APPDATA%\bandi`、
  macOS `~/Library/Application Support/bandi`、Linux `$XDG_DATA_HOME/bandi`）。命令行（`start.mjs`）、
  桌面壳（`shell.mjs`，开发版/安装版一样）、服务端（`config.mjs`）都 import 它 —— 不再各写一份。
- `<仓库>/data` 仍能用，但只是**显式沙盒**：`BANDI_DATA=<仓库>/data`；测试/临时库同理（smoke 全都这么干）。
- 服务器部署不变：systemd 单元显式 `BANDI_DATA=/var/lib/bandi`。
- 启动日志把数据目录打出来（`start.mjs` 也补了一行），`shell.log` 每次启动第一行就是它 ——「我在看哪个库」不靠猜。
- 验收：`smoke-data-dir.mjs` 加 ⓪ 两项 —— 不设 `BANDI_DATA` 时默认 = 用户目录、且不是 `<仓库>/data`。
