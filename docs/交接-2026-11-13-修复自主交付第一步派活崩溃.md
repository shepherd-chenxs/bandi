# 交接：2026-11-13 修复「完全自主交付」第一步派活崩溃

## 一句话结论

`dispatch.mjs` 里一处**误用**（把 `store.getWorkflowTask(taskId)` 当成"按 id 查"调用，而该函数签名是 `(runId, nodeId, visit)`）让 `nodeId = undefined`；**服务器运行的 Node v22.21.0 的 `node:sqlite` 对 `undefined` 绑定直接抛错**，自主交付流程第一步派活当场失败、写进信箱一条 `WF_FAILED`。已修复并用真实端到端验证通过。

## 根因（完整证据链）

**报错**：`「自主迭代班底项目并排查设计漏洞」自动派活没成功：Provided value cannot be bound to SQLite parameter 2.`

**出错代码**（`apps/server/src/dispatch.mjs` 第 765 行，修复前）：

```js
const workflowTask = opts.taskId ? store.getWorkflowTask(opts.taskId) : null;
```

`store.getWorkflowTask` 的真实签名（`apps/server/src/store/workflows.mjs`）：

```js
export function getWorkflowTask(runId, nodeId, visit = 1)
```

只传一个参数 `opts.taskId`（那是 `workflow_tasks.id`，如 `wt2-78c67d80`）→ `nodeId = undefined` → SQL
`SELECT * FROM workflow_tasks WHERE runId = ? AND nodeId = ? AND visit = ?` 的**第 2 个占位符**绑不上。

**为什么冒烟测试没抓到**（这是最值得记住的一条）：

| 进程 | Node 版本 | `getWorkflowTask(1 个参数)` 的行为 |
|------|-----------|-----------------------------------|
| 桌面壳拉起的服务器（`apps/desktop/target/debug/node.exe`） | **v22.21.0** | **抛** `Provided value cannot be bound to SQLite parameter 2.` |
| 命令行 `node`（fnm 当前版本） | v26.13.0 | 宽松地把 `undefined` 当 `null` 绑定 → 查不到行返回 `null`，**不抛** |

冒烟脚本跑在命令行 Node 上，所以这条误用在 v26 下"只是查不到、合同块少了一段"（静默降级），而在**真实桌面壳的服务器 v22 下当场爆炸**。同一个代码库、同一个库文件，只有运行时版本不同。

**为什么独立复现也是"好"的**：我先用 fnm node 写独立脚本复现，全部成功——一度误判为"服务器进程状态问题"。真正分水岭是发现桌面壳自带 node.exe（v22）并用它复现，立刻百分百复现报错。

## 修复（两个文件）

### 1. `apps/server/src/store/workflows.mjs` —— 新增按主键查

```js
export function getWorkflowTaskById(id) {
  if (!id) return null;
  return db.prepare('SELECT * FROM workflow_tasks WHERE id = ?').get(id) ?? null;
}
```

（`store.mjs` 门面整段转出 `apps/server/src/store/workflows.mjs`，新函数自动透出。）

### 2. `apps/server/src/dispatch.mjs:765` —— 改用正确的函数

```js
const workflowTask = opts.taskId ? store.getWorkflowTaskById(opts.taskId) : null;
```

派活那一刻手上只有 `opts.taskId`（流程引擎带着的那一步标记），没有 runId/nodeId/visit 可拼——按主键查才是对的语义。修复后任务合同块（`taskContractBlock` 的 `workflow.nodeName / visit / detail`）也真正拿到了数据（修复前即使不崩也是 `null`，合同里"流程节点/本步要求"那两行一直在静默缺失）。
