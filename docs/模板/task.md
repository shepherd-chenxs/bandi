# 任务卡的内容格式

> 这**不是每张卡一个文件** —— 任务卡建在**平台看板**上（项目 → 看板，或「定计划」时批量建），
> 下面这些字段写在**卡的描述**里。验收标准只有这一个住处，别的都是引用它。

```markdown
## 对应场景
S1.1、S2.1          ← 指向 spec 里的验收场景编号；来源只有 spec，不在这儿改写

## 要做什么
<边界说清楚：做哪些、明确不做哪些。>

## 验收标准
1. <能执行、能复现的一条；写"怎么验"而不是"感觉对">
2. …

## 验证命令
node tools/run-smokes.mjs        ← 研发自测和测试复现跑的是同一条；写不出命令的标准 = 没想清楚

## 依赖
T-002（没它做不了）/ 无

## 版本
1.3.0                            ← 必填、只能一个值；与 status.yaml 的 versions 对得上
```

## 检查

- 「对应场景」里的每个编号在 spec 里都存在；反过来，spec 里每个场景至少被一张卡覆盖。
- 验收标准逐条能执行；出卡的人自己先过一遍排期门。
- 描述里**不写状态、不写进度** —— 状态是看板的列，进度是流程实例。
