## 主体功能

**主体功能以本文件为准**，不走任务卡与版本台账那套重流程。只做这四条，做完就能用：

1. **集成 agent CLI** —— 第一版接 **Codex**（`codex exec --json`），dsh 作为第二个适配器并存。
   两个适配器输出**同一套事件词汇**，上层不关心底层是哪个 CLI。
2. **创建数字员工** —— 一个数字员工 = 名字 ＋ 职责指令 ＋ 绑定的 runtime ＋ 权限（沙箱模式）＋ 工作目录。
3. **和数字员工对话** —— 一条消息一次进程调用；从事件流里取回会话 id，下一句带回去就续上了。
4. **会话即工作项** —— 每个会话有标题、状态（待跑／跑中／完成／失败）和完整事件流。这是产品的骨架。

**这四条是骨架**。骨架之外后来陆续落地了：流程引擎（模板 ＋ 实例）、项目与任务看板、多台机器一起干活
（节点长轮询领活）、鉴权与开机自启 —— 那些的现状与实测证据在 [现状](现状.md)。

## 这一版不做

移动端、IM 集成、多租户、权限矩阵、成本分析、逐 token 打字机。

**中途递话**这一版也不做——但性质变了：Codex 有 `codex queue --thread <id> --message <text>`，
能给正在跑的会话递话；dsh headless 没这个能力（每次调用只跑一个任务）。
所以这是**排期问题，不是能力问题**，接口先按"排队式"设计，留出递话的位置。

## 怎么算做完了

一条可复现的链路，不靠感觉。两个 runtime 都已实测通过：

```sh
# Codex：新会话 + 续接
codex exec --json -C <项目目录> -s read-only -          # 退出码 0，事件流含 item.completed / turn.completed
codex exec resume <thread_id> --json -                  # 同一 thread，上下文还在

# dsh：同样的两件事
dsh --profile headless --json -                         # session 事件给出 sessionId
dsh --profile headless --json --session-id <id> -       # turn 变成 2
```

**平台的验收 = 在界面上点出同一件事，落进同一份事件流。**

## 统一事件词汇

两个适配器都产出这套，前端只认这一套：

| 事件 | 含义 |
| --- | --- |
| `session` | 本次运行的会话标识（Codex 的 thread_id／dsh 的 sessionId） |
| `status` | `turn_start` / `step_start` / `step_end` / `turn_end`（带 usage） |
| `thinking` | 推理文本 |
| `text` | 助手正式回复 |
| `tool` | 工具动作（命令执行、文件改动、MCP 调用…） |
| `error` | 失败 |
| `final` | 最终答案 |

## 技术选型

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 执行端 | 子进程拉起 `codex exec --json` / `dsh --profile headless --json`，读 stdout 的按行 JSON | 两个 CLI 都自带一次性模式，自行退出 |
| 服务端 | 一个薄 Node 进程：`node:http` ＋ SSE | **零依赖**，一个人能维护 |
| 存储 | `node:sqlite`（Node 22 内置） | 零依赖、零运维；权威进度仍留在各项目仓库。**暂不换库**，但 SQL 要先收口（见 [形态决策](形态决策.md) §十二） |
| 前端 | 一张静态页（先不引构建工具） | 保住零依赖；形态定了之后的结论是**不换框架** —— 真要动就拆 ES 模块，别上打包器（§十二） |
| 数据落点 | `BANDI_DATA`；不设仍是 `<仓库>/data` | **已可指**（2026-10-15）。桌面壳设成用户目录、systemd 设成 `/var/lib/bandi`。刻意**不做**「写不进去就自动换家」的兜底 —— 那会在权限抖动时悄悄换成空库（§十二） |
| 远程访问 | `BANDI_HOST` ＋ `BANDI_ORIGINS`；**默认只听本机** | 监听非回环就**自动开访问令牌**（2026-10-15）；不配来源的话远端浏览器**能看不能动**（§十二） |
| 客户端 | 薄壳：Tauri ＋ 拉起本地控制面，窗口指向它 | **已落地**：`apps/desktop/src/shell.rs` ＋ `apps/desktop/shell.mjs`；**安装包也能出了**（2026-10-15 实测 22 MB、自带 Node 运行时，见 [apps/desktop/README.md](../apps/desktop/README.md)） |

目录：`apps/server`、`apps/web`、`apps/desktop`（Tauri 壳）。

**形态已定（2026-10-15）**：**托管控制面 ＋ 客户端出站节点**。桌面客户端是形态，web 只是界面；
单机零外部依赖（控制面就地在本地跑）。"关掉浏览器会不会挂"不成立——干活的是客户端里的节点进程。
详见 [形态决策](形态决策.md)。

## 两个适配器的已知不对称

- **Codex**：`exec` 收 `-C <目录>` 与 `-s <沙箱模式>`；但 `exec resume <id>` **两个都不收**，
  续接靠进程 cwd 与会话记录。另外 `-p <name>` 可叠加 `$CODEX_HOME/<name>.config.toml`，
  正好可以当"员工配置层"。`codex queue` 可给运行中的会话递话。会话按 cwd 过滤（`--all` 可关）。
- **dsh**：CLI 不在 PATH 上，真实做法是 `ELECTRON_RUN_AS_NODE=1` 起 Electron 可执行文件再跑
  `app.asar` 里的 `cli.js`；`.cmd` 过 shell 有引号坑，所以直接起 exe ＋ 参数数组。
  班底只把**模型名**用 `--patch` 传下去；走哪条地址、带谁的 Key 由 profile 自己的配置决定
  （凭据由 dsh 从 `$DSH_HOME/.env` 读，班底不注入）。
  ⚠️ 补丁层是**整块替换 `config`**、不是逐字段合并 —— 只写 `model` 会把 profile 里的
  `provider:` 一起冲掉，所以那一行必须原样读回来再写回去。
