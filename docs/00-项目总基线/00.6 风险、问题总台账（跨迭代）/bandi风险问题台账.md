## 1. 开放风险

等级：**高**＝影响核心闭环或可能丢数据；**中**＝影响效率/可维护性；**低**＝已知代价，接受。

### R-001 专业度：手册判据没能拉动员工行为

| 项 | 内容 |
| :--- | :--- |
| 等级 | **高** |
| 状态 | 开放，**等主理人拍板方向** |
| 现象 | 岗位判据与技能正文都已注入，但跑 v2 与 v1 对比是 **4 平、0 升 0 降**；题 4（跑了命令但没有进程查询）、题 5（改完没重启也没提"要重启才生效"）两轮都 fail |
| 影响 | "员工更专业"这个产品目标**机制建了、效果没证明**。判据函数 `apps/server/src/regression/suite.mjs` 一个字没改，量具已可信，所以这不是尺子问题 |
| 候选应对 | A 改注入位置/措辞再跑 v3；B 只补题 4/题 5 的手册条目做单题验证；C 维持现状按"机制已建、行为未改"收档 |
| 约束 | **别自己拍**；也别拿 `v1-broken-claim*` 那批坏量具报告做对比 |
| 出处 | `docs/05-归档区/交接-2026-11-23-剩余工作.md` P0 段 |

### R-002 环境：安全软件黑名单拦住 `reg.exe`

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | 开放，**需主理人本人操作** |
| 现象 | 全量冒烟稳定 **1 红且只有 1 红**：`apps/server/src/smoke-runtime-detect.mjs` —— 它要读 HKLM 的 PATH，调 `reg.exe` 时被程序黑名单拦下 |
| 影响 | 环境性红，与业务代码无关；但员工按岗位判据跑全量冒烟时跑不全，等于测试覆盖有个洞 |
| 应对 | 安全中心 → 命令安全 → 程序黑名单，移除 `C:\Windows\System32\reg.exe` |
| 约束 | **禁止**用等价命令绕过、禁止换 shell 重试 —— 安全策略明令禁止 |
| 出处 | 交接文档 P1 段；`tools/run-smokes.mjs` 执行结果 |

### R-003 原生模块与 Node 版本绑定

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | 开放（工程约束，不是待修 bug） |
| 现象 | 换 Node 大版本后启动直接失败：`better_sqlite3.node was compiled against a different Node.js version … NODE_MODULE_VERSION 127 / 147` |
| 影响 | 升级 Node、或在同一台机器上换 Node 版本跑，会**起不来**；表现是服务启动即退出，容易被误判成"代码坏了" |
| 应对 | 在当前 Node 下 `npm rebuild better-sqlite3`；桌面安装包随包带运行时必需文件，不受影响 |
| 出处 | 服务端启动日志实况（2026-11-23 本机）；`apps/server/src/store/db.mjs` 顶部连接段 |

### R-004 共库多实例的清账误伤

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | **监控中**（机制已收口，边界仍在） |
| 现象 | 启动清账会把全库 `running` 一律判死。回归集用临时库、但 `BANDI_DATA` 会传给员工 CLI，员工跑启停类冒烟时另起实例继承同一个库 → 把正在跑的那轮判成 interrupted |
| 现有机制 | `apps/server/src/instance-lock.mjs`：锁在且 pid 活着 → 跳过清账与僵尸卡恢复；`BANDI_FORCE_REAP=1` 是排障逃生口 |
| 残留边界 | **旧版本进程不写这把锁**，所以"新旧混跑"判不出来；只有同版本多实例受保护 |
| 出处 | `instance-lock.mjs` 文件头注释（2026-11-22 回归实踩） |

### R-005 库结构升级是单向的

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | 开放（刻意设计） |
| 现象 | `PRAGMA user_version` 高于程序 `SCHEMA_VERSION` 时，程序**拒绝启动**；没有自动降级迁移 |
| 影响 | 回滚代码到旧版前必须先回滚数据，否则起不来。升级前备份因此是硬要求，不是建议 |
| 应对 | 升级前 `bandi data export`；回滚按运维手册 5.3 / 8.2 走 |
| 出处 | `apps/server/src/store/db.mjs` 版本号段；[运维手册](../00.5%20通用运维手册、管理员手册（基线）/bandi运维操作手册.md) 第 8 节 |

### R-006 前端无构建器：innerHTML 拼串靠纪律＋机制

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | 开放（选定形态的代价） |
| 现象 | 界面是原生 ES modules、无打包器；大量 `innerHTML` 拼字符串，转义靠 `esc()` |
| 现有机制 | 全站一份 CSP，`script-src` 用 `index.html` 内联脚本的 sha256 而不是 `'unsafe-inline'`；附件回显对 HTML/SVG 加 `CSP sandbox` |
| 残留风险 | 新增渲染代码若漏 `esc()`，XSS 面靠 CSP 兜底而不是代码本身；审查时要盯转义 |
| 出处 | 架构说明书 3.3「三处收口」；`apps/web/app.mjs` |

### R-007 回归基线靠手工跑，可能过期

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | 开放（刻意：不进 CI） |
| 现象 | 专业度回归集**不进** `tools/run-smokes.mjs`、不进任何 CI，只能 `node tools/regression.mjs` 手工跑 |
| 影响 | 基线报告（v1）是某个时点的快照。代码往前走之后，"4 平"这个结论的有效期需要重新评估 |
| 应对 | 每次要下"变专业了/没变"的结论前，重跑一版并落盘；报告不覆盖旧的 |
| 出处 | `tools/regression.mjs`；交接文档「回归集」段与铁律 |

### R-008 认证依赖外部身份中枢

| 项 | 内容 |
| :--- | :--- |
| 等级 | 中 |
| 状态 | 开放（架构选择） |
| 现象 | 浏览器/手机登录必须过 identity hub（bandi-hub，另一个仓库）；中枢不可达时，人进不来 |
| 缓解 | 授权全在本机；脚本/CLI 用 `X-Bandi-Token` 不受影响；本机钥匙与回环信任合成机主身份 |
| 残留风险 | 中枢是**外部单点**，其可用性与契约版本（`HUB_API_VERSION`）不在本仓控制范围内 |
| 出处 | 架构说明书 3.2；[SECURITY](../../../SECURITY.md) |

### R-010 审计表只增不减

| 项 | 内容 |
| :--- | :--- |
| 等级 | 低 |
| 状态 | 开放（合规要求） |
| 现象 | `security_events` 由触发器保证只追加、不可改不可删；写入量随请求量线性增长 |
| 缓解 | 有 `security_events_archive` 归档表与 `/api/security/audit/clear` 归档清理动作；归档表结构与主表同构 |
| 残留风险 | 清理是"搬走"不是"删除"，磁盘仍会缓慢增长；单机场景量可控 |

### R-011 Windows 上的编码往返会毁文件

| 项 | 内容 |
| :--- | :--- |
| 等级 | 低 |
| 状态 | 开放（工具链风险） |
| 现象 | 用 PowerShell 5.1 的 `Get-Content` / `Set-Content` 处理无 BOM 的 UTF-8 源码，会按 GBK 解码：中文乱码，且 GBK 双字节会把行尾字节吃掉，连换行一起丢 |
| 影响 | 一次往返就能写坏文件；2026-10-15 实测踩到过，且因未进版本控制无法回滚 |
| 应对 | 改文件只用编辑器 / `edit` 工具，不走 PowerShell 往返；打包用 `tar.exe`（bsdtar）能正确处理中文名，控制台乱码只是显示假象 |
| 出处 | [部署手册](../../../deploy/README.md) 第 B 节警告 |

## 3. 台账维护规则

1. **只记有据可查的**：每条都要能指回代码注释、交接文档或决策日志。查不到的推测不进台账。
2. **不删行**：关闭的移到第 2 节并写清收敛方式与时间；删除会让"这事发生过"永久消失。
3. **等级变化要写**：升级/降级在同一行说明原因，不要悄悄改数字。
4. **和迭代包联动**：某个迭代新引入的风险，先在本表登记，再在迭代包记录当时怎么处理；
   基线永远是最新真相，迭代包记录当时发生了什么。
5. **巡检节拍**：每个迭代收尾核对一遍本表 —— 关掉的够不够格关、开着的等级还准不准。
