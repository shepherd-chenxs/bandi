## 1. 产品定位

**班底（BANDI）**：把活派给 AI 数字员工，看它干，随时接管。自托管运行，数据和工作目录都留在你自己的机器上。

- **一句话**：你身边的一支 AI 班底 —— 有人管仓库、有人写代码、有人守流程，你像管理者一样派活、看过程、收结果。
- **解决什么问题**：直接用 agent CLI 是"一个人对一台机器"，活的组织、过程的可见、结果的验收、出错的接管全靠人肉。班底把"派活 — 执行 — 汇报 — 验收"变成一个可管理的工作系统。
- **给谁用**：一个人能维护、一个人能用的开发者 / 超级个体。不面向团队协作组织，不做多租户。
- **形态**：单机，一台机器一个完整实例。桌面客户端是形态，web 只是界面；手机原生壳和浏览器连同一台本机控制面。

## 2. 设计原则

这些信条贯穿每个功能的取舍，改设计时先对照这里：

1. **人管方向，机器管执行** —— 人定目标、给边界、拍板关键决定；拆解、执行、汇报交给员工。
2. **过程永远可见** —— 员工的思考、工具调用、回复实时流出来，没有黑盒。看得到才接管得了。
3. **随时接管，人永远是兜底** —— 任何会话可以停下、重跑、改派；员工做不了的事必须停下来问人，不硬编。
4. **停下来要像话** —— 说"没装 / 被占了 / 连不上"之前必须先实测过（环境类断言先跑验证命令），卡住要说清卡在哪、需要人做什么。
5. **交付要带证据** —— "我测过了"不算数，完成声明要有客观证据（测试输出、命令回执、事件流）背书。
6. **数据不出机器** —— 代码和密钥一个字节都不离开这台机器；云端中枢只转发请求，不存状态、不派活。
7. **界面单一来源** —— 三种客户端共用同一份网页 UI，壳只负责拉起和承载，不维护第二套界面。

## 3. 用户与核心场景

### 3.1 目标用户

一个人同时扮演**老板、项目经理、审阅人**三种角色：定需求、派活、验收。没有第二个真人协作者 —— 协作发生在**人与数字员工**之间。

### 3.2 核心场景

**场景一：日常派活**。用户在项目群里 @ 张坤："把这个 bug 修了"。张坤的会话开始跑，思考、读代码、改文件的过程实时刷在消息流里；跑完在群里交差，卡面从「跑中」变「完成」。用户全程可以插话补要求，也可以直接接管自己敲。

**场景二：一条龙流程**。用户起一个「需求 → 计划 → 写代码 → 测试」的流程实例：PM 把需求谈清楚写成 spec，架构师拆成任务卡和排期，研发按卡实现，测试跑验收。每步产出落成文档，下游节点直接接着干，用户只在关键节点看一眼。

**场景三：仓库值守**。仓库管家定时巡检 PR，按审阅判据给出"值得合 / 不值得合"的结论和理由；发现测试依赖本机环境这类硬伤，直接打回并说明。用户只在拿不准的"黄线"问题上被 @ 到。

**场景四：人不在电脑前**。员工把一个会话跑到了边界，通过飞书把卡点推到用户的手机上；用户在路上看一眼结论和证据，回一句"同意"，会话继续。

## 4. 信息架构

### 4.1 三端一核心

| 客户端 | 形态 | 与控制面的关系 |
| --- | --- | --- |
| 桌面 | Tauri 薄壳 | 拉起本机控制面 → 窗口指过去 → 退出时收掉**自己起的**那个 |
| 浏览器 / PWA | 同一份 apps/web | 直连本机控制面 |
| 手机 | Android 原生壳 | 中枢登录后的一台客户端；WebView 只承载已登录的面板 |

### 4.2 界面三层

网页界面是固定的三层骨架，所有功能都长在这三层里：

1. **一级：图标栏（rail）** —— 全局入口，固定七项：
   - **信箱**：平台事实通知（建卡失败、运行时异常这类），未读角标；不弹框、不在群里播报。
   - **消息**：与数字员工的会话、项目群聊 —— 日常主战场，默认停在这里。
   - **通讯录**：数字员工名录 —— 建员工、改配置、看每个人的运行记录。
   - **专家库**：可复用的专家角色，给员工的职责指令当参考。
   - **工作台**：项目、任务看板、流程编排与自动化。
   - **设置**（左栏底部）：运行时、令牌、隧道这类机器级配置。
   - **我的**（rail 最底）：当前登录的人 + 退出登录；只管"我是谁"，不承载功能。
2. **二级：列表面板** —— 列表标题、新建按钮、搜索框、列表主体；项目、任务、流程、插件共用这套框架。
3. **三级：内容区** —— 会话、详情、设置等视图容器，一次只看一个。

### 4.3 身份与进门

- **人走账号**：浏览器走账号密码表单转身份中枢；手机走中枢票进门。两条路最后都落到本机会话。
- **机器走凭据**：脚本 / CLI / 运维用 `X-Bandi-Token` 头或首次进场的 `?token=`（当场换成会话票并重定向掉）。
- **授权只有一个答案：登录即全权**。没有角色分级、没有菜单权限 —— 单兵作战的产品。
- 控制面缺省对外监听并强制鉴权；端口固定 18787，绝不偷偷挪端口。

## 5. 功能设计

### 5.1 会话：跟一个数字员工干活

会话是**最小工作单元**，也是一切执行的发生地。

- **一条消息 = 一次执行**：用户发话，员工开跑，思考 / 工具 / 回复按事件流实时刷出。从事件流里取回会话 id，下一句带回去就续上 —— 长任务天然多轮。
- **上下文占用环**：会话页常驻一个环形指示，显示这轮上下文窗口用了多少；快满时提示**自动换新会话**，该带走的记忆（经验簿、进度账）自动接过去，用户无感。
- **随时接管**：跑中可以停；失败可以重跑（主评论和回复上都有重跑按钮，重跑成功即隐藏）。
- **会话即工作项**：每个会话有标题、状态（待跑 / 跑中 / 完成 / 失败）和完整事件流；事件流落库，跨重启可回放。
- **运行记录**：每个员工有独立的时间线，哪轮几点跑的、结果如何，一一可查。

### 5.2 群聊：一支班底一起干

- **项目群 = 人 + 数字员工的混合群**：人在群里 @ 某个员工派活；员工之间**@ 接力** —— 张坤做完了 @ 架构师接手，过程在同一条群里全部可见。
- **群助手**：新建群默认配一个群助手，用户可在群设置里改 —— 群里没有明确对象时它接住话。
- **红线拍板**：删数据、对外发布、花钱这类危险动作，员工先 @ 群主拍板再动手，不自己决定。

### 5.3 数字员工：通讯录与简卡

- **建员工四件套**：名字 + 职责指令（他该干嘛）+ 绑定的运行时（用哪个 agent CLI）+ 工作目录（在哪干）。岗位决定手册：岗位手册随岗位固定注入，用户不可见、不可改。
- **简卡**：点头像弹出员工简卡，改职责指令、换运行时、换模型；头像仅数字员工可点，普通用户不可点。
- **记忆**：员工有长期记忆（经验簿）—— 听到"以后都这样"就记下来，下次干活带着；会话轮换时记忆跟着人走，不跟着会话丢。
- **秘书**：内置秘书「喜儿」不是通讯录里的一员，是平台自带的角色 —— 帮你建员工、查状态、判断连错库，但她不派活、不起流程、不碰代码（有明确的越界清单）。

### 5.4 项目与看板

- **项目**是活的组织单位：仓库、看板、群聊、流程实例都挂在项目下。
- **任务卡**：每张卡有描述和验收标准，验收标准要能执行、能复现；卡与验收场景编号绑定，测试知道自己在验什么。
- **看板列**：待办 / 进行中 / 待验 / 完成；员工按卡干活，卡状态跟着会话结果走。

### 5.5 流程引擎：一条龙自动化

- **模板 → 实例**：流程模板定义节点（如 需求 → 计划 → 写代码 → 测试），起流程就是实例化一份，每个节点是一次员工会话。
- **节点交接靠产物落盘**：上游产出写成文档（spec → plan → 代码 → PR），下游节点读目录接着干 —— 模板骨架由技能库提供，产物写进项目 docs。
- **自动化**：定时任务触发流程；也可从群聊、看板手动起流程。
- **一次 run 可以包含 1~N 次尝试**：连接抖动、进程被杀、上游报错不再直接落成「失败」，同一 run id 重试，只在最后收一次尾。

### 5.6 代码托管与 PR

- **仓库接入**：填 GitHub 访问令牌（PAT）后托管仓库；仓库身份在接入时一次性解析落库，之后目录改名不影响 GitHub 功能。
- **PR 管理**：PR 列表、合并请求卡片（领先提交平铺展示、待建 PR 计数）、建 PR 弹窗（只保留分支 / base / 领先数概览）。
- **巡检**：仓库管理员固定值守，定时 + 手动巡检；巡检区域常显在 PR tab，不折叠。「上次巡检」只显示时间。巡检结论按审阅判据台账给，红线一票否决，黄线 @ 人拍板。
- **Git 与 GitHub 分家**：Git 推拉代码不需要连接 GitHub；GitHub 令牌只影响 PR、合并、从账号添加仓库。文案里不许把两者混为一谈。

### 5.7 信箱与交付验收

- **信箱收平台事实**：建卡失败、运行时异常、巡检黄线待拍板…… 未读角标提醒，消息里不播报、不弹框。
- **交付两条腿**：员工的完成声明（`[完成]` / `[受阻]` 标记）+ 平台核对的客观证据，两条都成立才算交付；只有声明没有证据的，进信箱让人复核。
- **契约第 13 条的环境核验**：说环境问题必须先跑过验证命令，没跑过 = 不算结论，平台直接记进信箱。

### 5.8 专家库、插件与连接器

- **专家库**：沉淀可复用的专家角色（职责指令模板），建员工时拿来改改就用。
- **插件 / 连接器**：manifest 声明能力，MCP 三种接线方式；插件给员工添工具，不改平台代码。

### 5.9 飞书通道

- **员工级接入**：一个员工绑一个自建应用，凭据落 feishu-apps.json；员工把卡点、结论推到用户的飞书，用户在飞书里回话续会话 —— 人不在电脑前也不断线。

### 5.10 设置

- **运行时**：管理本机可用的 agent CLI（识别、不代装 —— CLI 自己装、凭据自备）。
- **令牌**：GitHub PAT、身份中枢配置。
- **隧道与自启**：远程访问用 tailscale / cloudflared / frp 三选一把本机接出去；开机自启拉起控制面。

## 6. 交互口径

这些口径是全局约定，写文案、做界面都要对齐：

- **结论先行**：员工开口第一句就是结论（顺利 / 有问题 / 卡住），不许铺垫。
- **第一人称**：员工说"我"连不上，不说"它"；失败提示给可操作指引，不甩技术栈。
- **降噪**：不弹框、不重复提示、按钮悬浮提示能省则省；需要人知道的事进信箱，用角标说话。
- **技术名换人话**：机器 ID 显示为运行时 label，错误码翻成"这是什么问题 + 你可以怎么办"。
- **可点的东西就让它可点**：提示里的「设置 → 运行时」是可以点过去的，不让人自己找。

## 7. UI 设计约定

### 7.1 头像

数字员工与专家的头像走**固定风格 + 固定工序**，任何一次生成都风格统一、免调参数。
产物落位 `apps/web/avatars/<id>.png`（256×256，UI 显示 26~58px）。

- **风格**：扁平厚涂、柔和上色的卡通胸像（头占画面约一半，水平居中、头顶留白），
  低饱和灰调底色 + 纸纹 + 暗角，暖色友好表情；无文字、无水印框。
- **新建头像**（文生图，1024×1024 方图 —— 不要竖版，人物比例不可控）：

```
Flat painterly soft-shaded cartoon avatar portrait of <角色描述：性别/职业/发型/眼镜/衣着/手持物>.
Medium shot showing head, shoulders and upper chest only; the head takes up roughly
half of the frame height. Character horizontally centered with comfortable empty
space above the hair. Solid muted <底色描述> background with subtle paper texture
and a soft vignette. Simple shapes, clean edges, warm friendly expression.
No text, no watermark, no border, no frame.
```

- **修改已有头像**（图生图，优先用这条）：必须拿**原版头像**做底（input_fidelity=high），
  不从零生成 —— 从零生成的风格和长相都不可控：

```
Keep this character and art style EXACTLY the same — same painterly soft-shaded
cartoon style, same face, hair, glasses, clothing, props, same muted textured
background. Fix ONLY: <要修的点>. No text, no watermark.
```

- **工序**：`node tools/avatar-process.mjs <源1024.png> apps/web/avatars/<id>.png` 自动裁成 256
  （水平居中并避开水印带，水印固定在右下角，不用在提示词里做文章）；细微偏移用
  `tools/avatar-nudge.mjs`（下移补头顶留白）、`tools/avatar-debox.mjs`（修头顶瑕疵）；
  居中度数值检测不可靠，**最终以目测为准**；动原图前先备份到 `tmp/avatar-backup/`。
  落盘后刷新页面即生效，无需重启服务。
- **底色**：低饱和、偏灰调；新头像取未被占用的相近灰调，避免相邻卡片撞色。
- **红线**：不让模型画黑底/边框来"承载水印"；不竖版再裁；不从零重画已有角色；
  不在提示词里求"人物小一点"救构图（不如图生图重排）。

## 8. 产品边界：明确不做

- **多机协同 / 算力节点 / 总机分机**：不注册、不报到、不心跳领活、不把本机派给别的机器。跨机器协作走 git 仓库 + PR，不组集群。
- **本机账号分级、角色与菜单权限、协作中心 / 分公司**：登录即全权，单兵作战。
- **配对令牌与设备身份**：手机走中枢登录，只有一种人的身份。
- **代装 agent CLI、平台侧一键生图、额度 / 用量闸**：运行时只识别不安装；头像由固定 prompt
  在会话侧出图（见 7. UI 设计约定）。
- **浏览器当执行器**：真正执行的是本地控制面拉起的 agent 子进程，关浏览器不影响干活。
- **控制面 ↔ 执行端的双向数据同步、P2P / NAT 打洞、以 30s 轮询为主**：实时性靠事件流。
- **面板 UI 原生重写**：桌面与手机共用同一份网页，不永久维护两套 UI。
- **端到端加密、多租户、IM 集成（飞书除外）、成本分析、逐 token 打字机**：这一版不做。
