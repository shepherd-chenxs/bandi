# 登录页 —— PC 与手机分端设计（2026-11-06）

## 为什么分两页

用户实报（2026-11-06）：「PC 端登录界面重新设计一下，手机端的账号密码登录页不必和
PC 端的一样。因为你想着同一个页面在两个地方显示，那就必定不好看。」

之前的登录页（`auth.mjs` 的 `loginPage()`）是一份 HTML 同时服务电脑和手机，唯一的
移动适配是 `@media (max-width:480px)` 收内边距 —— 正是「同一页面两头将就」的病根。
这次起**双端分设计**：两份完全独立的页面，逻辑共享、视觉各画各的。

## 架构（apps/server/src/auth.mjs）

```
loginPage({ hasUsers, loopback, users, mobile })   ← 分发器
  ├─ mobile=true  → loginMobilePage()   手机：对齐壳启动页的 iOS 语汇
  └─ mobile=false → loginDesktopPage()  PC：左右分栏
共用（只写一份）：
  brandSvg(key)         B 字母标 SVG（key 区分同页多处实例的 mask id）
  loginFormHtml(...)    四态表单标记（建号 / 磁贴 / 用户名密码 + #err）
  OTP_PANE_HTML         两段式登录第二段
  LOGIN_SCRIPT          内联脚本（提交 / OTP / 手机补卡 / CSRF）
  warnbarHtml()         明文 TLS 告警条（两端各调样式）
```

### UA 分叉口径（`isMobileUA(req)`）

两个信号任一命中即手机：`Sec-CH-UA-Mobile: ?1`（Chromium 系默认发的低熵提示）或
UA 正则 `/Android|iPhone|iPod|iPad|Mobi|Phone/i`（Safari / Android WebView 兜底）。
误判代价可控：手机被判成 PC 会拿到分栏页（≤960px 自动收成单列，仍可用）；
PC 被判成手机几乎不可能。guard 的三个发放点（回环 / 令牌 / 无凭据）各传
`mobile: isMobileUA(req)`。

## PC 页：左右分栏

- **左品牌大区**（约 60% 宽）：永远深色，深海军蓝渐变底 + 两团慢速色斑 + 渐隐网格；
  logo + 产品名 +「自托管 · 多 agent 协作平台」+ 三条特性（消息协作 / 专家库 /
  任务看板，图标 chip + 一行说明）；左下角 `bandi · self-hosted`。
- **右表单面**（`clamp(400px, 36vw, 480px)`）：跟随系统深浅（登录前读不到用户主题
  偏好，跟系统走是唯一合理默认）；紧凑品牌行 + 表单。
- **配色与主站同源**（用户 2026-11-06 选定）：交互蓝 `#0a84ff`（浅色 `#0066cc`）、
  实心主按钮 `#0071e3`（浅色 `#0066cc`，与 style.css `--btn-solid` 同口径）、
  logo 渐变 `#4b6cb7→#182848`（style.css `--logo-1/--logo-2`）；圆角收成 10px
  （主站「面」档），输入框 44px 带图标。
- **≤960px 是兜底不是设计目标**：左栏收成顶部横向品牌条（特性列表藏掉），表单照常
  —— 手机不该落到这页（isMobileUA 分流），落到这档的只有桌面窄窗口。

## 手机页：对齐壳启动页（apps/mobile/dist/launcher.css）的 iOS 语汇

- 纯色系统底（深 `#0a0b0d` / 浅 iOS grouped `#f2f3f7`），不加光晕，靠 filled 卡片
  + hairline 分层；token 与 launcher.css 同名同值（`--r-card 18px / --r-ctl 12px /
  --r-btn 14px / --accent #3d76f6`、15px 字号、去字距）。
- 品牌区 = iOS 大标题式一行、左对齐（居中 hero 是落地页的排法），与启动页首页同款。
- 输入框 48px filled、主按钮 50px 实心；`viewport-fit=cover` + safe-area padding；
  `min-height:100dvh`；内容**顶部对齐**不垂直居中 —— 输入框落上半屏，键盘盖不住
  （launcher「别垂直居中、别加大段留白」的教训）；body 不加 overflow-y（移动
  WebView 的滚动容器是文档本身）。
- **报错 = 底部浮出横幅**（launcher `.status` 同款）：`#err`/`#otpErr` 是共享标记
  里的同一些元素，手机页只用 CSS 把它改成 fixed 底部横幅（入场动画从 PC 的 shake
  改为上浮），脚本零改动。
- 磁贴态手机实际到不了（回环才摆磁贴），样式补全只为共享标记完整。

## 契约（别破坏）

- 元素 ID 两端一致：`loginPane / pwForm / signForm / tiles / pwRow / pwWho / nm /
  pw / pw2 / otpPane / otpForm / otpCode / otpErr / otpBack / err`。smoke 断言
  （smoke-csrf `id="pwForm"`、smoke-auth / smoke-bootstrap `id="signForm"`）和
  共享脚本都靠它们。
- 内联脚本嵌在模板字面量里，**不能引入反引号**；`\s` 等转义按模板字面量规则写
  （`\\s`）。
- 共享脚本里的手机 clientKey / 补卡逻辑只在手机 UA 生效，桌面浏览器登录页一位
  字节不变。
