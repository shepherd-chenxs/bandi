# 移动端任务看板重设计 · 视觉规格（v2 定稿，2026-11-05）

> 交付对象：前端工程 + ux-designer。所有色值走既有 token（--mb-* / --st-*），**本规格新增 hex = 0**。
> v2 与 ux 交互规格合并：接受「左返回 + 居中标题 + 右＋」「通栏列表」「无框输入区」「sticky 主按钮」，
> 保留「单张分组卡容器」「刷新常驻」。类名：`kb-l-*`（看板页）+ `kb-new-*`（创建页），`kb-m-*` 退役。

## 0. 视觉原则（四条）

1. **进 App 不进网页**：删面包屑；导航栏三槽（左返回 / 居中标题 / 右＋），52px 玻璃底 + 0.5px hairline，token 全部沿用 §16.2。
2. **容器是一张，行是连续的**：整个列表 = **一张** inset grouped 卡（不是每行一张、也不是按状态切 8 张），行间 hairline 内缩 16px —— §4 `.item` 的列表语汇。
3. **一屏只留一处彩色**：状态色是 6px 圆点（--st-*），词不上色、无 3px 色条、无 pill；页面蓝只出现在 tab 选中、＋、主按钮。
4. **表单双轨**：输入（标题/描述）无框满宽；选择（状态/执行方式/执行人/项目/流程）走 52px「label 左 · 值右 ›」value cell。

## 2. 状态筛选条 + 刷新（44px，**不滚动**）

滚动模型（与 ux 交互规格 §「唯一滚动容器」一致）：**`#kbList` 是唯一滚动容器**，顶栏与筛选条是 flex 列里的固定项——这里**没有 sticky**（容器本身不滚，sticky 是空转，iOS 上还会抖）。宿主：

```
#pluginView.kb-page .detail-body { display:flex; flex-direction:column; min-height:0; overflow:hidden;
                                   padding:0; }
#kbList { flex:1 1 auto; min-height:0; overflow-y:auto; -webkit-overflow-scrolling:touch;
          overscroll-behavior:contain; scrollbar-width:none; }
#kbList::-webkit-scrollbar { width:0; height:0; }
```

- **tab 定死：填充胶囊**（不换 segmented、不用下划线）。现有 `.kb-m-tab.on` 是「tint 10% 底 + 45% tint 描边」，本次**去描边**、底提到 14%（与 §20 身份卡 role pill 同浓度）；未选态从"透明 + 描边"换成 `--mb-fill` 实底——一排胶囊宽度才稳定，横滑时不抖。

- 按压：tab 切换即时生效，不加 :active 底色；刷新加 `--mb-press`。

              color: var(--mb-text-3, var(--dim)); }
```

**元信息行的收缩顺序（358px 宽下四段放不下，必须定优先级）**：
`[● 状态词] [项目 pill] [执行人] ……… [时间]`
1. 时间 `flex:0 0 auto` —— 永不缩、永不被挤掉；
2. 状态点 + 状态词 `flex:0 0 auto` —— 永不缩（它是行的维度，缩了就不可读）；
3. 执行人 `flex:1 1 auto; min-width:0` —— **第一个被省略**；
4. 项目 pill `flex:0 1 auto; max-width:40%` —— 第二个被省略（保住前 8 个字左右）。全局面板才渲染，项目入口不渲染。

**行高带**：单行标题 68px（下限），双行标题约 90px；标题两行截断即封顶，不设上限。

**状态色映射（行内 `--st-c`，与桌面 `.kb-col` 同一张表，随 data-theme 自动换档）**

| 列 key | 变量 |
|---|---|
| idea / todo / doing / review / blocked / failed / done / cancelled / other | `--st-idea` / `--st-todo` / `--st-doing` / `--st-review` / `--st-blocked` / `--st-failed` / `--st-done` / `--st-cancelled` / `--st-other` |

> **为什么是 6px 圆点，不是 3px 左色条**：色条是桌面卡片的语法（`.kb-card.manual` 的 border-left）。行高 68 时 3px×68 的色面积是 6px 点的 ~5.2 倍，8 种状态混排会把列表左缘变成一条彩条墙，抢在标题前面；而它承载的信息（当前状态）圆点 + 状态词已经完整说了两遍。圆点色取 token 原值，**不混明度**：--st-* 已按"压在 12% 淡底上 ≥4.5"双主题校准（style.css 143-154 / 227-237），再乘 60~70% 会让浅色档（如 #8a5200）糊在灰底上，反而不可读。

**跳转**：`data-kb-open / data-kb-conv / data-kb-flow` 照旧挂 `.kb-l-row`（wireBoard 原样认）。**不画 chevron**——三路跳转里两种是弹窗，箭头会骗人（采纳 ux 结论）。来源/PR/设备标签窄屏一律不画。

## 10. 2026-11-08 修订（用户评审后，v2 的四处更新）

> 评审起因：6px 状态点上「待办(青)」与「已完成(绿)」几乎同色、状态词是最弱的灰；
> 「全部 6」却只能数出 3 个状态 —— 已完成/已取消的 tab 被横滑藏在了刷新按钮后面。

| 处 | v2 原样 | 修订后 |
|---|---|---|
| 状态（§3.2） | 6px `--st-*` 圆点 + `--mb-text-2` 灰字，"词不上色、无 pill" | **浅底状态胶囊**：底 = `--st-*` 12%（正是那套色校对比度用的底）、字 = `--st-*` 原值；**不画点**（胶囊已是"色+词"）。仍钉右上角 |
| 执行人（§3.2） | 一行灰字，与来源签/项目 pill 同灰度 | 仍是**纯文字**（首字头像方案当天即撤：项目名一长时来源签/pill/头像/名字挤一行就乱，头像最先被牺牲）；未指派 = 虚线小框「待分配」（服务端「（没点名）」等括号话由前端替换） |
| 时间（§3.2） | 服务端 `at` 原样（UTC 墙钟的绝对时间） | **相对时间**：`kbRelTime()` 按 UTC 还原时刻，刚/N分钟/N小时/N天前；≤7 天内生效，解析不了/在未来/超 7 天回落绝对时间。绝对时间留在 `title` 与 aria-label |
| 筛选条（§2） | 右端刷新按钮"封口"，横向藏住的 tab 无任何暗示 | tab **右缘渐隐**：JS 按 `scrollLeft` 给 `.kb-l-tabs` 打 `can-more` / `can-prev`，真的还有内容才画（mask-image，不叠块）；左滚过头同理。tab padding 14→12、gap 8→6 |

- 新增类：`.kb-l-none`（待分配虚线框）。`.kb-l-ava` / `.kb-l-name` 已随头像方案一并撤销。
- `--st-*` 一字未动：胶囊底/字直接复用现有 token，双主题不新增 hex（修订原则同 §7）。
- 「＋」仍在导航栏右槽（§5 不变）：FAB 方案在评审里提过，落点否掉 ——
  导航栏对称、全页唯一主蓝这两条是 v2 的定稿原则，FAB 会同时破两条。
