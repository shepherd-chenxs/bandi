## 一、背景与现状（先读这段，别自己猜）

2026-10-28 起产品形态已定：**每台机器跑一个完整单机版**；多机协同是实验特性。
**瘦客户端反代（client-proxy）已经在 2026-10-21 整体移除** —— 已加入总机的机器，本机服务照常答自己的 UI/API。

所以现在已经有：

- `config.json` 里有 `controlPlane` ⇒ 这台机器是「节点」（判据：`apps/server/src/config.mjs` 的 `clientJoined`）。
- 节点机打开班底 → `apps/web/js/misc.mjs` 的 `boot()` 发现 `client.joined` 为真 → `renderNodeMode()` 渲染**节点状态页**（连着哪台总机、节点进程在不在、退出总机）。
- 本机配置接口已存在：`/api/local/*`（`apps/server/src/routes/local.mjs`）、`/api/runtimes`、`/api/hello`、`/api/web-version`。
- 节点协议（`apps/server/src/node.mjs` 出站 claim/events/finish）**完全不动**。

**缺口**：节点页只是一个状态卡片，不是「配置面」；也没有身份 → 菜单的映射。

## 二、目标（一句话）

让已加入总机的机器有一个**围绕本机配置的面板**（不是总机面板），并把「身份 → 菜单」做成代码里的**矩阵**，为后续用户/角色/菜单配置留好唯一扩展点。

## 三、两个必须区分的概念

1. **机器角色**（这台机器是谁）：`operator`（未加入，本机单机版）｜`node`（已加入某台总机）。
   来源：服务端 `clientJoined`，经 `/api/hello` 的 `role` 字段给出。
2. **查看者身份**（打开页面的人是谁）：`operator`（本机/令牌）｜`device`（手机配对令牌）。
   来源：现有 `/api/pair/me`（`S.isDevice`）。

菜单矩阵的输入是这两个的**组合**。本刀只落 `node` 机器角色的菜单，`operator`/`device` 的现有行为**保持不变**。

## 四、本次范围（P0）

### 4.1 服务端：`/api/hello` 增加机器角色
- 文件：`apps/server/src/server.mjs`，`helloPayload()`。
- 加字段 `role: 'node' | 'operator'`。
- **判定用 `localMode.isJoined()`（每次现读 config.json）**，**不要**用 `config.clientJoined`
  —— 那是**启动那一刻的快照**，运行期加入/退出后它会过期（同一类坑见 `config.mjs` 里
  `lanOrigins()` 的注释）。`helloPayload()` 已经 import 了 `localMode`，直接调。
- 不加任何秘密，不涉及鉴权；`/api/hello` 仍免令牌。
- 同步：`apps/web/js/misc.mjs` 里已经用它取 hostname/version，别改字段名。

### 4.2 前端：新增身份/菜单矩阵（唯一扩展点）
- 新文件 `apps/web/js/roles.mjs`：
  - `ROLE = { OPERATOR:'operator', NODE:'node', DEVICE:'device' }`；
  - `MENU_KEYS`（稳定字符串 key，中文标签单独一份）；
  - `MENUS_BY_ROLE`：每个角色能看到哪些 key；
  - `resolveRole({ isDevice, machineRole })`；
  - `canSee(role, key)`。
- 本刀的 `node` 菜单 key（与 4.3 的分节一一对应）：
  `node.connection / node.machine / node.runtimes / node.access / node.data / node.about`。
- `operator` 的 key 先照现有导航写全（messages/contacts/experts/workbench/settings），
  `device` 照现有手机受限视图写（工作台/会话/通讯录/我的）。**本刀不用它们去改现有渲染**，只是把矩阵立起来。

### 4.3 前端：节点页升级为配置面
- 文件：`apps/web/js/misc.mjs` 的 `renderNodeMode(st)`。
- 保留现有能力：`body.node-mode`、5 秒轮询 `/api/local/status`、`退出总机`（`confirmDo`，文案不动）。
- 改成**一页分节**（沿用仓库既有 `set-sec` / `set-box` / `set-row` 样式，别新造一套视觉）：
  1. **连接**：总机名/地址、节点进程在线与否、加入时间、「打开总机面板」按钮（`window.open(controlPlane)`，**不做令牌注入**，提示"用总机的访问令牌登录"）。
  2. **这台机器**：主机名、版本、实例标识（来自 `/api/hello`）。
  3. **运行时**：调 `GET /api/runtimes`，列出本机装了的 CLI（只读）；拿不到就显示「读不到」，别白屏。
  4. **访问方式**：当前监听（节点机恒为 `127.0.0.1`）、说明"节点机不对外开放；要远程访问请用隧道"。
  5. **数据**：数据目录、库大小/条数（`/api/local/status` 里的 `local` 字段；没有就用已有字段，不要为此新增接口）。
  6. **关于**：版本、仓库/文档入口。
- 每个分节渲染前过 `canSee('node', key)`（本轮恒真，但这行必须有）。
- 保留「退出总机」按钮在最下方。
- 文案要求：说清「面板（员工/会话/项目）只在总机上；这台机器只负责配置和干活」。

## 六、验收

### 6.1 新增冒烟 `apps/server/src/smoke-node-panel.mjs`
照 `smoke-lan-origin.mjs` 的写法（临时数据目录 + 临时端口 + `spawn server.mjs`）：
1. 预写 `<tmp>/config.json`：`{"controlPlane":"http://127.0.0.1:1","token":"x","scope":"compute"}`；
2. 起服务，`GET /api/hello` → `role === 'node'`，且版本/主机名照旧；
3. `GET /api/local/status` → 200 且 `client.joined === true`；
4. `GET /api/runtimes` → 200（节点页要用）；
5. `GET /api/web-version` → 200；
6. 清了 `controlPlane` 再起一个 → `role === 'operator'`；
7. 反向断言：节点页**不需要**新增的任何业务接口（不要为它开 `/api/state` 之类的口子）。
- 把新用例登记进 `tools/run-smokes.mjs` 的 `RUN`（不登记会直接报错退出）。
