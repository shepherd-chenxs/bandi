# 任务书（第三刀）：账号、登录与角色分配

> 给执行方（WorkBuddy）的完整任务书。仓库：`E:\02CodeSpace\github\bandi`。
> 前两刀已进 `main`：① 节点配置面 + 身份/菜单矩阵；② 角色与菜单可配置化（`roles` / `role_menus` 两张表 + 管理页）。
> 本刀把「人」接上去。**这是全项目鉴权风险最高的一刀**，按 §三 的硬约束做，别扩大范围。

## 一、目标（一句话）

让**非回环访问**的人可以「用户名 + 密码」登录，拿到一个**角色**；角色决定他能在界面上看到
哪些菜单，管理员角色才有管理权限。**回环、共享令牌、手机配对、节点协议全部照旧。**

验收：本机（回环）照旧免登录；局域网/公网浏览器出现登录页；登录后按角色看到不同菜单；
非管理员改配置被 403；退出后会话失效；`smoke-auth` / `smoke-pair` / `smoke-roles` 全绿。

## 二、三个已经拍板的决定（照做）

1. **登录方式 = 用户名 + 密码**。密码用 `node:crypto` 的 `scryptSync`（**零依赖**），
   每人独立 salt；库里只存 salt + hash。不做邮箱、不做一次性链接、不做 2FA、不做找回密码。
2. **与现有鉴权并存，不替换**：
   - **回环永远免登录**，身份仍是 `operator`（物理在场 = 最高权限，也是防锁死的兜底）；
   - **共享令牌保留为 root**（部署 / 脚本 / 节点；`BANDI_TOKEN` 与数据目录 `token` 文件不动）；
   - **没建任何用户时，行为与今天一模一样**（还是令牌登录页）；
   - 账号只对**非回环的浏览器**生效。
3. **本刀菜单只作用于「登录的浏览器会话」**：按角色过滤**一级导航 / 底部导航 / 设置分节 /
   工作台里的管理磁贴**。节点本地面板（回环）和手机端**不变**。把角色下发到节点/手机是第四刀。

## 三、硬约束（违反即返工）

- **不重写 `auth.mjs` 的既有判定**：`identify()` / `decide()` 只**加一条** `user` 身份分支；
  `operator` / `node` / `device` / `revoked` 的行为一个字节都不许变。
- **`mayManage(req)` 变成**：`operator`（含回环/令牌）**或**「登录用户且角色 id = `admin`」。
  其余角色一律 `false`。
- **非 admin 用户的 API 面 = 现有 `deviceMayReach` 白名单**（读 + 发消息 + 便签 + 审批 + 停止）。
  直接在 `decide()` 里复用那个函数，**不要复制一份新白名单**。
- **回环分支先于会话检查**：回环直接 `operator`，不查 Cookie（否则"本机打不开"）。
- 密码/会话**绝不进日志、不接口回显**（列表接口连 hash/salt 字段都不出现）。
- 登录失败文案统一「用户名或密码不对」，**不暴露用户是否存在**；同一 IP / 同一用户名
  5 分钟内失败 5 次 → 429（内存计数即可，重启清零，够用）。

## 四、数据（SQL 只在 `apps/server/src/store/`）

新文件 `apps/server/src/store/users.mjs`（并在 `store.mjs` 里 `export *`）：

```
users(
  id TEXT PRIMARY KEY,          -- newId('u')
  name TEXT NOT NULL,           -- 1–20 字，唯一（大小写/空白归一后比较）
  salt TEXT NOT NULL,           -- 16 字节随机，hex
  hash TEXT NOT NULL,           -- scrypt(password, salt, 64)，hex
  roleId TEXT NOT NULL,         -- 指向 roles.id
  builtin INTEGER NOT NULL DEFAULT 0,  -- 第一个用户 = 1（不可删、不可降级）
  disabled INTEGER NOT NULL DEFAULT 0,
  createdAt TEXT, updatedAt TEXT
);
user_sessions(
  tokenHash TEXT PRIMARY KEY,   -- sha256(会话 token)，明文只在登录响应里回一次
  userId TEXT NOT NULL,
  createdAt TEXT NOT NULL,
  expiresAt TEXT NOT NULL,      -- 30 天
  lastSeenAt TEXT
);
```

- **第一个用户**：本机（回环）在设置页创建，自动 `roleId='admin'`、`builtin=1`；
  该用户**不可删、不可改角色、不可禁用**（防锁死）。
- 删除用户 / 改角色前检查：**不能把最后一个 admin 弄没**（返回明确错误码）。
- 会话 token：32 字节随机 base64url；Cookie `bandi_sid`，`HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000`。
- `roleId` 必须指向存在的角色（`store.getRole`），否则 400。

## 五、服务端接口

新文件 `apps/server/src/routes/users.mjs`，在 `server.mjs` 链里注册（放在 `handleRoles` 前后皆可，自己判路径）：

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/login` | **免令牌**（`auth.guard` 里豁免；CSRF 闸照过） | `{name,password}` → 设 Cookie + `{ok, kind:'user', user:{id,name}, role:{id,name,menuKeys}}`；失败 E38xx |
| POST | `/api/logout` | 任意已登录 | 删当前会话 + 清 Cookie |
| GET | `/api/me` | 任意已登录 | `{kind:'operator'}` 或 `{kind:'user', user, role:{id,name,menuKeys}}`；未登录 401 |
| GET | `/api/users` | `mayManage` | 列表（**不含** salt/hash） |
| POST | `/api/users` | `mayManage` | `{name,password,roleId}`；密码 ≥ 8 字 |
| PATCH | `/api/users/:id` | `mayManage` | `{name?,password?,roleId?,disabled?}`；内置 admin 不可改 role/disabled |
| DELETE | `/api/users/:id` | `mayManage` | 内置 admin 不可删；删最后一个 admin 拒绝 |

- 用户名字 1–20 字、唯一（归一后比较）；密码 8–128 字。
- 错误码先 grep 全仓领号（E38xx 段），在文件头登记；**一个码只表达一件事**。
- `/api/me` 在 `auth.required === false`（回环）时返回 `{kind:'operator'}`。

### `auth.mjs` 的最小改动

1. `guard()`：登录页分支现在要给前端一个「有没有用户 / 该显示什么表单」的信号
   （`loginPage({ wrong, hasUsers })`）。**没有用户时保持今天的样子**。
2. 在非回环分支里、`identify(token)` 之前：先看 Cookie `bandi_sid` →
   `store.userBySession(token)` → `{kind:'user', userId, roleId, admin: roleId==='admin'}`；
   命中且未过期就把它交给 `decide()`。
3. `decide()` 加 `user` 分支：
   - `who.admin` → `'allow'`；
   - 否则 `deviceMayReach(method, pathname) ? 'allow' : 'E4033'`（复用，别复制）。
4. `mayManage(req)`：`operator || (user && admin)`。
5. `POST /api/login` 与 `POST /api/logout` 在 `guard()` 里豁免（logout 可要求 session 自校验）。

## 六、前端

1. **登录页**（`auth.mjs` 里的 `loginPage()` HTML）：优先用户名 + 密码表单；
   底部保留一个可折叠的「用访问令牌登录」入口（root 兜底）。**没有用户时只显示令牌表单**。
2. **`state.mjs load()`**：增加一次 `GET /api/me`（只问一次，照现有 `isDevice` 的写法），
   存 `S.me`；`S.menuKeys` = 该用户的 `role.menuKeys`（operator 为全部，device/node 沿用现逻辑）。
3. **菜单收敛（本刀唯一的渲染改动）**：
   - 一级导航 `.nav-btn`：按 `S.menuKeys` 隐藏（key 用 `roles.mjs` 的 `MENU_KEYS`）；
   - 底部导航（手机）：同上；
   - 设置页分节：非 admin 用户只显示 `prefs` 与 `about`（硬编码，**不**按菜单 key 拆设置小节）；
   - 工作台宫格：非 admin 隐藏「研发」区（代码托管/远程连接）与「自动化」区（定时任务/工作流设计），
     只留项目与任务看板；

4. **设置 →「用户」分节**（`SETTINGS_SECTIONS` 加 `['users','用户','账号与角色']`，
   `DEVICE_SETTINGS_SECTIONS` 不加）：列表 + 新建/改名/改密码/改角色/删除；破坏性操作走 `confirmDo`。
5. 退出登录入口：设置 →「用户」页底部（或「关于」页）放一颗「退出登录」（仅用户会话显示）。
6. 新文件 `apps/web/js/useradmin.mjs`；记得在 `sw.js` 的 `JS_MODULES` 登记并把 `VERSION` +1。

## 七、验收

### 7.1 新增 `apps/server/src/smoke-users.mjs`
照 `smoke-roles.mjs` 的写法（临时数据目录 + 临时端口 + `BANDI_HOST=0.0.0.0` 那种非回环形态 + `BANDI_TOKEN`），覆盖：
1. 没用户时：`GET /api/me` → 401；登录页只给令牌表单（可只查接口）；令牌照旧可用；
2. 用 root 令牌建第一个用户（admin）→ 该用户 `builtin=true`；
3. `POST /api/login` 正确密码 → 200 + Set-Cookie；错密码 → 401 + 统一文案（不含"用户不存在"）；
4. 带会话 Cookie：`GET /api/me` → `kind=user` + `role.menuKeys`；`GET /api/users` → 200；
5. 建一个非 admin 用户（角色用内置 `operator` 或 `node-ops`）→ 登录后：
   - `GET /api/roles` → 403（`mayManage` 拦截）；
   - `POST /api/users` → 403；
   - `GET /api/state` / 发消息白名单内接口 → 200；
6. admin 用户：`GET /api/roles` → 200；
7. 退出登录 → 原 Cookie 再打 `/api/me` → 401；
8. 内置 admin 不可删、不可改角色、最后一个 admin 不能被移除；
9. 会话落库：重启服务后原 Cookie 仍有效（未过期）；伪造/乱码 Cookie → 401；
10. **不回归**：回环形态照旧 `operator`、共享令牌照旧可用（这两条可由 `smoke-auth` 覆盖，
    这里各补一条即可）。
- 登记进 `tools/run-smokes.mjs`（不登记会直接报错退出）。
