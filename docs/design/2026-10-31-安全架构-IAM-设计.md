## 一、结论（TL;DR）

采用 **BFF 会话 + 统一 Principal + 集中授权策略（PDP）+ 路由权限清单 + 审计**；令牌用**不透明 `at_`**，JWT **已拍板不做**（取舍见附录 A）：

| 层 | 方案 |
|---|---|
| 浏览器 | **BFF**：登录后只发 HttpOnly 会话 Cookie，**不把令牌放进浏览器 JS/localStorage**；CSRF 双提交 |
| API / CLI | `access token` **不透明**（`at_`，10–15 分钟，只存哈希）；`refresh token`（不透明、轮换、复用检测、30 天）。**JWT 已拍板不做**（附录 A） |
| 机器 | 节点/手机/分公司继续用**不透明长期凭据**（哈希存中心、可吊销），需要短票时换成 `at_`（带 scope） |
| 授权 | 权限词表 + 角色→权限 + **路由清单默认拒绝** + 一个 `authorize()` PDP；`E1094`/`mayManage`/`PANEL_FORBIDDEN` 逐步收编 |
| 会话 | `tokenVersion` 撤销、空闲/绝对超时（**按会话种类分别定义**，§9）、会话/设备列表、退出全部 |
| 传输 | TLS 在 node 外面终结（反代/隧道，§10.1）；非回环明文只告警；Cookie `Secure`；CORS/Host/CSRF；URL 不再携带长期令牌 |
| 滥用 | 登录/刷新/OTP/加入/导出限速 + 锁定；安全审计表（**策略层自动记**，§11.2） |
| 迁移 | 四期逐段替换，**授权先于令牌**，旧会话/旧令牌不强制下线，每期可回滚 |

**风险排序（决定先做哪一期）**：
① 反代下「回环」可以被伪造（§5.2，能直接搬走数据）→ ② 授权散落、新接口不登记就上线（§8.3）→ ③ 无审计、出了事查不到（§11.2）→ ④ 令牌形态（附录 A，收益最低，最后做）。

一句话：**JWT 只是令牌格式；真正要建的是“身份 → 凭据 → 授权 → 审计”四层。**

## 二、现状与差距

### 2.1 已经有的（复用，不重写）

- `users`（scrypt + 独立 salt，空密码 = 免密）、`roles` / `role_menus`（UI 菜单）、`user_otp`（TOTP + 恢复码）；
- `user_sessions`：**不透明会话 token 只存 sha256**，30 天 HttpOnly Cookie `bandi_sid`；
- 根令牌（数据目录 `token` / `BANDI_TOKEN`）= operator；回环 = operator；
- 节点 `bn_` / 手机 `bd_` / 协作分公司 `bc_`：不透明、中心只存哈希；
- `auth.guard` 做认证；`decide` 做粗粒度 API 面；`mayManage` 做管理动作；`PANEL_FORBIDDEN` 限制 panel；
- `E1094`：`/api/local/*` 只准回环；`guardWrite` 的 Origin + `X-Bandi` 防 CSRF。

### 2.2 缺的（本设计要补）

1. **没有 Principal 统一模型**：`bc_` 在 handler 里自己校验，身份分散；
2. **没有接口级授权**：`/api/local/*` 只按网络位置判，而"网络位置"本身判错了（反代下全部变成回环，见 §5.2）；新接口靠 handler 各写各的；
3. **没有令牌生命周期**：没有 access/refresh、没有轮换、没有复用检测、没有 `tokenVersion` 撤销；
4. **没有路由权限清单**：路由与权限的对应关系散落在 `decide` / `PANEL_FORBIDDEN` / handler 里；
5. **没有安全审计**：登录失败、越权、令牌签发/吊销、加入/退出没有统一留痕；
6. **没有会话管理**：看不到“谁在哪登录”，不能单踢/全踢；
7. **传输与浏览器加固不足**：没有强制 TLS、没有 CSRF token、`?token=` 会进 URL/历史/日志；
8. **没有资源级权限**：项目/机器/分公司的“谁可见、谁可派活”还没有模型。

## 三、目标与非目标

### 目标

- 任何请求都有**唯一 Principal**，任何 API 都有**明确权限**，未声明 = 拒绝；
- 人、机器、设备、分公司、operator 用同一套身份/令牌/审计模型；
- 令牌可过期、可轮换、可撤销；密码/角色变更立即生效；
- 浏览器不持有可被 XSS 偷走的长期令牌；
- 新接口**不登记就上不了线**（测试拦住），不再靠“记得加判断”。

### 非目标（本期不做）

- 多租户 / 组织隔离（表结构预留 scope，不做产品）；
- 完整 OIDC Provider / SSO（保留适配器位，Phase 4 再说）；
- WebAuthn / 硬件密钥、密码less（Phase 4 可选）；
- 外部 SIEM / 告警平台；逐字段审计。

### 4.1 资产

## 五、身份模型（Principal）

每个请求解析成**恰好一个** Principal：

```js
{
  kind: 'user' | 'operator' | 'node' | 'device' | 'branch',
  id,                 // userId / nodeId / deviceId / branchId；operator 为 'root'
  roleId,             // user：roles.id
  permissions: Set,   // 计算后的权限集合（user / operator）
  scopes: Set,        // node/device/branch：compute / panel / mobile / collab
  machineId,          // 节点/设备/分公司归属
  sessionId,          // 浏览器会话或 API 会话
  tokenVersion,       // user 的撤销水位
  via: 'loopback' | 'session' | 'access_token' | 'machine_token' | 'root_token',
  source: 'loopback' | 'network',
}
```

### 5.1 解析顺序（唯一入口 `security/principal.mjs`）

1. `Authorization: Bearer <access token>` → 查哈希（不透明票，**唯一形态**）→ 查用户/机器状态；
2. `bandi_sid` Cookie → 会话表 → 用户；
3. `X-Bandi-Token` / `bandi_token` Cookie → 根令牌 / 节点 / 手机 / 分公司；
4. `source === 'loopback'` 且无凭据 → `operator`（`via: loopback`）；
5. 其余 → `anonymous`。

**歧义规则**：同一请求带多种凭据时按上述顺序取第一个有效者，**不合并权限**；与现行「令牌优先、会话兜底」一致。

**查询参数 `?token=` 不在解析顺序里（v2 改）**。原稿把它列为「仅过渡期」的一项，与 §10「URL 不带长期令牌」直接冲突，实施时必然分叉成两套。改为：只在 `BANDI_ALLOW_URL_TOKEN=1` 时启用、只接受 **operator 根令牌**、命中即 302 换成一次性 `?code=`（§10.4），默认关闭，Phase 1 结束时删除该分支。

### 5.2 `loopback` / `network` 的判定（唯一口径，v2 新增）

**这是本设计里唯一能直接导致数据外带的地方，必须先定死。** 现行 `routes/local.mjs` 的 `isLoopbackRemote()` 只看 `req.socket.remoteAddress`；而 nginx / cloudflared / frp 反代到本机时，**所有外部请求的 remoteAddress 都是 `127.0.0.1`** —— 按 §10 推荐的反代部署一上线，`/api/local/export|import|join` 就对全网开放。

判定看四件事：**监听地址**、**有没有声明可信代理**、**有没有转发头**、**Host 是不是本机/回环**（最后一条 v2.4 补：防止反代漏配转发头时被误判成 loopback）。

| 监听地址 | `BANDI_TRUST_PROXY` | 转发头 | Host | 判定 |
|---|---|---|---|---|
| 回环 | 未设 | 无 | 本机 / 回环 | peer 是回环 → `loopback`；否则 `network` |
| 回环 | 未设 | 无 | 外部域名 | **`network`**（反代漏配转发头，Host 兜底） |
| 回环 | 未设 | 有 | 任意 | `network`（前面架了反代） |
| 回环 | **已设** | 任意 | 任意 | **`network`**（声明了"我在代理后面"= 回环不可信，§5.3） |
| **非回环** | 任意 | 任意 | 任意 | **`network`** —— 服务器形态下 `loopback` 不作为身份 |

```js
// security/principal.mjs —— 全仓唯一判定点，routes 不许自己判
export function classifySource(req, cfg) {
  const peer = normAddr(req.socket?.remoteAddress);
  const forwarded = !!(req.headers['x-forwarded-for'] || req.headers['x-real-ip'] || req.headers['forwarded']);
  if (cfg.trustProxy) return 'network';            // ① 声明了可信代理 → 回环一律不作数
  if (forwarded) return 'network';                 // ② 有转发头 = 不是物理本机
  if (!cfg.listeningOnLoopback) return 'network';  // ③ 监听 0.0.0.0/:: 时不认回环
  if (!isLoopbackAddr(peer)) return 'network';     // ④ peer 必须是回环
  if (!isLocalHost(req.headers.host, cfg)) return 'network'; // ⑤ v2.4：反代漏配转发头时靠 Host 兜底
  return 'loopback';
}
```

> **v2.4 补（第三轮评审）**：只靠「监听 + 转发头 + trustProxy」挡不住一个**漏写 `proxy_set_header X-Forwarded-For` 的反代** —— 外部请求在服务端看就是"回环、无转发头、无 trustProxy"。所以加 Host 兜底：`isLocalHost()` 只认 `localhost` / `127.*` / `::1` / 本机网卡地址 / `os.hostname()`；反代通常会把外部 Host（`proxy_set_header Host $host`）带进来，这一道就能判成 `network`。反代把 Host 也改写成 `127.0.0.1` 的极端配置，只能靠部署契约强制 `BANDI_TRUST_PROXY=1`；两种漏配都要在 Phase 1 用例里覆盖（见 §15）。

**非回环形态怎么证明「我在本机」**：不再靠 IP，改为**持有文件秘密** —— 数据目录下 `local_secret`（0600，首次启动生成），破坏性本机动作要求头 `X-Bandi-Local: <内容>`。能读到这个文件的进程，本来就能改数据库，授权上没有额外损失；而反代转发不过来这个头（除非运维主动配置，届时 §11.2 会留痕）。

- 必须带这个头的动作（v2.5 对齐 §8.5）：`export` / `import` / `collab join|leave` / 算力 `join|leave` / `hosts/*` / `discover` / `probe` —— **`restart` 已移出**（v2.5：`secret:'never'`，理由见 §8.5 注，避免"开了局域网关不回单机"的单向门）；
- 逃生口 `BANDI_LOCAL_SECRET=off`：只给"反代已经 deny 掉破坏性本机路径"的部署用，启动时打一条 warning；
- **部署契约（v2.4 修）**：反代 **deny 破坏性本机路径**（`/api/local/export|import|join|leave|hosts/*`、`/api/local/collab/join|leave`、`/api/local/discover|probe`、`/api/restart`），但**必须放行只读的 `/api/local/status`、`/api/local/collab/status`** —— 原稿写"整组 `/api/local/*` 一律 deny"，会让反代后面的设置页读不到状态，与 §8.5 矩阵直接打架。全组 deny 只作为"不打算用面板管理本机"的激进选项。

### 5.3 回环信任的边界：**认证豁免 ≠ 位置判定**（v2.2 新增，P0）

> **这是比 §5.2 更大的洞，v2.1 漏了。** §5.2 只管住了 `/api/local/*`，但**整站**的免鉴权开关在 `auth.mjs:105`：
> `if (isLoopbackHost(host)) return { required: false, token: '', ... }` —— 只要监听地址是回环，`auth.required = false`，**任何**请求都直接变成 `operator`（`auth.mjs:613`）。
> 而 §10.1.2 恰恰要求反代把流量转进 `127.0.0.1:8787`。两者一叠加：**上反代那天，面板、会话、员工、导出全部免登录**，`/api/local/*` 只是其中一小块。

**规则（v2.4：直接以 `classifySource(req, cfg) === 'loopback'` 为准，四条同时成立）**：

1. **监听地址是回环**（`127.0.0.1` / `::1`），且
2. **没有配 `BANDI_TRUST_PROXY`**，且
3. **这个请求没有带任何转发头**（`X-Forwarded-For` / `X-Real-IP` / `Forwarded`），且
4. **Host 是本机/回环**（`localhost` / `127.*` / `::1` / 本机网卡 / `os.hostname()`；v2.4 补，见 §5.2）。

任一条不成立 → **这个请求不是本机**：`guard()` 不得直接给 `operator`，必须继续走认证（`/api/local/*`、`/api/ai/*`、`/api/events` 全一样）。`BANDI_TRUST_PROXY` 一旦设置，等价于"我知道前面有代理"，此时回环身份只能靠 `X-Bandi-Local`（§5.2）证明，不能靠 IP。

**四处现行代码必须改（Phase 1 第一件事）**：

| 位置 | 现状 | 改成 |
|---|---|---|
| `auth.mjs:587`（`guard()` 内 `if (!auth.required)`） | 只看启动期算出的 `auth.required`，命中就直接给 `operator`（`auth.mjs:613`） | 改成**每次请求现算**：`const trustedLoopback = classifySource(req, cfg) === 'loopback'`（四条规则全在里面）；`trustedLoopback` 才给 `operator`，否则继续往下走认证 |
| `auth.mjs:583`（`/api/ai/*` 免令牌） | `req.socket.remoteAddress` 直接判 | `classifySource(req, cfg) === 'loopback'`；`network` 不豁免 |
| `routes/imageai.mjs:29` | `isLoopbackRemote(req.socket?.remoteAddress)` 直接判 | 同上 —— **Phase 1 就改，别等 Phase 2 的 grep 才发现** |
| `routes/local.mjs:218` | `isLoopbackRemote(...)` 一刀切 | 由 `route-policy` 替代（`source` + `secret: 'network'`） |

> **setup 必须接收 `trustProxy`（v2.4 修）**：`setup()` 是**启动期**调用的（`auth.mjs:104`），那里拿不到 `req`，所以"逐请求是不是本机"仍然只能落在 `guard()`；但 `required` 这个**进程级开关**必须由启动期决定：
>
> ```js
> // auth.setup({ host, dataDir, envToken, trustProxy })
> const required = !isLoopbackHost(host) || !!trustProxy;
> ```
>
> `required` 为真时 setup 要**加载/生成 token 文件**。否则 `BANDI_TRUST_PROXY=1 + 监听回环` 下，`guard()` 逐请求要求认证、而 `auth.token` 仍为空 → root 令牌 / break-glass 不可用（用户会话还能用，但 CLI 与应急入口断了）。
>
> `loopback + 转发头但没配 trustProxy` 属于**误配**：`guard()` 按 `classifySource` 会要求会话认证（用户可登录），但进程没生成 root token；部署契约必须设 `BANDI_TRUST_PROXY=1`（或已有 token 文件）。**别把"进程没开闸"当成"每个请求都是本机"**——这正是 v2.1 的洞。

**禁止**：除了 `classifySource()`，任何地方不得再用 `req.socket.remoteAddress` 做安全判断。Phase 2 的测试扫描要覆盖这一条（`grep -rn "remoteAddress" routes/ auth.mjs` 只允许出现在 `classifySource` 与日志里）。

**Phase 1 验收新增（v2.4 补三条）**：

1. 以 `BANDI_HOST=127.0.0.1 + BANDI_TRUST_PROXY=1` 启动，带 `X-Forwarded-For: 1.2.3.4` 请求 `/api/state`、`/api/sessions`、`/api/local/export`、`/api/ai/image-config`，**四个都必须 401/403**，一个都不许过；
2. **裸反代漏配**：`BANDI_HOST=127.0.0.1`、不设 `BANDI_TRUST_PROXY`、不设 `X-Forwarded-*`，只把 `Host` 设成外部域名请求 `/api/state` —— **必须 401**（Host 兜底生效）；
3. **trustProxy 下的 root 令牌**：`BANDI_HOST=127.0.0.1 + BANDI_TRUST_PROXY=1` 启动后，带 `X-Bandi-Token` 请求 `/api/state` **200**，不带凭据 **401**（证明 setup 确实加载/生成了 token）。

> 相关文档同步：`2026-10-31-本机接口授权-设计.md` 已按本节改成 v4 —— `loopback` 定义、矩阵（拆成「网络 + 秘密」列）、`authorizeLocal()` 签名（收 `source` / `principal` / `hasSecret`）、错误码（`E4090` 未登记 / `E4091` 越权 / `E4097` 缺秘密）四处全部对齐。

## 六、认证方案

### 6.1 浏览器：BFF 会话（推荐，不让浏览器持有 JWT）

- 登录：`POST /api/login`（用户名 + 密码 + 可选 TOTP）→ 服务端建 `user_sessions`，Set-Cookie：
  - `bandi_sid`：不透明 32B，`HttpOnly; Secure(https); SameSite=Lax; Path=/`；
  - `bandi_csrf`：随机值，**非 HttpOnly**（前端读出放 `X-CSRF-Token` 头），双提交校验。
  - **不变量（2026-11-01 实报补）**：**凡是发会话/设备票，必须同时种 `bandi_csrf`** —— 登录、建第一个账号自动登录、改密重签、配对 claim 无一例外；漏一处，那台浏览器之后所有写请求全吃 `E4099`（用户看到"点了没反应"）。兜底：每个 HTML 页面响应在缺 csrf 时补种一枚（打开一次页面即自愈）。
- 会话超时：**空闲 30 分钟 + 绝对 12 小时**（可配）；刷新页面续空闲，不续绝对。
- 退出：删会话 + 清 Cookie（`bandi_sid` 与 `bandi_token` 两张都清）；「退出全部设备」= 删该用户全部会话 + `tokenVersion +1`。
- **回环形态没有"退出"可言**（2026-11-01）：guard 在令牌识别之前就判 `operator via 'loopback'`，清了 Cookie 重载仍是操作员 —— 前端据此**不摆**退出按钮，换成一句说明；有账号后启动即走登录页，那时才有真的登录态可退。
- 为什么不用浏览器 JWT：同源 BFF 下 JWT 没有收益，反而把令牌暴露给 JS；令牌只留给 API / CLI / 机器。

> 如果坚持浏览器也用 JWT：只能放 **HttpOnly Cookie**（不能放 localStorage），并且仍要 refresh + tokenVersion；不推荐。

### 6.2 API / CLI：access + refresh（**不透明 `at_`**；JWT 已定不做）

> **形态已定（2026-10-31）**：access token 用不透明票 `at_`（32B，只存 sha256，10–15 分钟，等价一张短命会话票），refresh 照旧轮换。**JWT 不做**。
> 理由：§7.1 已规定「权限不入 token、PDP 每请求查库」，验签剩下的收益只有「省一次 token 表查询」，抵不过自研验签 + 密钥轮换 + `kid`/`alg`/`base64url` 那一圈攻击面。JWT 的唯一正当理由是**将来拆服务 / 接第三方客户端**——本项目只在一台机器上部署，不拆（附录 A）。

| 接口 | 作用 | 形态 |
|---|---|---|
| `POST /api/auth/token` | 密码 + TOTP（或 refresh token）换 `{access_token, token_type, expires_in, refresh_token}` | 通用 |
| `POST /api/auth/refresh` | refresh 换新 access + 新 refresh（轮换） | 通用 |
| `POST /api/auth/revoke` | 撤销当前 refresh/会话 | 通用 |
| `POST /api/auth/logout` | 撤销当前会话（浏览器/CLI 共用） | 通用 |
| ~~`GET /.well-known/jwks.json`~~ | ❌ **不实现**（JWT 已定不做，附录 A） | — |

- access token（**唯一形态，不透明**）：`at_` + 32B；**10–15 分钟**；`Authorization: Bearer`；不放 Cookie；表 `access_tokens(tokenHash PK, subjectKind, subjectId, kind, scopes, tv, expiresAt, revokedAt)`（见 §12）；
- refresh token：不透明 32B，**只存 sha256**，30 天；**每次刷新轮换**；旧 token 再用 = 复用攻击 → 撤销整个 family + 审计 `E4092`；
- 刷新时校验：会话未撤销、用户未禁用、`tokenVersion` 未变、所属会话种类的绝对超时未到（§9）。

### 6.3 机器身份（节点 / 手机 / 分公司）

- 继续用**不透明长期凭据**（`bn_` / `bd_` / `bc_`，中心只存哈希）；长期 JWT 不可吊销，不适合机器；
- 可选交换：`POST /api/auth/machine-token`（凭机器凭据）→ **短票 `at_`**（10–15 分钟，`kind` + `scopes` + `machineId`），机器到期再换；短票落 `access_tokens`，`subjectKind='machine'`；
- 节点协议可继续用不透明令牌（零改动）；
- 机器凭据支持：最近使用、吊销、轮换（Phase 4）。

### 6.4 operator / 紧急入口

- 根令牌（数据目录 `token`，0600）保留为 **break-glass**；回环无凭据仍 = operator（物理在本机）；
- 根令牌可以换 access token（`POST /api/auth/token` 带 `X-Bandi-Token`），也可继续用不透明头；
- 管理界面里不展示根令牌；只提示文件位置。

### 6.5 密码 / OTP / 恢复码

- scrypt 保持（零依赖）；密码 8–128；空密码 = 免密账号（现有口径，保留）；
- 管理员默认要求 TOTP（可配置）；恢复码一次性；
- 登录失败统一文案 + 时间侧信道处理（现有）；
- 改密码 / 禁用 / 改角色 / 退出全部 → `tokenVersion +1`。

> **本节没有"签名密钥"小节。** 只有 JWT 形态才需要密钥，而 JWT 已拍板不做（附录 A）。原先的 Ed25519 / `kid` / JWKS 内容已整段移入附录 A「A.3 如果将来要做 JWT」，**属于非规范参考，不参与实现**。

## 七、令牌规范

### 7.1 Access token（不透明票 `at_`，唯一形态）

| 项 | 值 |
|---|---|
| 形态 | `at_` + 32B base64url，**无结构、不签名** |
| 存储 | 库中**只存 sha256**（`access_tokens.tokenHash`），原文只在签发响应里出现一次 |
| 生命周期 | 10–15 分钟（§9） |
| 携带 | `Authorization: Bearer <token>`；不放 Cookie、不放 URL |
| 校验 | 查 `access_tokens` → 判 `expiresAt` / `revokedAt` → 取 `subjectKind` / `subjectId` → **再查主体状态**（`users.disabled`、`users.tokenVersion == tv`） |

- **权限不写进票**：票里只有"我是谁"，PDP 每次从库取角色权限（SQLite 点查，单进程足够快）；
- `tv` 与 `users.tokenVersion` 不一致 → 401 `E4093`（已撤销）；
- 机器票的 `kind` 为 `node` / `device` / `branch`，`scopes` 必填，`subjectId` 为机器 id；
- **为什么不做自校验票（JWT）**：见附录 A。一句话——每请求都要查库取权限，验签省不掉那次查询，只剩攻击面。

### 7.2 Refresh Token

- 随机 32B base64url，前缀 `rt_`；库中只存 sha256；
- 表：`refresh_tokens(tokenHash PK, familyId, sessionId, userId, createdAt, expiresAt, usedAt, revokedAt, ip, ua, tv)`；
- 轮换：每次使用写 `usedAt` 并发新 token；旧 token 再用 → 撤销 family + 审计；
- 与 `user_sessions` 一对一/一对多由实现定：**一个会话一个 family**。

### 7.3 撤销策略

| 事件 | 动作 |
|---|---|
| 退出登录 | 删/撤当前会话 + refresh family |
| 退出全部 | 删该用户全部会话 + refresh + `tokenVersion +1` |
| 改密码 / 改角色 / 禁用 | `tokenVersion +1` + 撤全部 refresh |
| 机器移除 | 删机器凭据 + 刷新缓存 + 撤该机器的 `at_` |
| 机器凭据轮换 | 旧凭据保留 24h 重叠窗口（给在线节点换票时间），之后拒绝 |

### 8.3 路由权限清单（默认拒绝）—— ✅ 已落地（`security/route-policy.mjs`，约 130 条）

### 8.4 PDP —— ✅ 已落地（`security/policy.mjs` 的 `authorize()`；`decide()` 已变兼容包装）

```js
authorize({ principal, method, path, resource, source }) -> { ok, code?, reason? }
```

判定顺序：

1. 路由是否存在 → 不存在 404；
2. `auth: public` → 放行；
3. `principal` 为空 → 401；
4. 身份种类允许？（如 `principals: ['operator','user']`）
5. 是 admin 且需要 admin？/ 权限集合包含 `perm`？
6. 来源允许？（按 §5.2 的判定；不在 `source` 集合 = `E1094`；`secret: 'network'` 且来源是 network 而头不成立 = `E4097`）
7. 资源 scope（Phase 4：项目/机器/分公司成员）；
8. 通过。

**为什么来源判在权限之后**：`E4091`（越权）和 `E1094`（位置不对）是两种事实，混成一个 403 会让排查变成猜。顺序固定为「身份 → 权限 → 位置 → 资源」。

`decide()` / `mayManage()` 保留为兼容包装（内部调 PDP）；**路由层已不再用它们**（v2.8 收编完成：roles/pair/node/collab/users 的 handler 闸全部摘除，授权归 PDP 单门；原 handler 闸覆盖的面板边界在清单上显式 `noPanel`。仅剩 `persona.mjs` 一处 —— 那是"改模型/运行时字段"的 body 内容判断，不是身份判断，不算散落角色判断）。

> **v2.7 施工现状（v2.8 已收编）**：`decide()` 已是 `policy.authorize()` 的包装（归属判定 nodeMayReach/runMayReach 经 `rules` 参数注入，避免 security/ ↔ auth.mjs 成环）；成员口径 = **成员基线（member）∪ role_permissions（perm）**，行为与 v2.5 的 deviceMayReach 白名单逐字一致。`mayManage()` 在 v2.8 已收编完毕：roles/pair/node/collab/users 五文件的 handler 闸全部摘除，词表解锁（如给角色授 `user:manage`）在 PDP 层直接放行、handler 不再二次拦；原 handler 闸覆盖的面板边界在清单上显式 `noPanel`。`smoke-security-policy` ⑧ 段已改为验证端到端解锁。

### 8.5 本机接口矩阵（Phase 1，先修当前问题）

「位置」= §5.2 的 `source`；「文件秘密」= `X-Bandi-Local`。

> **v2.2 重画（原表的致命错误）**：原表把 `network` 下的 operator/admin 在 `join|leave|export` 上全写成 ❌，同时又要求这些动作带 `X-Bandi-Local` —— 结果是**服务器形态（监听 `0.0.0.0`）永远进不了 loopback，`collab join` 永远做不了**，也就是本轮要解决的场景本身被表挡住了。修法：把 `network` 拆成**带秘密 / 不带秘密**两列。

| 方法 | 路径 | `loopback` | `network` + `X-Bandi-Local` | `network` 无秘密 | 其余身份（member/panel/node/device） |
|---|---|---|---|---|---|
| GET | `/api/local/status` | ✅ | ✅ operator/admin | ✅ operator/admin（只读，反代要放行，§10.1.2） | ❌ |
| GET | `/api/local/collab/status` | ✅ | ✅ operator/admin | ✅ operator/admin（只读） | ❌ |
| POST | `/api/local/collab/join` | ✅ | ✅ operator/admin | ✅ operator/admin（**v2.7 修 2026-11-02：`secret:'never'`**，单向门论证同 leave，见本机接口授权设计 v10） | ❌ |
| POST | `/api/local/collab/leave` | ✅ | ✅ operator/admin | ✅ operator/admin（**v2.6 收窄注 2026-11-01：`secret:'never'`**，单向门论证同 restart，见本机接口授权设计 v9） | ❌ |
| POST | `/api/local/export` / `import` | ✅ | ✅ operator/admin | ❌ `E4097` | ❌ |
| POST | `/api/local/hosts/*` | ✅ | ✅ operator/admin | ❌ `E4097` | ❌ |
| POST | `/api/local/join` / `leave`（算力） | ✅ | ✅ operator/admin | ❌ `E4097` | ❌ |
| POST | `/api/restart` | ✅ | ✅ operator/admin（`secret:'never'`，见下注） | ✅ operator/admin（`secret:'never'`，见下注） | ❌ |
| 其余 | `/api/local/*` | ✅ | ✅ operator/admin | ❌ | ❌ |

**两条配套结论**：

1. **`local_secret` 只解决"这台机器上的进程"**，不解决浏览器 —— 见 §10.1.3；
2. `/api/restart` 不在 `/api/local/*` 前缀下（实现在 `routes/runtime.mjs:97`），必须**逐条登记**，不能靠前缀规则兜。

**`/api/restart` 的秘密档位 = `never`（v2.5 修，与实现对齐）**：施工时发现 `secret:'network'` 会造成**单向门**——`0.0.0.0` 监听下重启请求被 `E4097` 挡住，而改回单机又必须先重启（`/api/restart`），形成"开了局域网就关不回去"的死锁。重启本身**不动数据、不读秘密、只换监听地址**，泄漏面趋近于零，所以**不要求** `X-Bandi-Local`；operator/admin 身份照旧要过。注意这不是给反代开口子：§10.1.2 的反代契约对 `/api/restart` 仍是**无条件 deny**（直连服务、带 operator/admin 会话的本机浏览器不受影响）。`smoke-auth` ⑩ 已回归验证。

读法：`loopback` 列回答"这台机器的物理用户能不能做"，后面几列回答"从网络来的人（带合法身份）能不能做"。两件事分开判，不要合成一列。

**和 v2.2 的差别（v2.3 修）**：v2.2 曾写「`collab/join|leave` 收成只认物理位置」，与本表第 3、4 行（`network` + 秘密 = operator/admin ✅）自相矛盾 —— **已作废**。现在的口径是：**角色管"是什么身份"，`X-Bandi-Local` 管"能不能碰这台机器"**，两条同时满足才放行。一个从局域网进来的 admin **可以**执行 `join`，只要他手上有一份 `local_secret`（意味着他本来就有这台机器的 shell/文件系统权限）——那时他已经是这台机器的主人，再区分"物理位置"没有意义。

**清点：不能只扫 `routes/*.mjs` 里写死的 `/api/...`，也不能只扫 `auth.guard()` 的豁免**。Phase 0 的扫描范围必须包含**五处**：① `guard()` 豁免；② `decide()` 的 operator 分支；③ `nodeMayReach` / `runMayReach`；④ `deviceMayReach`；⑤ `isPanelForbidden()`。以下是从这五处**实际 grep 出来的全量**（v2.4 补 `runMayReach` / `deviceMayReach`，上一版只扫了前三处）：

| 豁免 | 位置 | 为什么免 |
|---|---|---|
| `POST /api/nodes/join`、`GET /api/hello` | `auth.mjs:519-520` | 新机器还没有令牌，凭一次性邀请码进来；`hello` 故意不带秘密（披露字段与 UDP 应答同源） |

### 8.6 内置账号不变量（v2 新增）

三条，全部进 PDP 前置校验，**不是 UI 层的灰按钮**：

1. **`admin` 隐式 `*`**，不落 `role_permissions`（§8.2）—— 防"误删权限把自己锁死"；
2. **至少保留一个启用的 admin**：把某账号降级 / 禁用 / 删除前检查"剩余启用 admin ≥ 1"，否则 `E4096`。最后一个 admin 点"退出全部"不受限（那只是撤会话，不降权）；
3. **免密账号的 admin 限制，按形态分（v2.2 修，原稿此条与首账号引导冲突）**：`users.mjs:418` 规定**第一个账号强制 `admin`**，而 `checkPassword` 允许空密码 → "免密账号不得 admin"直接把首次开机堵死。改成按形态：

| 形态 | 免密账号 | 理由 |
|---|---|---|
| `loopback`（单机 / 桌面壳） | **允许持有 `admin`**，登录页摆账号磁贴点了就进 | 这是"开机选账户"的既有体验；回环 = 这台机器自己的屏幕 |
| `network`（总机 / 服务器） | **不得持有 `admin`/`security:manage`**；登录只给**受限会话**（仅可改密码/退出），其余 403 `E4098` | 免密 + 管理面 = 任何人打开网页就能改安全策略 |

**首个管理员怎么建（v2.3 补，DeepSeek 抓的 P1 之一）**：`POST /api/users` 在库里没有账号时是公开的（`users.mjs:418` 直接把它建成 `admin`），这在 `network` 形态下等于"**谁先连上谁就是管理员**"。改成按形态引导：

| 形态 | 首账号创建 | 凭据 |
|---|---|---|
| `loopback` | 允许，空密码可以，直接是 `admin` | 无（回环 = 这台机器的屏幕） |
| `network` | **必须同时带 `X-Bandi-Setup`** | 值 = `<数据目录>/setup_code`（0600，首次启动生成，**建成首个 admin 后立即删除**）；或走 CLI `bandi user create --admin`（CLI 读 `local_secret` 调本机回环 API，**不绕过鉴权、不直接写库**） |

- 没有 `setup_code` 文件的服务器，运维用 CLI 建第一个管理员（同 `bandi collab join` 的思路：**破坏性/引导性动作交给本机进程**，见 §10.1.3）；
- `setup_code` 只对"库里零账号"这一种状态有效；已有账号时即使带了也 403（`E4098`），避免它变成第二个后门；
- 缺 / 错 / 文件已删 → `E4098`，文案指向 CLI；
- 这样 `network` 形态既不是"裸奔等第一个访客"，也不需要一上手就配 SMTP 或 OIDC。

**存量免密 admin 怎么恢复（v2.3 修，原来两条规则打架）**：表格里写"不得登录（`E4098`）"，下面又写"登录后强制跳设置页改密"——**免密账号如果完全登不进去，"登录后改密"就永远到不了**。统一成"**受限会话**"：

1. 免密 admin 在 `network` 形态**可以完成登录**（否则没人能救它）；
2. 但会话被标 `restricted=1`：**只放行引导页必需的读 + 改密 + 退出** —— `GET /api/me`（前端 `load()` 拿身份/菜单）、`GET /api/state`、`GET /api/skills`（`load()` 的 `Promise.all` 另一半，缺了整页起不来）、`GET /api/web-version`、非 `/api/*` 的静态 GET（HTML/JS/CSS/图标/SW）、`POST /api/me/password`（设密码）、`POST /api/logout`；其余一律 403 `E4098`；
3. 设密码成功后 `restricted` 自动解除，并要求重新登录（`tokenVersion +1`）；
4. 启动日志 + 设置页顶部红条提示"存在免密管理员，请立即设密码或在 CLI 里 `bandi user passwd`"；
5. **不自动降级、不自动禁用**——自动处理会把现有用户锁在门外。

错误码：`E4096` 最后一个管理员 / `E4097` 缺本机文件秘密 / `E4098` 免密账号不得进管理面。

## 九、会话与凭据生命周期

生命周期按**会话种类**分别定义，两套不能混用（v2 修：原稿把「绝对 12h」和「refresh 30d」并列写在一张表里，实施时必然分叉——refresh 若受 12h 约束，CLI 的 30 天是假的；若不受，浏览器的 12h 被 refresh 绕开）。

| 会话种类 | access | 空闲超时 | 绝对超时 | refresh |
|---|---|---|---|---|
| `browser`（BFF Cookie） | 不签发（会话 Cookie 即凭据） | 30 分钟 | **12 小时** | 不适用，到期即重新登录 |
| `cli` / `api` | 15 分钟 | 不适用 | **30 天**（每次刷新顺延） | 30 天，轮换 + 复用检测 |

**存量会话怎么迁（v2.2 补）**：现有 `user_sessions` 只有 `expiresAt`（30 天），没有 kind、没有绝对/空闲水位。上线当天：

1. 全部存量会话标 `kind='browser'`（现在确实都是浏览器）；
2. `absoluteExpiresAt` **不按"创建时间 + 12h"回推**（那会把所有老会话一次性踢掉），改为 `max(now+1h, 原 expiresAt 截到 now+12h)` —— 给一个 12 小时内的缓冲期，用户下次登录即自然落进新规则；
3. `idleExpiresAt = now + 30min`（从现在起算，不追溯）；
4. 启动日志打一行"N 条存量会话已按新规则迁移，12 小时内自然过期"。

这样不会出现"升级即全体掉线"，也不会出现"老会话永远绕过 12h"。

| 其它项 | 值（可配） |
|---|---|
| 登录失败锁定 | 同一 IP+用户名 5 次/5 分钟 → 429 `E4095`；15 分钟解锁；**计数落 `users.failCount` / `failAt`（最后失败）/ `lockedUntil`（锁定截止）**（重启不清零） |
| 刷新复用 | 立即撤销 family + 审计 `E4092` |
| 机器凭据 | 长期，手动轮换/吊销；最近使用节流写入 |
| 会话列表 | 设置 → 安全：设备/时间/IP/最近使用；单踢/全踢 |

**为什么浏览器不签 access token**：BFF 下 `bandi_sid` 本身就是凭据，再签一个 JWT 只是把同一份权力复制一份出去，多一个被偷的东西。浏览器只持有两样：`bandi_sid`（凭据）和 `bandi_csrf`（不是凭据，是防伪）。

## 十、传输与浏览器安全

### 10.1 TLS（**已定：在 node 外面终结**，ADR-003）

**结论**：班底自己不做 TLS。生产形态由外面那一层（nginx / Caddy / cloudflared / frp）持有证书、完成握手，班底继续只监听明文 HTTP（`127.0.0.1:8787`）。

**为什么**：① 证书签发与续期交给成熟工具，与「零依赖」不冲突（自研 ACME 会破坏它）；② 代码零改动 —— 换成内置 https 要重写 server 创建、WebSocket upgrade、SSE 三条路径；③ 「有公网 IP 用反代 / 没有就用隧道」这两个分支对代码的要求完全相同（都是"前面终结 + 可能带 `X-Forwarded-*`"），**这一格可以推迟到上线时按成本算，不阻塞任何一期**。

#### 10.1.1 启动时的检查（Phase 1 只做这一层，不实现 TLS）

| 条件 | 行为 |
|---|---|
| 监听回环（`127.0.0.1` / `::1`） | 不检查、不告警 —— 单机形态零配置不变 |
| 监听非回环 + 无 `BANDI_TRUST_PROXY` + 无 `BANDI_TLS_*` | **warn 日志 + 登录页顶部黄色条**：「当前明文 HTTP，同网段可嗅探密码与 Cookie」 |
| 同上 + `BANDI_TLS_STRICT=on` | **error 拒绝启动**（给"必须防呆"的公网部署用） |
| 有 `BANDI_TRUST_PROXY`（声明"我在可信反代/隧道后面"） | 不告警；同时启用 §5.2 的转发头识别（同一个开关，别设两个） |

> v2 早期写的是"非回环无 TLS 一律拒绝启动"，**已推翻**：局域网总机（家里两台机、公司内网）是正常用法，一刀切会把这类部署直接挡在门外；而自签证书在浏览器里还要点"继续访问"，体验比明文更差。

#### 10.1.2 部署契约（反代和隧道都要满足）

**必须 deny 的是「破坏性本机路径」，不是整个 `/api/local/` 前缀**（v2.3 修）。

原稿写"整组 `/api/local/*` 一律 deny"，与 §8.5 矩阵直接打架：矩阵允许 `network` 来源读 `/api/local/status` 与 `/api/local/collab/status`（设置页要显示本机与协作状态），全组 deny 之后反代后面的面板就永远读不到状态。

```nginx
# 破坏性本机路径：一律 403（这是第二道，不是第一道 —— 第一道是 §5.2 的 X-Bandi-Local）
# v2.4 补：collab/(join|leave) 是这轮协作的核心破坏性接口，必须单列；discover/probe 也要挡（SSRF/探测面）
location ~ ^/api/local/(export|import|join|leave|hosts/|discover|probe|collab/(join|leave)) { return 403; }
location = /api/restart                                { return 403; }   # ⚠️ 不在 /api/local/ 前缀下，必须单写
# 只读状态：放行（否则反代后面的设置页看不到本机/协作状态）
#   /api/local/status、/api/local/collab/status —— 不写 location，自然走下面的通用 proxy_pass

location /api/events {                 # SSE 不能被缓冲，否则事件流被攒住
  proxy_buffering off;
  proxy_read_timeout 1h;
  proxy_http_version 1.1;
  proxy_set_header Connection '';
}

location / {
  proxy_pass http://127.0.0.1:8787;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;   # 配了它 = 必须同时设 BANDI_TRUST_PROXY=1
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

```caddyfile
# Caddy：默认不缓冲 text/event-stream，只需挡破坏性路径（v2.4 补 collab/discover/probe）
@dangerous path /api/local/export /api/local/import /api/local/join /api/local/leave /api/local/hosts/* /api/local/discover /api/local/probe /api/local/collab/join /api/local/collab/leave /api/restart
respond @dangerous 403
reverse_proxy 127.0.0.1:8787
```

> ⚠️ **两个必须成对的动作**：写了 `X-Forwarded-For` 就必须设 `BANDI_TRUST_PROXY=1`，否则 §5.2 会把请求判成 `network`（有转发头）—— 这是安全的一侧，出错只会"更严"；反过来设了 `BANDI_TRUST_PROXY=1` 却没写转发头，`status` 仍然可用，但本机 CLI 带 `X-Bandi-Local` 才是唯一能执行破坏性动作的路。
> ⚠️ **`deny` 只是纵深防御**，真正拦得住的是 `X-Bandi-Local`：即使运维漏写这一段，没有秘密文件也调不动 `export`。

| 你的网络条件 | 用哪种 | 说明 |
|---|---|---|
| 有公网 IP（VPS / 公司专线）+ 域名 | nginx / Caddy 反代 | 443 接客 → 转 `127.0.0.1:8787` |
| 无公网 IP / 运营商不开端口 | cloudflared / frp 隧道 | 主动外连，服务商在公网接客再送回来 |

**这一格什么时候定**：等真要上线那天，按带宽 / 流量 / 域名成本算。两种做法对班底的要求一致，现在定不下来不影响 Phase 0–2 的任何工作。

#### 10.1.3 `local_secret` 怎么交到"人手"上（v2.2 新增）

原稿只说"破坏性动作带 `X-Bandi-Local`"，**没说这个头由谁来带**。三个错误答案先说清楚：

| 做法 | 为什么不行 |
|---|---|
| 服务端把 secret 注入页面（`<meta>` / `window.__`） | 任何一个 XSS 就把它带走，而且它等于全站破坏性权限 |
| 放进 Cookie | 浏览器会自动带，等于**任何页面上的 CSRF 都能触发导出**；跨 host / 代理边界还会丢 |
| 放 localStorage | 同 XSS 问题，且永不过期 |

**正确做法：CLI 优先，浏览器不做破坏性动作。**

- **服务器形态（`network`）**：算力 `join|leave` / `hosts/*` / `discover` / `probe` 一律**由本机终端发起**，CLI 自己读 `<数据目录>/local_secret` 并带头；浏览器里这些按钮**直接不渲染**（不是渲染后报错）。**`collab join|leave`、`export` / `import`、`restart` 例外** —— 依次放宽成 `secret:'never'`（v2.6 / 本机接口授权设计 v8–v10）：单向门论证同 restart，operator/admin 会话即可在界面里操作；
- **单机形态（`loopback`）**：不需要秘密，按钮照旧，行为一行不变；
- 前端判断依据：`/api/state` 返回 `source` 与 `localSecret: 'not-required' | 'required'`，页面按它显隐，**不猜**。

这条同时解决了 §10.4 的同类问题：一次性 `?code=` 的**发起方**也必须是本机进程（CLI / 桌面壳），不能是网页自己——网页能自己换 Cookie 的话，`?code=` 就退化成一次无用跳转。

### 10.2 Cookie / CSRF

**先分两种部署（v2.2 修）** —— 原稿只写 https 形态，落到"非回环明文"（§10.1.1 允许）时登录会直接不可用：

| 部署 | `bandi_sid` | `bandi_csrf` | 损失 |
|---|---|---|---|
| **https（推荐）** | `HttpOnly; Secure; SameSite=Lax; Path=/`，加 `__Host-` 前缀 | 非 HttpOnly，加 `__Host-` 前缀 | 无 |
| **明文 HTTP（局域网临时）** | `HttpOnly; SameSite=Lax; Path=/`，**不加 `Secure`、不加 `__Host-`** | 同左 | 子站可覆写 Cookie（cookie tossing），双提交只剩 Origin + `X-Bandi` 两道 |

`Secure` 与 `__Host-` 前缀都以 Secure 为前提，明文下带上就等于**浏览器不保存这个 Cookie** → 登录死循环。所以两者必须跟着部署形态二选一，**不能写死**；明文分支启动时按 §10.1.1 打 yellow 提示。

- 双提交 + Origin 校验 + `X-Bandi` 三道并存，任一不合即 403 `E4099`；
- CORS：仅 `BANDI_ORIGINS` 白名单；不允许 `*`；带凭据请求必须精确 Origin。

### 10.3 安全头

`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`（或 CSP `frame-ancestors 'none'`）、`Referrer-Policy: no-referrer`、基础 CSP（`default-src 'self'`，按前端实际需要放行）。

### 10.4 URL 不带长期令牌（`?token=` → `?code=`）

现有 `?token=` 会进地址栏、浏览器历史、反代日志。换成一次性码：

1. 本机生成 `code`（32B、**60 秒**、**单次**、绑定 client 指纹），通过本地回环调用交给浏览器；
2. 浏览器 `GET /?code=xxx` → 校验后 `Set-Cookie: bandi_sid` → `302` 到干净 URL；
3. 失败统一 `E4094`（无效/过期/已用），**不区分原因**。

唯一保留 `?token=` 的场景：`BANDI_ALLOW_URL_TOKEN=1` 且仅 operator 根令牌（§5.1）。

### 10.5 Host / 来源

- Host 守卫保留（DNS rebinding）；
- **`X-Forwarded-*` 只用于"确认是可信代理"，绝不用于"升级身份"**：出现转发头 = `network`，判定见 §5.2。

## 十一、滥用防护与审计

### 11.1 限速

| 端点 | 限制 |
|---|---|
| 登录 / OTP | 5 次/5 分钟/IP+用户名；锁定 |
| token / refresh | 20 次/分钟/IP |
| 加入（节点/协作/手机） | 10 次/分钟/IP |
| 导出 / 导入 | 3 次/分钟/用户；**需本机文件秘密**（§5.2） |
| 全局 API | 1200 次/分钟/身份（可配） |

实现：内存滑动窗口 + 429 `E4095`。**登录失败计数落库**（`users.failCount` / `failAt` / `lockedUntil`，Phase 1 就做）——窗口可以随重启清零，锁定状态不行，否则"重启一次就解锁"在无人值守的服务器形态下等于没锁。多机形态（总机 / 各分公司）各自限速，不做跨机聚合。

### 11.2 审计

新表 `security_events`：

```sql
id TEXT PRIMARY KEY,
at TEXT NOT NULL,
kind TEXT NOT NULL,        -- login / authz.deny / token.issue / token.refresh / token.revoke /
                           -- session.revoke / machine.join / machine.revoke / export / import / role.change
actorKind TEXT, actorId TEXT,
action TEXT, resource TEXT,
result TEXT NOT NULL DEFAULT 'pending',  -- pending / ok / deny / fail（v2.4：NOT NULL + 默认，防 NULL 绕过触发器）
reason TEXT,               -- 错误码或短原因
httpStatus INTEGER,        -- 响应收尾回填（v2.3 加）
endedAt TEXT,              -- 响应收尾回填；- at 的差即 handler 耗时（v2.3 加）
ip TEXT, ua TEXT, requestId TEXT
```

**记录责任划分（v2 新增）** —— 不靠 handler 自觉，否则 Phase 3 收编完你会发现漏一半：

| 事件 | 谁记 | 什么时候写 | 漏不漏得了 |
|---|---|---|---|
| 认证失败（401）、越权拒绝（403） | `authenticate()` / `authorize()` 内部**无条件记** | 当场写，`result='deny'` | 漏不了（handler 根本不参与） |
| 写操作（POST/PUT/PATCH/DELETE） | 策略层按路由清单的 `perm` **先写一条 attempt** | 授权通过后立刻写 `result='pending'`；响应收尾时 `res.on('finish')` 把**同一行**改成 `ok` / `fail` | 漏不了 |
| 业务细节（改了哪些字段、导出多少行、踢了谁） | handler 调 `audit.note()` 补一条 | handler 内 | 靠自觉，但只影响"细节"，不影响"有没有" |

**attempt → result 的写入方式（v2.3 修，这是 DeepSeek 抓的第 3 条）**：v2.2 写"先记一条 attempt 占位，再回填 result"，但 §12 的 `BEFORE UPDATE` 触发器会把回填直接 `RAISE(ABORT)` —— **回填就是 UPDATE，两条规则不可能同时成立**。

选定的解法是**允许且只允许一次 `pending → ok|fail` 的状态迁移**（不是记两行，也不是取消 append-only）：

```sql
CREATE TRIGGER trg_events_no_update BEFORE UPDATE ON security_events
WHEN COALESCE(OLD.result,'') <> 'pending'
  OR COALESCE(NEW.result,'') NOT IN ('ok','fail')
  -- v2.4：只允许改 result/reason/httpStatus/endedAt；身份/时间/动作等字段一律不许动
  OR OLD.id          IS NOT NEW.id
  OR OLD.at          IS NOT NEW.at
  OR OLD.kind        IS NOT NEW.kind
  OR OLD.actorKind   IS NOT NEW.actorKind
  OR OLD.actorId     IS NOT NEW.actorId
  OR OLD.action      IS NOT NEW.action
  OR OLD.resource    IS NOT NEW.resource
  OR OLD.ip          IS NOT NEW.ip
  OR OLD.ua          IS NOT NEW.ua
  OR OLD.requestId   IS NOT NEW.requestId
BEGIN SELECT RAISE(ABORT, 'security_events is append-only'); END;
```

- 只有 `result='pending'` 的行可以被改，且只能改成 `ok` / `fail`；改第二次（`ok → fail`）或改别的行 = ABORT；
- **v2.4：允许变的列只有 `result` / `reason` / `httpStatus` / `endedAt`**；`id/at/kind/actor/action/resource/ip/ua/requestId` 任一变化都 ABORT（否则"pending 行"可以被改写成另一条历史）；
- 回填语句固定为 `UPDATE security_events SET result=?, reason=?, httpStatus=?, endedAt=? WHERE id=? AND result='pending'` —— **`AND result='pending'` 是并发下的幂等保证**；
- 进程崩溃留下的 `pending` 行本身就是线索（"这次写操作没走完"），比丢记录好；
- 归档 / 清理走 `BEFORE DELETE` 的另一路（见下），不碰 UPDATE 这条路。

> 备选方案（若 SQLite 触发器在增量迁移里不好维护）：**记两行**——`attempt`（`kind='write.attempt'`）与 `result`（`kind='write.result'`），共用同一个 `requestId`，把"有没有做"和"成不成"拆开。代价是查询要 group，好处是零 UPDATE、append-only 绝对严格。**本项目选前者**（一行两阶段），因为审计页要看的是"一次操作"。两种都满足"handler 漏不掉"这个核心要求。

- 只追加；索引 `(at)`、`(actorId, at)`；保留 90 天（可配）；
- **append-only 用两条触发器兜底**（v2.3 改，原句写的 `BEFORE UPDATE/DELETE` 与上一段的回填冲突）：
  - `trg_events_no_update`：**只放行 `pending → ok|fail` 一次**，其余 UPDATE 全部 `RAISE(ABORT)`；
  - `trg_events_no_delete`：任何 DELETE 全部 `RAISE(ABORT)`。
- 清理走单独的归档语句（`INSERT INTO security_events_archive ... ; DELETE`，归档时临时 `DROP` 删除触发器 + operator 身份 + 往新表留一条 `kind='audit.archive'`），**不支持就地 UPDATE 改写历史**；
- 记录：登录成功/失败、越权（含身份/路径/来源）、令牌签发/刷新/复用、会话撤销、机器加入/移除、导出/导入、角色/权限变更；
- UI：设置 → 安全 → 审计（admin），支持按人/类型/时间筛；
- 日志中**不写令牌明文/密码/OTP**；`ip` 只存完整地址，不做脱敏（内部工具，排查优先）。

> **2026-11-09 实现注记（降噪与保留期）**：本节最初按"每个请求一行"落库，实测本机 5 天
> 攒出 23 万行 / 25 MB（94% 是桌面壳探活 `GET /api/state` 的 401）。现在三条上限：
> ① 静态资源（非 `/api/`，如 `/style.css`、`/js/*.mjs`、`/manifest.webmanifest`）被 401 挡下
> **不入审计**——闸照旧挡，只是不算安全事件；② 同一 (IP, 动作, 原因) 的拒绝在 **60 秒窗口内
> 只落一行**，窗口过后补一行并在 reason 里写"另有 N 次"（"拒绝必记"仍然是记的，只是不再一行一次）；
> ③ 主表保留 90 天不变，**归档表按事件时间保留 1 个月**，启动时清理并往主表留 `audit.prune` 痕。
> 实现：`store/audit.mjs` 的 `deny()` / `pruneArchive()`；冒烟：`smoke-growth-caps.mjs` +
> `smoke-audit.mjs` ④ 的两条降噪断言。

## 十四、迁移路线（四期，每期可回滚）

**顺序原则（v2 改）：授权先于令牌。** 原稿先做 JWT（Phase 2）再收编授权（Phase 3），等于在入口还没统一的时候又插一条认证路径，散落面反而变大；而 JWT 的收益（§7.1 已规定每请求查库）本来就最低。新顺序把"堵漏"提到"换格式"之前。

| 期 | 主题 | 解决的风险 | 能跳过吗 |
|---|---|---|---|
| Phase 0 | 骨架与清点 | 现状不可见（有多少接口、多少豁免） | 不能 |
| Phase 1 | 会话加固 + 审计 + **回环判定** | 令牌撤不了、出事查不到、**反代下回环可伪造** | 不能 |
| Phase 2 | 全站授权收编（PDP）—— ✅ **2026-10-31 完成** | 越权、新接口不登记就上线 | 不能 |
| Phase 3 | 令牌形态（只做不透明 `at_`，**不做 JWT**） | CLI / 脚本的短期凭据 | 能 |
| Phase 4 | 资源级与外部身份 | "谁可见哪台机器 / 哪个项目" | **能**（本期不做；触发条件见 Phase 4 节） |

**验收**：登录/退出/改密码/停用即时生效；越权有审计且 handler 没参与；**反代伪造 loopback 的用例被拒**；**`smoke-proxy-auth` 五条路径全 401/403**；`grep -rn "remoteAddress" apps/server/src` 只剩三处记录用途；单机形态（监听回环、无代理）零配置行为一行不变；`smoke-auth` / `smoke-users` / `smoke-lan-origin` 全绿。

### Phase 2：全站授权收编（**原 Phase 3**）

- 所有 `/api/*` 进路由清单；`decide` / `PANEL_FORBIDDEN` / `mayManage` 改为 PDP 包装；
- `role_permissions` + 角色管理页（勾权限）；手机/节点权限映射；
- 删除 handler 里的散落角色判断；§8.6 的不变量进 PDP 前置校验。

**验收**：路由覆盖率 100%；矩阵用例；现有 smoke 全绿；普通用户/手机/节点越权回归；`grep -rE "mayManage|PANEL_FORBIDDEN|E1094" routes/` 只剩包装层。

### Phase 3：令牌形态（**原 Phase 2**；**已定：只做不透明票，不做 JWT**）

> 拍板依据（2026-10-31）：部署形态就是**一台机器、一个 node 进程、一个 SQLite**，不拆服务、不接第三方客户端。JWT 的唯一价值（让连不上库的进程自验身份）在这里不存在；而 §7.1 规定每请求查权限表，验签也省不掉那次查询。将来真要拆，补这一段是**纯加法**（入口多一个 Principal 解析分支），不需要回滚任何一期。

- 只做 `at_` 不透明短票 + `refresh` 轮换 / 复用检测（约 150 行，无密钥、无 `alg`/`kid` 攻击面）→ ✅ 已落地（v2.8，见版本摘要 1）；
- **不做**：`jwks`、`kid` 轮换、JWT 签发/验签（`security/keys.mjs`、`jwt.mjs` 整段不实现）；
- 机器凭据换短票（先 CLI / 脚本，节点协议不动）→ ⏸ 可选口 `/api/auth/machine-token` 本期未做；CLI / 脚本已可用密码换票或根令牌换 break-glass 票，节点协议零改动。

**验收**：签发 / 过期 / 篡改 / 复用 / 撤销用例；旧会话与根令牌继续可用 → ✅ `smoke-token`（§15）。**不需要** JWT 负向用例集（附录 A 的触发条件成立时才补）。

### Phase 4：资源级与外部身份（**已定：本期不做**）

> 拍板依据（2026-10-31）：现在**只有一个真人用户**，短期内不会有第二个协作的人。资源级权限解决的是"多人之间互相不可见"，在这个形态下没有需要保护的对象。
> **触发条件**：出现第 2 个真人用户，且他**不该看到全部**会话/项目。届时先做下面第一条的「中间态」，不要直接上全量过滤。

- **中间态（触发时先做这个）**：`project_members(projectId, userId)` + 只在「项目列表」「项目详情」两条查询上过滤；其余资源保持全局。成本约全量的 1/10，表结构以后扩全量不用改；
- 全量：项目/机器/分公司的成员与 scope（形状参考若依 `@DataScope` 的"角色上的数据范围维度"，不是纯 ACL 表，见附录 B）——**注意 PDP 只能判动作，行级可见性必须落进 `store/` 的每条查询**，漏一处就是越权读；
- 外部 OIDC（Keycloak / Authentik）适配器、WebAuthn —— 与人数无关，可按需单独启用。

## 附录 A：令牌形态取舍 —— 为什么只做不透明票、不做 JWT（ADR-001）

**背景**：本设计的授权部分规定「权限不写进 token、PDP 每请求从库取」+「`tv` 每次校验」。这意味着**无论用哪种令牌，每请求都要落一次 SQLite**。

| 方案 | 收益 | 代价 |
|---|---|---|
| **A. 不透明 `at_`（默认）** | 代码约 150 行；撤销即时（删行）；无密钥；无 `alg` / `kid` / `base64url` 攻击面 | 每请求查一张 token 表（单进程 SQLite 点查，60 QPS 无感）；非标准 |
| B. JWT（EdDSA） | 标准格式；将来拆服务/接第三方能直接接；跨服务验签不用共享库 | 自研验签（本项目零依赖）；密钥文件 + `kid` 轮换 + JWKS；负向用例至少 4 条 |
| C. JWT（HS256） | 实现最短 | 密钥要分发到每个验证方；单密钥泄漏全盘皆输 |

**决策（2026-10-31 拍板）：只做 A，B 不做，C 也不做。** 依据：部署形态固定为**一台机器、一个 node 进程、一个 SQLite**，不拆服务、不接第三方客户端 —— B 的唯一价值（让连不上库的进程自验身份）在这里不存在。

**B 的触发条件（满足任一才回头补）**：① 真的把某部分拆成了独立进程（执行器 / 面板 / 协作同步）；② 要接第三方客户端（浏览器插件 / 原生移动端 / 别人的系统）；③ 需要把只读权限下放到某个不共享库的进程。补的时候是**纯加法**（入口多一个 Principal 解析分支），不影响既有会话。

**为什么不选 C**：机器 / 节点 / 分公司本来就从中心拿凭据，多一个共享密钥只是多一个泄漏面，换不来任何"无状态"的实际收益——它们本来就连着中心。

**若走 B，最低要求**：固定 `alg` 白名单（只 EdDSA）、严格 base64url（拒绝 padding 与非法字符）、`kid` 必须命中已知键、`exp`/`iss`/`aud`/`typ` 全验、拒绝重复键的 JSON、token 长度上限 4KB。这六条没跑通不许合并。

### A.3 如果将来要做 JWT（**非规范，仅备查；当前不实现**）

> 本节是从正文 §6.6 / §7.1 原样搬过来的参考材料。**它不是本设计的一部分**：没有任何一期会实现它，Phase 0 的实现者请直接跳过。
> 保留它的唯一理由：真到了附录 A 的触发条件那天，不用重新设计一遍字段和密钥管理。

**Header**：`{ alg: "EdDSA", typ: "JWT", kid: "k1" }`

**Payload**：

```json
{
  "iss": "bandi:<instanceId>",
  "aud": "bandi-api",
  "sub": "u_xxx",
  "typ": "access",
  "kind": "user",
  "role": "admin",
  "tv": 3,
  "scopes": [],
  "mid": null,
  "jti": "…",
  "iat": 1790000000,
  "exp": 1790000900
}
```

- 权限仍不写死进 token：`role` / `tv` 只是提示，PDP 照旧每次从库取（所以做 JWT 也省不掉那次查询）；
- 密钥：Ed25519（`node:crypto`），`jwt-keys.json`（0600）存当前 + 上一把，`kid` 轮换；HS256 只作测试回退（`BANDI_JWT_HS256_SECRET`，不落库）；
- 禁止 `alg: none`；验证时固定算法白名单 + `iss` / `aud` / `exp` / `typ`；
- 机器票的 `kind` 为 `node`/`device`/`branch`，`scopes` 必填，`sub` 为机器 id；
- 若启用，`access_tokens` 表退化为 `jti` 黑名单，`smoke-auth-jwt.mjs` 同时补上。

## 附录 B：与若依（RuoYi）式 RBAC 的对照（ADR-002）

**不是同一物种**：若依是通用后台管理脚手架（Java + `sys_user` / `sys_role` / `sys_menu` 三十余张表 + 代码生成器），解决"很多人、很多部门、很多按钮"；班底是自托管单进程工具，解决"一台机器、几台设备、一个人"。拿若依套班底会重得跑不动，拿本设计套企业后台会缺数据权限和审计自动化。

| 维度 | 本设计 | 若依 |
|---|---|---|
| 授权模型 | RBAC + `域:动作` 词表 + PDP | RBAC + 菜单/按钮 perms 串 + `@PreAuthorize` |
| **默认拒绝** | **有**（路由清单 + 未登记测试红） | **无**（漏写注解就裸奔） |
| 浏览器令牌 | BFF HttpOnly Cookie，JS 取不到 | JWT 交前端，XSS 直接带走 |
| 令牌轮换 | refresh family + 复用检测 | 无（Redis 滑动续期） |
| 即时撤销 | `tokenVersion` + 会话表 | 删 Redis key（效果等价） |
| 数据权限 | Phase 4，暂时没有 | `@DataScope`（全部/本部门/本人），成熟 |
| 审计 | 策略层自动记 `security_events` | AOP 自动 `sys_oper_log` + 登录日志 |
| 机器身份 | 一等公民（node/device/branch） | 无，需自己加 |
| 多租户 | 明确不做 | 社区版无，Plus 版有 |
| 生态 / 人力 | 无 | 极大（Java 人才 + 教程 + 代码生成） |

**该抄的三样**

1. `@DataScope` 的思路：把"数据范围"做成**角色上的一个维度**，而不是散在每条 SQL —— Phase 4 的 `project_members` 按这个形状设计，别做成纯 ACL 表；
2. 切面式自动审计（本设计用"策略层无条件记"达到同一效果，见 §11.2）；
3. "超管不可删改"的硬规则（本设计补成 §8.6 的不变量）。

**不该抄的三样**

1. 把 token 交给前端 JS（XSS 直接带走长期凭据）；
2. 按钮级 perms（几百个字符串，对班底是纯维护负担，§8.1）；
3. 用注解 / 约定做授权（漏了不报错）—— 本设计的"路由未登记即测试红"是刻意反着来的。
