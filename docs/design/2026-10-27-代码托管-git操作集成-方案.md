# 代码托管 · 一站式 git 操作集成（方案 + 实现）

> 2026-10-27｜提出：用户（两张截图：同类工具的分支切换器弹层、班底「工作台 › 代码托管」页）
> 输入原话（转述）：「我想完善一下这个代码托管功能，可以参考这种分支形式」「我觉得专业 IDE 里的 git 操作集成得更好，班底有没有办法集成」
> 状态：**已实现**（范围经用户拍板：分支 + 改动 + 历史三件套；冲突合并编辑器、图形化拓扑图明确不做）。

---

## 0. 结论

班底是本地 server 直接跑 git，专业 IDE 那套核心操作大多能实现，而且地基已有一半：
「建 PR」弹窗会读改动文件、提交、推分支，「同步」就是 pull。这一轮把这三块补齐成
**一站式 git 操作**：

1. **分支切换器** —— 详情头当前分支 pill（createCombo 胶囊皮）：搜索、本地/远程分组、
   当前分支 ✓、末尾「拉取更新」（fetch --prune）；点分支 = 确认后 checkout，远程分支由
   git dwim 建本地跟踪分支。
2. **改动管理** —— 详情区「改动」卡：提交行（说明 + 提交）+ 未提交文件行（增/删/改/移
   徽标）；点行展开**只读 unified diff**（+/− 上色，超 1200 行截短）；行尾「丢弃」= 单文件
   Rollback（危险色确认）。提交**不建 PR、不推送** —— 推送是 head-actions 上独立的
   「推送」按钮，与 git 的两步语义一致。
3. **历史** —— 详情区「历史」卡：HEAD 最近 50 条（sha · 主题 · 作者 · 时间），只读。

## 1. 这轮不做

- 新建 / 删除分支（切换器的后续小增量）
- 三路冲突合并编辑器（专业 IDE 最重的一块，要自建编辑器 UI）
- 图形化提交拓扑图（git graph）

## 2. 服务端（`apps/server/src/git-repos.mjs` + `routes/git.mjs`）

新段「分支 / 改动 / 历史（2026-10-27）」，全部**只读本地 git**（除 fetch/push），复用
`gitIn` / `workState` / `assertBranchName` / `findSecretPaths` / `commitIdentityArgs` ——
凭据闸、提交身份、推送错误翻译与建 PR **同一套**，不另写一份。

| 函数 | 端点（错误码） | 要点 |
| --- | --- | --- |
| `listBranches` | GET `branches`（E1101） | `for-each-ref` 本地 + 远程，滤掉 `origin/HEAD` |
| `checkoutBranch` | POST `checkout`（E1102） | `origin/` 前缀剥掉交给裸 checkout（dwim 建跟踪分支）；**脏工作区拒绝**（同 settleAfterMerge） |
| `commitAll` | POST `commit`（E1103） | 空说明/空改动拒；疑似凭据拦（`allowSecrets` 二次放行）；`add -A` + `commit` |
| `pushCurrent` | POST `push`（E1104） | 推人当前站着的分支（不替人挑、不拦直推 main），**绝不强推**，拒收/没权限翻译成人话 |
| `fetchRepo` | POST `fetch`（E1105） | `fetch --prune origin`，只刷远程清单不动工作区 |
| `recentLog` | GET `log`（E1106） | HEAD 最近 50 条；空仓库不算错 |
| `fileDiff` | GET `diff?path=`（E1107） | 统一 `git diff HEAD`（staged+unstaged 合一份，IDE 本地改动口径）；未跟踪先 `add -N` 再看 |
| `discardPaths` | POST `discard`（E1108） | path 必须在**当下** dirty 清单里；按 X 列分派：`??`→clean、`A`/`R`/`C` 新路径→`rm -f`、其余→`checkout HEAD --`（index+工作区一起回 HEAD），重命名两路径都处理 |

## 3. 前端（`apps/web/js/skills.mjs` + `style.css`）

- 详情头：`<span class="gr-branch">` 挂 createCombo（`search:true`、placeholder「搜索分支」、
  `buttonText` 整体接管写当前分支 / 游离 HEAD）；`onOpen` 才拉分支清单。
- 切分支确认照「回 main」：确认前**现读一次** `/changes`（不联网秒回），摆「当前 → 目标」、
  ahead 提醒（危险色）、脏工作区说明；取消/失败都把 pill 文案复位。
- 「改动」卡在 `/changes` 回来后画：干净 → 一行灰字；有改动 → 提交行 + 文件行
  （`data-chg-path` 行 + 相邻 `.gr-diff` 容器，懒取：点开拉一次、收起不销毁）。
  提交被凭据闸拦 → confirmDo 危险确认 → 带 `allowSecrets` 重发。
- 「历史」卡 `/log` 回来后画；空仓库显示 git 的原话。
- 样式 `gr-` 前缀沿用现有变量；徽标增/删/改/移 = ok/bad/accent/warn 四色文字。

## 4. 护栏清单（验收必测）

1. 脏工作区切分支 → 服务端拒绝、原话带回（不吞改动）。
2. 疑似凭据提交 → 先拦，「就是要提交」确认后才放行。
3. 丢弃：path 不在当前清单 → 拒（防旧清单/乱传路径）；未跟踪文件丢弃 = 删除（确认文案写明）。
4. 推送：非 fast-forward → 拒收提示先同步；令牌没写权限 → 说清是 Contents: write。
5. push/fetch 不经 `--force`；所有 git 失败原话带回，不谎报成功。

## 5. 二改（同日）：分支弹窗升级成专业 IDE 的形态

用户第二张截图是专业 IDE 的 Git 分支弹窗（搜索「分支和操作」、顶部操作区、最近/本地/远程/标签四分组）。
原弹窗（本地/远程两组 + 拉取更新）升级为：

- **顶部操作区**：更新项目（=「同步」的 pull）、提交…（聚焦改动卡提交框）、推送…、
  新建分支…。搜索框 placeholder 改「搜索分支和操作」—— createCombo 本来就按 label 过滤，搜"推"能命中操作。
- **四分组**：最近（HEAD reflog 的 `checkout: moving from X to Y` 派生，只留本地分支、去重、限 6）、
  本地、远程、标签（`refs/tags` 按创建时间倒序、限 30）。
- **新建分支**：`POST /branch`（E1109）→ `git checkout -b`，**从当前 HEAD 拉出、不做脏工作区闸**
  （checkout -b 不动文件，把没提交的改动带到新分支正是"干到一半开新线"的用法）；重名/非法名翻译成人话。
- **切标签**：走 checkoutBranch（`git checkout <tag>` 进游离 HEAD），确认框写明后果
  （提交/推送停用、切回任意分支即恢复）。**「签出任意修订」不做**——游离 HEAD 太深，从简。

**两条明确边界**（回答"能不能照专业 IDE 全搬"）：

1. **快捷键不搬**：Ctrl+T / Ctrl+K / Ctrl+Shift+K 是浏览器自己的（新标签页、地址栏），网页抢不到；
   只做菜单项。
2. **「拉取更新」（纯 fetch）被「更新项目」（pull）取代**：两个"拉"并存只会让人选错；
   远程清单的更新随 pull 走。

服务端新增：`listBranches` 回体加 `recent[]` / `tags[]`，`createBranch`，端点 `POST /branch`（E1109）。

## 6. 三改（同日）：分支树 + 折叠不关窗

用户第三张截图是专业 IDE 的**分支树**（本地里按 `/` 前缀分出可折叠文件夹：bandi/ 装着两条 bandi 分支），
外加实报「点击折叠展开不要关闭弹窗」：

- **前缀文件夹**：`folderize()` 把 `前缀/名字` 的分支收进「前缀」文件夹（`bandi/x`、`bandi/y` →
  文件夹 bandi 装 x、y），叶子缩进一层成树形；无前缀的（main）直接排组里。文件夹也是可折叠行
  （▾/▸ 同款），折叠键带 `本地/`、`远程/` 前缀 —— 两边同名前缀互不串门。远程先剥 `origin/` 再分文件夹，
  条目 id 保留全名，checkout 照旧剥前缀。
- **折叠关窗的根因**（探针抓到调用栈）：`app.mjs` 的"点组件外面收起"委托用
  `!e.target.closest('.combo')` 判内外 —— 折叠点击的 handler 里 `paint()` 换掉了 innerHTML，
  **被点的标题当场离场**，事件冒到 document 时 `closest` 找不到祖先，被误判成"点外面"关掉。
  修法：委托加 `e.target.isConnected`（离场目标 = combo 内部的交互，不收起）。
  一并兼容：`pickable` 排除文件夹行（键盘导航不停在死路上）、搜索时文件夹同标题一起隐藏（搜索永远全展开）。
- createCombo 的新能力都是**可选字段**（`foldable` / `folder` / `sub` / `foldKey`），
  不带的条目输出逐字不变，其他下拉零影响。

**验证**：浏览器实测——折叠/展开（组与文件夹两层）全程弹窗不关、搜索穿透折叠、
文件夹树渲染（缩进 + ✓ 在当前分支）、折叠状态跨开关记忆。

## 7. 四改（同日）：顶层分组折不动 + 折叠钮加大带图标

用户实报两个问题：

1. **「本地分支/远程分支」点了没反应**。根因（回看测试数据对上了：折「本地分支」后条目数没少）：
   paint 的藏匿链里，**文件夹行无条件用自己的开合状态覆盖父组的藏匿态** ——
   组标题折了，下面第一个文件夹立刻把 `hiding` 改回自己的值，整组又冒出来。
   修法：`hiding` 为真时文件夹与叶子一起藏、文件夹状态只在父组展开时生效
   （`if (hiding) return false;` 挡在文件夹分支之前）。
2. **折叠指示太小、文件夹没图标**：▾/▸ 由 9px 提到 10~11.5px、加宽占位；
   文件夹行复用现成的 `ICON_FOLDER`（「＋ 添加仓库」菜单同款描边文件夹，不新画）。

**验证**：bandi/feat/fix 三前缀样例实测 —— 折「本地分支」整组 6 条全藏、再点恢复、
折「bandi」文件夹只藏它自己两条；全程弹窗不关、折叠状态幂等。
