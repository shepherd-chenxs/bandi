# 本机接口（`/api/local/*`）授权设计

> 版本：**2026-10-31 v7（与 IAM v2.6 对齐，Phase 1 全部收尾）** ｜ 状态：**已施工（`security/local-policy.mjs`），本文随实现同步** ｜ 起因：协作中心的加入接口在局域网地址下被 `E1094` 挡，暴露了「只有认证、没有接口级授权」的架构缺口
> 前置：[协作中心 MVP 任务书](2026-10-31-协作中心-MVP任务书.md)、[局域网加入总机设计](2026-10-20-局域网加入总机-设计.md)
> v2 修订：`loopback` 判定改为三条件（原定义只看 `remoteAddress`，反代下形同虚设）—— 后续 v4/v5 又补了 `trustProxy` 与 Host，**最终以 IAM §5.2 的五条为准**；权威定义见 [安全架构 IAM §5.2](2026-10-31-安全架构-IAM-设计.md)。
>
> **v7 同步（2026-10-31，跟 IAM v2.6，Phase 1 收尾）**：① CSRF 双提交（`security/csrf.mjs`，`E4099`）挂在 `server.mjs` 请求链的**写请求入口**，不在 `authorizeLocal` 里 —— 与本文件「路由层不自己判安全」同一条规矩：位置判定归 `classifySource`，秘密归 `local-policy`，防伪归 `csrf`，三件事别混；② 破坏性本机动作在服务器形态下**浏览器不渲染按钮**（数据导出/导入、协作加入/退出已收；前端据此读 `/api/state` 的 `localSecret`）；③ 每次命中 `E4097` 之外的拒绝都会进 `security_events`（`authz.deny`，策略层自动记）。
>
> **v3 同步（2026-10-31，跟 IAM v2.2）**：① 本文件所有"仅回环"的破坏性动作，在**服务器形态（监听非回环）**下改由 **`X-Bandi-Local` 文件秘密**放行 —— 否则矩阵与 IAM §5.2 打架，服务器形态永远做不了 `collab join`；② 反代契约从"整组 deny `/api/local/*`"收窄为"只 deny 破坏性路径，放行只读 `status`"；③ **`/api/restart`（`routes/runtime.mjs:97`）不在本文件范围内，但必须同样登记**，不能靠前缀规则兜。
>
> **v6 修正（施工对齐，跟 IAM v2.5）**：`/api/restart` 登记为 **`secret:'never'`** —— `secret:'network'` 会造成单向门（`0.0.0.0` 监听下重启被 `E4097` 挡住，而关回单机必须先重启）；重启不动数据，泄漏面趋近于零。反代部署契约对它**仍无条件 deny**（见下行 ⚠️）。
>
> **v5 同步（2026-10-31，跟 IAM v2.4）**：① `loopback` 判定加 **Host 兜底**（反代漏配转发头时 Host 是最后一道信号）；② 反代契约补 `collab/join|leave` 与 `discover|probe`；③ 明确服务器形态由 CLI（`bandi collab join` / `bandi data export`）读 `local_secret` 执行，浏览器不渲染破坏性按钮。

## 一、问题（一句话）

**现在系统能回答“你是谁”（`auth.guard`），也能按接口面粗分（`decide` 的 operator / node / device / panel），但 `/api/local/*` 没有一张“什么身份、从哪来、能做哪个动作”的授权表。**

- `auth.guard` 在局域网模式下要求令牌/登录，匿名请求 401 —— **认证存在**；
- 之后 `routes/local.mjs` 用 `E1094` 一刀切“只准回环”，既不区分身份，也不区分读/写/危险动作 —— **授权缺位**；
- 结果：本机管理员在 `192.168.5.19:8787` 上被挡（正常需求），而 `panel` 令牌这种不该碰本机管理的身份，只是“恰好”被 `E1094` 挡住了。
- 以后每加一个本机接口，都要在 handler 里再写一遍判断 —— 这就是“打补丁”。

**结论：补一层声明式、默认拒绝的接口级授权（`local-policy`），`E1094` 降级为策略表里的一个来源条件。**

## 二、身份与来源（唯一口径，先定死）

### 2.1 身份（来自 `auth.identify` / 登录会话）

| 身份 | 怎么来 | 现在能做什么 |
|---|---|---|
| `loopback` | **五条同时成立**：监听地址是回环 + 无 `BANDI_TRUST_PROXY` + 无转发头 + peer 是 `127.0.0.1` / `::1` + Host 是本机/回环（判定见 §2.2，权威定义在 [IAM §5.2](2026-10-31-安全架构-IAM-设计.md)） | 全部（**只在单机形态存在**；服务器形态这一行不可达） |
| `operator` | root 令牌（数据目录 `token` / `BANDI_TOKEN` / 回环 Cookie） | 全部 |
| `admin` | 登录用户，`roleId === 'admin'` | 管理动作 |
| `member` | 登录用户，非 admin | 读 + 发消息等（`deviceMayReach` 白名单） |
| `panel` | 节点令牌，`scope` 含 `panel` | 面板「看 + 用」，五类管理动作禁止 |
| `compute` | 节点令牌，只有 `scope` 含 `compute` | 节点自己的活 |
| `device` | 手机配对令牌 | 手机白名单 |
| `anonymous` | 没有凭据 | 登录页 / 免令牌接口 |

### 2.2 来源

- **loopback**：**五条同时成立**才成立 —— ① 监听地址是回环；② **没有配 `BANDI_TRUST_PROXY`**；③ 请求没有 `X-Forwarded-For` / `X-Real-IP` / `Forwarded`；④ `req.socket.remoteAddress` 是回环；⑤ Host 是本机/回环（`localhost` / `127.*` / `::1` / 本机网卡 / `os.hostname()`；v5 补，防反代漏配转发头）。
  **只看第 ④ 条是错的**：nginx / cloudflared / frp 反代到本机时，所有外部请求的 `remoteAddress` 都是 `127.0.0.1`，`E1094` 会形同虚设；
  **漏了第 ② 条也是错的**（v4 补）：声明了"我在可信代理后面"之后，回环就不再是可信来源，否则 nginx 一转发就等于绕过；
  **漏了第 ⑤ 条同样是错的**（v5 补）：反代漏写 `X-Forwarded-For` 时，外部 Host 是最后一道能把它判成 `network` 的信号。
- **network**：其余（局域网 / 隧道 / 反代）；
- **非回环形态（监听 `0.0.0.0` / `::`）下 loopback 不作为身份**：破坏性本机动作（export / import / join / leave / hosts / backups）改要求 `X-Bandi-Local` = `<数据目录>/local_secret` 的内容 —— 只有本机进程读得到，反代伪造不了。**`restart` 例外（v6）：`secret:'never'`**，理由见头部 v6 修正。

> ⚠️ `E1094` 只应该表达"这个动作不允许 network 来源"，不再承担"你是不是管理员"。本文件策略表**不产出** `E1094`（见 §4.1）。
> ⚠️ **部署契约**：反代 **只 deny 破坏性路径**（export/import/join/leave/hosts/*、`collab/join|leave`、`discover|probe`、`/api/restart`），**必须放行只读的 `/api/local/status` 与 `/api/local/collab/status`** —— 整组 deny 会让反代后面的设置页看不到状态。这是第二道，第一道是 `X-Bandi-Local`。
> 判定实现只有一处：`security/source.mjs` 的 `classifySource()`（施工落点；规划期写在 principal.mjs 名下，Phase 1 拆出来独立成模块，不 import auth 避免成环）；`routes/` 里不许再出现 `remoteAddress` 判断（`local.mjs:218` / `imageai.mjs:29` / `auth.mjs:583` 三处都要改）。

## 三、授权矩阵（Phase 1）

「网络 + 秘密」= 从 `network` 来源进来、但带了 `X-Bandi-Local`（只有本机进程读得到 `<数据目录>/local_secret`）。

| 方法 | 路径 | loopback（不查角色） | 网络 + 秘密（operator/admin） | 网络无秘密（operator/admin） | member / panel / compute / device |
|---|---|---|---|---|---|
| GET | `/api/local/status` | ✅ | ✅ | ✅ | ❌ |
| GET | `/api/local/collab/status` | ✅ | ✅ | ✅ | ❌ |
| POST | `/api/local/collab/join` | ✅ | ✅ | ❌ `E4097` | ❌ |
| POST | `/api/local/collab/leave` | ✅ | ✅ | ❌ `E4097` | ❌ |
| POST | `/api/local/discover` / `probe` | ✅ | ✅ | ❌ `E4097` | ❌ |
| POST | `/api/local/hosts/add\|test\|remove` | ✅ | ✅ | ❌ `E4097` | ❌ |
| POST | `/api/local/join` / `leave`（算力节点） | ✅ | ✅ | ❌ `E4097` | ❌ |
| GET | `/api/local/backups` | ✅ | ✅ | ❌ `E4097` | ❌ |
| POST | `/api/local/export` / `import` | ✅ | ✅ | ❌ `E4097` | ❌ |
| POST | `/api/restart` | ✅ | ✅（`secret:'never'`，v6） | ✅ operator/admin（`secret:'never'`，v6） | ❌ |

**三条口径（v4 修，原来写成"只认物理本机"，与 IAM §8.5 打架）：**

- **角色管"是什么身份"，秘密管"能不能碰这台机器"**，两条同时满足才放行。一个从局域网进来的 admin 只要手上有 `local_secret`，就可以执行 `join` —— 拿到那个文件意味着他本来就能改这台机器的数据库，再区分"物理位置"没有意义；
- `status` 两个只读接口**不要秘密**：反代后面的设置页要显示本机与协作状态，要秘密就等于永远显示不出来（IAM §10.1.2 也因此只 deny 破坏性路径）；
- `join` 仍然要求**中心发的一次性邀请码**；授权表只解决"谁能在分机上执行"，不替代邀请码。
- **服务器形态怎么执行破坏性动作**：监听 `0.0.0.0` / `::` 时 `loopback` 永远不成立，所以走"网络 + 秘密"这一列 —— **本机终端用 CLI**（`bandi collab join` / `bandi data export`）读 `<数据目录>/local_secret` 带 `X-Bandi-Local` 发起；浏览器里这些按钮**不渲染**（IAM §10.1.3）。

**以后要放开某一行**：改这张表 + 补测试，不改 handler。

## 四、代码结构

### 4.1 新模块 `apps/server/src/security/local-policy.mjs`（✅ 已施工）

纯逻辑（不 import store、不写 SQL、不碰 DOM）——施工落点在 `security/` 子目录下，与 `source.mjs` / `local-secret.mjs` / `setup-code.mjs` / `tls-check.mjs` 并列：

```js
// v4：字段与 IAM §8.3 对齐（principals + secret 三档），不再用 allow: ['secret'] 这种混身份与位置的写法
export const LOCAL_POLICY = [
  // 只读状态：网络来源也放行（设置页要显示），不要秘密
  { method: 'GET',  path: '/api/local/status',        principals: ['operator', 'admin'], secret: 'never' },
  { method: 'GET',  path: '/api/local/collab/status', principals: ['operator', 'admin'], secret: 'never' },

  // 破坏性：loopback 不要秘密；从网络来必须带 X-Bandi-Local（只有本机进程读得到）
  { method: 'POST', path: '/api/local/collab/join',   principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/collab/leave',  principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/export',        principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/import',        principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/hosts/add',     principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/hosts/test',    principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/hosts/remove',  principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/discover',      principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/probe',         principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/join',          principals: ['operator', 'admin'], secret: 'network' },
  { method: 'POST', path: '/api/local/leave',         principals: ['operator', 'admin'], secret: 'network' },
  { method: 'GET',  path: '/api/local/backups',       principals: ['operator', 'admin'], secret: 'network' },
  // ⚠️ /api/restart 不在 /api/local/ 前缀下（runtime.mjs:97），单独登记
  // v6：secret 改 'never' —— 'network' 会造成"开了局域网关不回单机"的单向门（IAM §8.5 注）
  { method: 'POST', path: '/api/restart',             principals: ['operator', 'admin'], secret: 'never' },
];

/**
 * 返回 { allow, code?, message? }；**默认拒绝**。
 * @param {{method:string, pathname:string, source:'loopback'|'network',
 *          principal:{kind:string, roleId?:string, admin?:boolean}|null,
 *          hasSecret:boolean}} ctx
 */
export function authorizeLocal({ method, pathname, source, principal, hasSecret }) { ... }
```

- **身份归一**：`principal` 为 null → `anonymous`；否则按 `principal.kind` + `admin` 映射成 `operator` / `admin` / `member` / `panel` / `node` / `device`（同 IAM §2.1）；
- **位置归一**：`source` 由 IAM §5.2 的 `classifySource()` 给出 —— **本模块不自己判 IP**（v4 改：原签名里那个 `isLoopback` 是各自判回环的老路子，正是 §5.2 要收编的东西）；
- **秘密归一**：`hasSecret` 由调用方比对 `X-Bandi-Local` 得出（`local-secret.mjs`）；
- **判定顺序**：未登记 → `E4090`；身份不在 `principals` → `E4091`；`secret: 'network'` 且 `source === 'network'` 且 `!hasSecret` → `E4097`；否则放行；
- 路径匹配：精确串为主；带 `:id` 的用 `RegExp` 行（如 `hosts/:host` 不存在，目前全是固定路径）；
- 拒绝时打一行日志（身份 + 方法 + 路径 + 来源），便于排查。

> **为什么不再有 `E1094` 在这里**（v4 改）：`E1094` 的语义已收窄成"这个动作不允许 network 来源"（IAM §5.2），而本表里**没有任何一行是"拒绝网络来源"**——破坏性动作对网络是"要秘密"而不是"禁止"。所以本模块只产出 `E4090` / `E4091` / `E4097`，`E1094` 只在 IAM 的 route-policy 里作为 `source` 不含 `network` 时出现。

### 4.2 接入点

- `routes/local.mjs` 的 `handleLocal()` 开头：
  1. `const source = classifySource(req, cfg)`（IAM §5.2，**不要在 routes 里判 IP**）；
  2. `const principal = principalOf(req)`（IAM §5.1）；`const hasSecret = localSecret.ok(req)`；
  3. `const verdict = authorizeLocal({ method, pathname, source, principal, hasSecret })`；
  4. 不允许就回对应码；
  5. 原有 handler 不再各自判断 `isLoopbackRemote`（`local.mjs:218` 那处删掉）。
- `auth.guard` 继续只做认证（401 在授权之前），两者职责分开 —— 但 **IAM §5.3 那条"回环不再无条件免鉴权"必须先落地**，否则反代下 `principal` 恒为 operator，这一层怎么判都是全过。
- `mayManage`/字段级判断继续留在各自的 handler（body 级细节，如改员工 model/runtime），**不承担接口准入**。

### 4.3 错误码（v4 与 IAM 附录 C 对齐）

| 码 | HTTP | 文案 |
|---|---|---|
| `E4090` | 404 | 本机接口未在策略表登记（默认拒绝） |
| `E4091` | 403 | 当前身份不能做本机管理动作（需要管理员或操作员） |
| `E4097` | 403 | 这个动作需要 `X-Bandi-Local`（服务器形态请在终端用 CLI） |
| `E1094` | 403 | 这个动作不允许从网络来源调用（本表实际不产出，保留给 route-policy） |

> **v4 修**：本文件早期把 `E4090` 定义成"身份不够"，与 IAM 附录 C（`E4090` = 未登记 / `E4091` = 越权）冲突。**以 IAM 附录 C 为准**，本文件全部改成 `E4091`。一码一义，别让同一个码在两个文件里指两件事。

## 五、测试

### 5.1 新用例 `apps/server/src/smoke-local-policy.mjs`（纯逻辑，不 spawn 服务）

对矩阵做穷举：

- 身份 × 来源 × 每条策略 → 断言 allow/deny；
- **默认拒绝**：未登记的 `/api/local/whatever` → deny；
- **覆盖检查**：从 `routes/local.mjs` 里抽出所有 `/api/local/...` 字面量，必须都在 `LOCAL_POLICY` 里有一行（漏登记 = 测试红）；
- 断言 `operator/admin` 在 `network` 无秘密时：`status` 允许、`collab/join` → `E4097`、`export` → `E4097`；**带秘密时三者全允许**；
- 断言 `loopback` 不看角色（`anonymous` 也能过）、也不要求秘密。

### 5.2 集成（可并入 `smoke-collab.mjs` 或独立）

- 起一台 `BANDI_HOST=0.0.0.0` 的服务，用本机网卡地址访问：
  - 无令牌 → 401（`auth.guard` 先挡）；
  - root 令牌 → `GET /api/local/collab/status` 200（不要秘密）；
  - root 令牌 + `X-Bandi-Local` → `POST /api/local/collab/join` 能到 handler（坏码回 `E4040`，不是 `E4097`）；
  - root 令牌不带秘密 → `POST /api/local/export` 回 `E4097`；带秘密 → 200（`E4097` 是"缺证明"，不是"禁止"）；
  - 非 admin 登录 → `E4033`；
  - `panel` 令牌 → `E4091`。
- **反代形态**（`BANDI_TRUST_PROXY=1` + `X-Forwarded-For`）：即使 peer 是 `127.0.0.1`，`source` 必须是 `network`；不带秘密的 `export` 必须 `E4097`（这条同时是 IAM §5.3 的用例）。
- 回环行为逐条不变（本机免登录、导出/导入照旧）。

### 5.3 回归

`smoke-auth` / `smoke-lan-origin` / `smoke-users` / `smoke-node-jobs` / `smoke-collab` / `smoke-data-dir` 全绿。

## 六、迁移与兼容

- 回环不变：本机物理访问仍是最高权限，`/api/local/*` 行为一行不改；
- 局域网已登录管理员：`status` / `collab/*` 从“被 E1094 挡”变成“可用”；其他接口行为不变；
- 没有新表、没有新依赖、不动 `config.json`/数据库；
- 前端只需把 `E1094` 的文案展示逻辑保留（现在可能是管理员看到它）；接口通了之后这条基本不再出现。

## 七、明确不做

- 不做全站 RBAC 重写：`decide` / `mayManage` 的现有边界不动，只补 `/api/local/*` 的接口准入；
- **不把导出/导入/算力节点加入开给"只有登录态的远程"**：它们只在 `loopback` 或 `network + X-Bandi-Local` 下可用（v4 修，原来写"不开给远程"过于绝对，服务器形态就执行不了）；
- 不做按 IP 白名单：IP 会变（DHCP/NAT/IPv6 隐私地址），而且它限的是“哪台机器能来”，不是“谁有权在你机器上执行”；
- 不把邀请码当授权：邀请码只证明“中心邀请了你”，执行仍要分机自己的身份。
