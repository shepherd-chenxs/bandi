# 完全自主交付（数字员工无人工拍板）

> 决策快照：用户拍板 **A —— 完全自主、人不逐步拍板**。一条流程起完后，节点按岗位自动指派、跑完自动流转，全程不让人点「通过」；最后由 PM 写汇报落进信箱给雇主，雇主再择时合并 PR / 上线。本文是设计定稿，具体实现以代码为准。

## 一、问题（背景）

用户要的是：「数字员工能自迭代班底项目、检查设计上的漏洞，项目经理就能组织讨论、制定方案、施工，最后汇报给我结果」，**人不介入拍板**。

班底原本的定位是「把活派给数字员工，看它干，随时接管」，契约里有两条硬红线：

- 第四节「部署永远要人下令」：内建模板的部署节点写死 `manual: true`，跑完不自动流转。
- 第五节「只认点名 + 一次只推进一条流程一步」：节点上写谁派给谁，派到的只做那一段，推进是平台的事。

经探索，引擎本身**已支持无人工闸的自动流转**：非 `manual` 节点跑完，`onAgentRunFinished` 会自动 `decide('通过')` 并自动派下一步（到站即派活 + 30 秒节拍补派）。唯一的硬闸就是内建模板的部署 `manual` 节点。自主交付不需要「部署」这一步——交付物是 PR + 报告——所以真正要补的工程缺口只有四处：

1. **PM 自主起一条流程实例**：原建卡通道只支持「派人 / 派群」，不能建「由流程执行」的卡。
2. **一条不含人工闸、按岗位点名的自主模板**：节点不点具体人（跨机器可复用），全部 `manual: false`。
3. **跑完 / 卡住自动写信箱汇报给雇主**：信箱表结构已通用（`store/notices`），只差在收尾处写一条。
4. **修订契约红线**：第四节「部署永远要人下令」加补充口径，新增「自主交付」段落。

## 二、定稿口径

### 1. 自主交付 = 一种流程模板（加一列标）

`workflow_templates` 加 `autonomous` 列（`INTEGER DEFAULT 0`）：

- `0` / null = 普通流程（人可逐步拍板，部署节点要人下令）。
- `1` = 自主模板（无 `manual` 节点，实例终态/受阻自动写信箱）。

**关键判断**：自主与否由模板这一列决定，**普通流程一行代码都不改**——这是「不破坏现有行为」的前提。

### 2. 节点按岗位自动指派（不点具体人）

`assigneeFor(node)`（`apps/server/src/workflows.mjs`）原只认 `personaId`；新增：节点声明 `roleKey` 时，按岗位找一个该岗位的员工办。
busy/额度/没点名三条原逻辑不变：忙 → 退回待办、30 秒节拍重试；没点名（既无 `personaId` 也无 `roleKey`）→ 标「已阻塞」等人。

**为什么按岗位不按技能**：契约第五节明确「节点上没有技能这一维」。岗位是系统内置对象（`roles.mjs`），权限挂在岗位上；按岗位指派与「只认点名」同一哲学，只是「名」从具体员工 id 升到岗位 key。

### 3. 自动流转 = 复用现有引擎，零新逻辑

自主模板不含 `manual` 节点 → `onAgentRunFinished` 自动 `decide('通过')` → `goto` 自动派下一步。这是引擎早已支持的行为，本功能**不写第二套流转逻辑**，只在终态/受阻处挂一个汇报钩子。

### 4. 汇报 = 复用信箱（已有设施）

`apps/server/src/store/notices.mjs` 的 `addNotice` + 前端 `inbox.mjs` 轮询/角标已就绪。写一条 `kind='workflow.delivery.report'`，`severity` 按状态区分（done=info / failed=warn / blocked、terminated=blocking），`code` 分别 `WF_DONE` / `WF_FAILED` / `WF_BLOCKED` / `WF_STOPPED`，`dedupeKey = wf:<实例id>:<状态>` 避免重试刷屏。

触发点分三层，都只认 `tpl.autonomous`：

- **任务级**（实例仍 `doing`）：`onAgentRunFinished` 的 `blocked`/`failed`/`stopped` 用 `asStatus` 写「卡住了」；
- **实例级**：`done`/`terminated` 收口在 `settleRun()`（`goto` END、`decide('终止')`、`abortWorkflow`、打回超限、节点丢失放行共用）；
- **平台自己卡住**：`createTask` 没岗位、`startCurrentStep` 的不认识动作节点 / 动作 `handler.run` 抛错或 `finishActionTask(ok:false)` 自报失败 / 派活准备或派活失败 / 额度闸，都写 `WF_BLOCKED` 或 `WF_FAILED`。动作失败统一走 `finishActionTask` 这一处，不重复写状态/汇报；派活的 try 从「找工单会话」就开始（点名的人中途离职会在这里抛），不能让任务永远停在「进行中」静默不报。

完成报告要让人**直接收到结果**：自主模板最后一个节点（出口指向 `end`）的回话全文去掉交付标记后存进 `result.report`；`notifyDeliveryReport` 在 `done` 时优先把它作为「交付汇报」正文，并从全部任务 `result.artifacts` 收集 `http(s)` 链接列为「PR」。时间轴仍只认原来的 `{state, summary, artifacts, error}`，普通流程的 result 一行不改。实例 id 写在 detail 与 dedupeKey 里，不占 `notices.runId` —— 那个字段是「哪一轮 agent 执行」，流程实例不是一轮执行。

### 5. 安全边界不越过

自主交付**不自动合并 PR、不部署、不对外发布、不花钱**。PR 由 `pr-create` 动作节点建好（平台动作），但**合并仍由雇主在面板上点**（`pr-merge` 的 `onDecide` 只认人）。这符合契约「部署永远要人下令」的精神——只是自主模板本身不含部署节点，交付物是 PR，合并/上线交回给雇主择时。

## 三、已拍板（2026-11-13 用户确认）

- **完全自主、人不拍板**：PM 可自主组织讨论 → 方案 → 施工 → 汇报，人只在信箱收结果。
- **触发方式**：人在消息里对 PM 说一句（如「自迭代班底、查设计漏洞」），PM 经建卡通道立一张「由流程执行」的卡发起自主流程。不强制走定时任务。
- **讨论/评审的承载**：复用流程节点按岗位点名（PM → 架构师 → 研发 → 测试），上游产出落 `docs/模板/*.md`，下游读目录拿上游产出。**不碰群接力防环**（深度 ≤2 的三条防环会挡自由圆桌，且没必要）。
- **交付物**：PR + 信箱报告；合并/部署/发布保留人工。

- 改动如上表 9 个文件 + `tools/run-smokes.mjs`、`tools/check-doc-drift.mjs`（把新交接快照登记进快照表，文档对账才不报「没人管的文档」）。

## 六、接口与界面

- **入口**：`POST /api/agent/cards/batch` 体 `{ cards: [{ title, description, projectId, flowTemplateId: 'bandi-self-delivery', status: 'todo' }] }`（运行钥匙可达，仅 PM 岗）。卡必须挂在项目下；建完即起流程实例（卡上写 `flowRunId`）。
- **界面**：流程实例页与普通流程同一套（工作台 → 工作流），自动推进、无「等你验收」人工按钮；信箱出现「自主交付报告」条目（角标 +1）。

## 七、迁移

`db.mjs`：`SCHEMA_VERSION` 9→10；`ensureColumn('workflow_templates', 'autonomous', 'autonomous INTEGER DEFAULT 0')`。旧库升级时这一列默认 0（= 普通流程），不影响任何存量模板/实例。内建的 `bandi-self-delivery` 是例外：`ensureSelfDeliveryTemplate()` 每次启动对 `builtIn` 且该列为 0 的模板补 1（用 `setTemplateAutonomous`），否则旧库里这条自主模板终态/受阻会漏汇报；用户手动接管（清 `builtIn`）后不再动它。

## 八、冒烟与验收

`smoke-self-delivery.mjs`（已登记 `tools/run-smokes.mjs`，实测全通过）：

1. 模板播种 → 已发布、`autonomous=1`、7 节点全无 `manual`、按岗位点名、出口连成一条链且驳回只回退；二次播种幂等。
2. `roleKey=dev` 指派到研发岗；岗位不存在 → 到站即「已阻塞」并写一条 `WF_BLOCKED`，再点派活不重复刷屏。
3. 非 `manual` 节点跑完 → 自动放行 → 流程 `done` + 信箱一条 `WF_DONE`（info）；报告带 PM 交付汇报正文与 PR 链接。
4. `[受阻]` / 失败 / 人工终止 → 各写一条（`WF_BLOCKED`/`WF_FAILED`/`WF_STOPPED`），流程状态符合预期。
5. 平台自己卡住也汇报：未知动作节点、动作 `handler.run` 抛错、`finishActionTask(ok:false)` 自报失败、派活准备/派活失败、额度闸分别写一条 `WF_FAILED`/`WF_BLOCKED`，`count` 保持 1。
6. 普通流程（`autonomous=0`）`manual` 仍停在「待验收」、收尾不写汇报；内建 `bandi-delivery` 部署节点仍 `manual: true`。
7. 同进程控制面 + PM 运行钥匙：`POST /api/agent/cards/batch` 带 `flowTemplateId` → 201、卡上 `flowRunId` 非空、实例第一步按岗位派给 PM。

全量门禁：`node tools/run-smokes.mjs` → 68 个全通过（含 `smoke-agent-cards` / `smoke-workflows` / `smoke-inbox`、文档/路由/分发链/幽灵引用对账等回归）。

## 九、边界（本设计不解决）

- **不自动合并/部署/发布/花钱**：这些仍由雇主在面板择时（契约「部署永远要人下令」的精神）。
- **跨步骤交接靠文档落盘**：上游产出写 `docs/模板/*.md`，下游读目录——没有结构化的 step 输出 → step 输入管道（这是引擎既有缺口，本设计不新造）。
- **多 agent 自由圆桌讨论**：不做；用流程节点按岗位点名 + 文档交接替代（避免群接力防环与 ping-pong）。
- **运行钥匙拍板 `decide`/`start`**：未放开；自主靠「无 `manual` 节点 + 自动流转」实现，不需要 agent 调用 decide。

## 十、分期

- **Phase 1（已落地、冒烟全过）**：建卡通道支持 `flowTemplateId` 且批量口真起实例；`assigneeFor` 按岗位；`autonomous` 列 + 自主模板播种；终态/受阻汇报钩子；契约/PM 提示/信箱标签；独立冒烟 + 全量门禁。
- **Phase 2（可选，不在本 PR）**：给运行钥匙暴露 `workflow.decide`/`workflow.start`（`route-policy` 加 `run:true` + `roles.mjs` 加权限位），让 PM 在模板之外动态起/拍板流程；放宽 `BANDI_CHAIN_DEPTH` 支持自由圆桌。
