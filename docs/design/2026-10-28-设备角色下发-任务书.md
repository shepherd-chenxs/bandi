# 任务书（第四刀）：把角色菜单下发到节点机与手机

> 给执行方（WorkBuddy）的完整任务书。仓库：`E:\02CodeSpace\github\bandi`。
> 前三刀已进 `main`：节点配置面、角色菜单数据、账号登录（角色菜单已作用于**登录的浏览器**）。
> 本刀把同一张角色表送到**节点机的本地面板**和**手机端**。

## 一、目标（一句话）

总机管理员能给每台节点机、每部手机**指定一个角色**；被指定的设备按该角色的 `menuKeys`
渲染自己的菜单（节点面板 / 手机底部导航）。**没分配 = 用内置默认角色，行为与今天一致。**

验收：给节点/手机换角色 → 那台设备下一次心跳/刷新后菜单跟着变；改回「默认」恢复；
角色还有设备在用 → 删不掉（E2071 已在第三刀用于账号，本刀扩到设备）。

## 二、现状（先核，别猜）

- `roles` / `role_menus` 在 `apps/server/src/store/roles.mjs`，内置 `admin` / `operator` / `node-ops`
  三个角色；`node-ops` 的 6 个 key 正好是节点配置面的六个分节。
- 节点机：`config.json` 有 `controlPlane` = 已加入；`node.mjs` 出站心跳
  `POST /api/nodes/:id/heartbeat`（`apps/server/src/node.mjs:281`），总机侧 handler 在
  `apps/server/src/routes/node.mjs:147-164`（现在回 `{node, heartbeatSeconds}`）。
- 节点本地面板：`apps/web/js/misc.mjs` 的 `renderNodeMode()`，六个分节各自过
  `canSee(role, key)`（`apps/web/js/roles.mjs`）；`resolveRole()` 里 `node` 列是代码常量。
- 手机：设备令牌身份；`/api/me`（`apps/server/src/routes/users.mjs`）对 `kind:'device'`
  现在**不回 role**；前端 `apps/web/js/state.mjs` 里 `S.menuKeys` 对设备是 `null`（不收敛）。
- 设备数据：`nodes`（`store/nodes.mjs`）、`mobile_devices`（`store/devices.mjs`）。

## 三、设计决定（照做）

1. **默认角色**：新增内置角色 `mobile`（名字「手机」，`builtin=1`，预置 key
   `messages / contacts / workbench / settings`）。`node-ops` 已存在。
   **未分配 = 默认**：节点 → `node-ops`；手机 → `mobile`。注意 `smoke-roles` 里有内置角色断言，
   加第 4 个内置角色是**允许的**（它只查存在性，不查总数；跑一遍确认）。
2. **存储**：`nodes`、`mobile_devices` 各加一列 `roleId TEXT`（可空）。
   用 `PRAGMA table_info` 判存在再 `ALTER TABLE ... ADD COLUMN`（老库平滑升级；别重建表）。
3. **下发方式**：
   - **节点**：心跳响应**加字段** `panelRole: { id, name, menuKeys } | null`（null = 用默认）。
     `node.mjs` 收到后写 `<dataDir>/node-panel.json`（内容变了才写，临时文件 + rename 原子替换）。
     本地面板经 `GET /api/local/status` 读它：`localMode.status()` 加 `panelRole` 字段
     （读不到文件就 `null`，前端回落到静态默认 = 六个分节全显示）。
   - **手机**：`/api/me` 对 `kind:'device'` 增加 `role` 字段（同形状；未分配时是默认 `mobile` 角色）。
     前端 `S.menuKeys` 对设备改成 `role.menuKeys`；`applyMenuGating()` 已经会处理 `.mb-tab`。
4. **节点面板安全阀**：`node.connection`（含「打开总机面板」「退出总机」）**永远显示**，
   不受角色限制 —— 否则管理员一次误配就把那台机器锁死在里面。其余五节按菜单 key 收敛。
5. **不做的边界**：菜单只是**界面**收敛；服务端权限边界仍然是 `mayManage`（管理员）
   与 `deviceMayReach`（手机）/节点令牌那套，**本刀不加"按菜单 key 拦 API"**。
6. **删除角色保护扩展**：第三刀的 `countUsersByRole` 之外，再加设备引用计数；
   角色被账号**或设备**绑着 → 409 `E2071`，文案说清数量。

## 四、改动清单

### 4.1 服务端
- `store/roles.mjs`：SEEDS 加 `mobile`；seed 保持幂等。
- `store/nodes.mjs`：`nodes` 加 `roleId`；`getNode`/`publicNodes` 带出 `roleId`；
  新增 `setNodeRole(nodeId, roleId|null)`。
- `store/devices.mjs`：`mobile_devices` 加 `roleId`；`listDevices` 带出；
  新增 `setDeviceRole(deviceId, roleId|null)`。
- `store/users.mjs`：`countUsersByRole` 旁边加 `countNodesByRole` / `countPhonesByRole`
  （或一个 `countDeviceRolesByRole`）。
- `routes/node.mjs`：
  - 心跳响应加 `panelRole`：`roleId = node.roleId ?? 'node-ops'` → `store.getRole()` →
    `{id,name,menuKeys}`；角色被删了也回落默认。
  - 新增 `POST /api/nodes/:id/role {roleId|null}`（`mayManage`；校验角色存在）；
- `routes/pair.mjs`：新增 `POST /api/pair/devices/:id/role {roleId|null}`（`mayManage`）。
- `routes/users.mjs`：`/api/me` 的 device 分支加 `role`（同上默认逻辑）。
- `routes/roles.mjs`：DELETE 前把设备引用计数一起算进 `E2071`。
- `local-mode.mjs`：`status()` 加 `panelRole`（读 `<dataDir>/node-panel.json`，坏文件当 null）。

### 4.2 节点进程
- `node.mjs`：心跳处理里，若 `hb.body?.panelRole` 与本地缓存不同 → 写 `node-panel.json`
  （`{ roleId, name, menuKeys, at }`；写失败只 warn，不影响心跳）。`--once` 也写一次。

### 4.3 前端
- `roles.mjs`：加 `canSeeKeys(menuKeys, key)`（`menuKeys == null` = 不限制）。
  `resolveRole` 保持不动（节点/手机的身份列不变）；节点页改成**读 `panelRole.menuKeys`**。
- `misc.mjs` 的 `renderNodeMode()`：从 `st.panelRole` 拿 menuKeys；`canSee` 换成
  `canSeeKeys`；`node.connection` 强制显示；其余五节照角色收敛。
- `state.mjs`：`/api/me` 的 `role` 对设备也取（`S.menuKeys = me?.role?.menuKeys ?? null`，
  但**仅 device 与 user**；operator 仍是 null=不限制）。
- `machine.mjs` 的 `renderDeviceDetail()`：加「面板角色」一行 `<select>`（选项来自 `/api/roles`，
  含「默认（节点运维）」），改动即 `POST /api/nodes/:id/role`，成功后 toast + 重画。
- `pairing.mjs` 的 `renderDeviceList()`：每台手机行加同样的下拉，走 `/api/pair/devices/:id/role`。
- `sw.js` 若新增 JS 模块 → 登记 + `VERSION` +1；本刀原则上不新增前端文件。
- 文案：设备端说明「菜单由总机分配；未分配时用默认」。

### 4.4 冒烟
新增 `apps/server/src/smoke-device-roles.mjs`（非回环 + `BANDI_TOKEN`，照 `smoke-users.mjs`）：
1. 用 `POST /api/nodes/invites` + `POST /api/nodes/join` 造一个节点（照 `smoke-node.mjs` 的报到写法）；
   心跳响应 `panelRole` = `node-ops` 的 6 个 key；
2. 建一个自建角色（2 个 node.* key）→ `POST /api/nodes/:id/role` → 下次心跳 `panelRole` 变成它；
3. `roleId:null` → 恢复默认；
4. 手机：配对（pair/claim）→ `/api/me` 的 `role` = `mobile` 的 4 个 key → 分配自建角色 →
   `/api/me` 跟着变；`null` → 恢复默认；
5. 删一个**被节点/手机绑着**的角色 → 409 `E2071`；解绑/删设备后能删；
6. 未分配时节点/手机的菜单与今天一致（默认角色 key 数对）。
- 登记进 `tools/run-smokes.mjs`；`node tools/run-smokes.mjs` 全绿。
