## 1. 美学方向

这一页不是"填一张表"，是**把一张卡递给某个人**。所以它该长得像 iOS「提醒事项」的建卡纸：
一张抬头（写什么），两枚签（谁来干），签完就走。全页只允许两种材质 —— `--mb-surface`
的卡面与 `--mb-page` 的纸底；唯一的实心彩色是主按钮，唯一的第二种彩色是"你挑中的那一张卡"。
**克制点**在于：不画输入框、不画单选圆点、不画第三颗勾；**不落俗套**的点在于：整页字只有
两条竖线（16 / 32），扫视时不会在三种缩进之间跳。

---

## 2. 设计原则（5 条 + 明确"避免什么"）

1. **两条竖线**：卡外边缘与分节头在 16；所有卡内文字在 32。现状有三条（16/32/48，48 是
   圆点让出来的）—— 这是"表单感"最大的来源，必须消掉。
2. **两种材质**：卡 = `--mb-surface` + 0.5px 环；底 = `--mb-page`。输入区也是卡，但**卡里不画框**
   （无边框、无分隔线、无标签）。
3. **一处实心彩**：只有主按钮是实心色块。选中态用"描边 + 染色标题"，**不用填充色**、**不用勾**。
4. **值的阅读顺序 = 想事的顺序**：标题（干什么）→ 值（给了谁）→ 解释（怎么走）。现状把值放在
   解释下面，等于把答案写在注释里。
5. **状态变化不许引起布局位移**：只允许改 `color / box-shadow / background / transform`；
   不允许改 `border-width / font-weight / display / 字号`。

**避免**（返工高发区）：

- ✗ radio 圆点、卡左图标槽、"label 左 · 值右 ›"之外的自造行 —— 这页一旦出现两套行语汇就回到表单。
- ✗ 选中卡加 tint 淡底（`color-mix(tint 5%, surface)`）：深色下几乎不可见，浅色下像 `:active` 残留。
- ✗ 第三颗 ✓（✓ 已经用满：选择页行尾 + 开关旋钮语义）。
- ✗ 把「更多设置」拆成多张卡（现在是一张卡里的三行，拆了就成碎卡墙）。
- ✗ 卡底压一条 hairline 收边（圆角会被切出"断口"，且暗示"下面还有内容"）。
- ✗ 描述 textarea 加边框/底色/字符计数 —— 它是"补充说明"，不是字段。

## 3. 色彩系统（token 映射 + 深浅对应）

全部走 §16.0 token，因此**深浅两套不需要第二条规则**；下表是"哪一档用哪个"的对照（含实测色，仅供校色，实现在 CSS 里必须写 token）。

| 角色 | token | 浅色实测 | 深色实测 | 用在哪 |
|---|---|---|---|---|
| 纸底 | `--mb-page` | #F2F2F7 | #000 | 页底、底栏 |
| 卡面 | `--mb-surface` | #FFF | #1C1C1E | 草稿卡 / 两张大卡 / 设置卡 |
| 卡环（静） | `color-mix(in srgb, var(--mb-text) 9%, transparent)` | ≈ #E9E9EB | ≈ #232325 | 所有卡的 0.5px 外环 |
| 分隔线 | `--mb-hairline` | rgba(60,60,67,.12) | rgba(84,84,88,.65) | 卡内行间（左缩进 16） |
| 正文 | `--mb-text` | #000 | #FFF | 标题、行 label、有值的回显 |
| 次文 | `--mb-text-2` | rgba(60,60,67,.72) | rgba(235,235,245,.60) | 设置行的值、箭头 |
| 三文/占位 | `--mb-text-3` | rgba(60,60,67,.38) | rgba(235,235,245,.38) | 分节头、解释小字、空值、占位 |
| 交互色（图形） | `--mb-tint` | #007AFF | #0A84FF | 返回箭头、选中环、开关轨道（非文字，3:1 档即可） |
| 交互色（文本） | `color-mix(in srgb, var(--mb-tint) 78%, var(--mb-text))` | ≈ #005FC7（6.0:1 压白卡） | ≈ #409FFF（6.2:1 压 #1C1C1E） | 选中卡标题、「去发布 ›」。**tint 一旦当文字用就走这档**：浅色裸 tint 压白只有 4.0:1，不达红线 |
| 选中环 | `color-mix(in srgb, var(--mb-tint) 60%, transparent)` | — | — | 选中卡 1.5px 环（唯一"第二种彩"，图形档） |
| 主按钮 | `--mb-btn-send`（= `--mb-bubble-me`） | #0071E3 | #0071E3 | 创建任务（白字 4.7:1） |
| 按钮字 | `--mb-on-bubble` | #FFF | #FFF | 主按钮文字、开关旋钮 |
| 填充面 | `--mb-fill` | rgba(118,118,128,.12) | rgba(120,120,128,.24) | 禁用按钮底、开关 off 轨道 |
| 按压 | `--mb-press` | rgba(118,118,128,.22) | rgba(120,120,128,.36) | 行/箭头/返回的 `:active` |

**彩色预算**（一屏最多这几处）：主按钮（实心）、选中卡标题（文本级 tint）+ 环、返回箭头（图形 tint）、
「去发布 ›」（文本级 tint）。状态色点 `--st-*` **本页不出现**（状态行是"取值"，圆点在 mbPicker
选项行里、保持 `--st-*` 原色不染 tint —— 与 ux §3.2 同口径）。

## 5. 分段视觉规范

### 5.1 导航栏（收口，不改形态）

现状：`.kb-new-bar` 只有 `detail-head` 一个类，高度/玻璃底/发丝线全靠 `body.no-list .detail-head`
匹配——一旦 `no-list` 不在（刷新恢复、转屏），导航栏会塌成"内容撑高"。**收口到自己的类上**：

- `.kb-new .kb-new-bar`：`position: relative`；`flex: 0 0 auto`；`height: calc(var(--mb-nav,52px) + env(safe-area-inset-top,0px))`；
  `padding: 0 var(--mb-pad,16px)`；`padding-top: env(safe-area-inset-top,0px)`；`box-sizing: border-box`；
  `background: var(--mb-nav-glass)`；`backdrop-filter: blur(20px) saturate(180%)`（含 `-webkit-`）；`border-bottom: 0`。
- `.kb-new-bar::after`：`content:''`；`position:absolute`；`left:0;right:0;bottom:0`；`height:0.5px`；`background: var(--mb-hairline)`。
- 返回 `‹`：沿用 `.kb-l-navbtn.back`（22px stroke2 / `--mb-tint` / 44×44 / `left:10px; margin-left:-6px`）。
- 标题 `.kb-new-bartitle`：**17/600、绝对居中、`left:52px; right:52px`**、单行省略（现值即可，不动）。

### 5.2 草稿区（本轮最重要的结构变化：裸排 → 卡）

**为什么卡化**：浅色下两个占位（19px 灰 + 15px 灰）压在 #F2F2F7 上，读起来像两个**静态标签**而不是
"可以打字"；且裸排与下方三张卡之间没有任何语汇承接（这就是"衔接生硬"）。卡化之后，整页 = 抬头纸 + 三张卡，
每个块都在同一条 16 的轨道上，缝自然就没了。**卡里依旧不画框**，所以它仍然是"抬头"不是"字段"。

- `.kb-new-draft`：`margin: 12px var(--mb-pad,16px) 0`；`padding: 12px 16px 14px`；
  `border-radius: var(--mb-r-card,12px)`；`background: var(--mb-surface)`；
  `box-shadow: 0 0 0 0.5px color-mix(in srgb, var(--mb-text) 9%, transparent)`。
  **不加 `:focus-within` 环**（v1.1，按 ux §4 裁决：无框输入区 focus 无描边，caret 即焦点指示；
  v1 的 30% tint 环方案作废）。
- `.kb-new-inputtitle`：`font-size:19px`；`font-weight:600`；`line-height:1.3`；`min-height:25px`；
  `padding:0`；`border:0`；`background:transparent`；`color: var(--mb-text)`；占位 `--mb-text-3`。
- `.kb-new-desc`：`margin-top:8px`；`font-size:15px`；`line-height:1.5`；`min-height:44px`；
  `max-height:180px`；`overflow-y:auto`；`padding:0`；`resize:none`；`color: var(--mb-text)`；占位 `--mb-text-3`。
- 内部**不画 hairline**（标题与描述是一组）；空态整卡高约 103px。

> 被否掉的两个方案：① 裸排 + 底部分隔线（线在输入区下面 = Web 表单下划线）；
> ② 裸排 + 更大留白（占位仍是灰对灰，缺"可输入"的暗示）。
> 顺带被否掉的第三案：focus 时给卡上环 —— ux 已裁决"caret 即焦点指示"（§4 标题输入行）。

### 5.3 分节头

`.kb-new-sec`：`padding: 24px 16px 8px`（**上 20 → 24**，页顶到"怎么干"的缝才和别处一致）；
`font-size:12px`；`font-weight:600`；`letter-spacing:0.06em`；`color: var(--mb-text-3)`。
文案：B 段「怎么干」不变；**C 段「更多设置」→「建好之后」**（ux 决策 D1，改 `sec()` 一处字符串，不动结构）。

> 说明：0.06em 字距对中文略"仿栏目"，但这是全站分节头的统一值（`#mbPicker .mb-picker-sec` 同值）。
> 本页若单独改 0，从本页推进选择页时会看出两套头。**全局统一另立任务**，本轮不动。

### 5.4 「怎么干」：两张大卡（撤圆点，值上移）

结构（模板里只动两处：删一行、挪一行，钩子一个不动）：

```
<label class="kb-new-radio is-card">
  <input type="radio" name="kbNewMode" value="person">     ← 不动（仍是真的 radio，视觉隐藏）
  <span class="kb-new-rtxt">
    <span class="kb-new-rtitle">派给他</span>               ← 15/500
    <span class="kb-new-rpick is-on">王工</span>            ← 从 sub 之后挪到这里
    <span class="kb-new-rsub">发到他的会话里去做…</span>    ← 12.5/400
  </span>
  <button class="kb-new-gopick" data-kb-gopick="who">      ← 不动
    <i class="kb-new-chev"></i>
  </button>
</label>
```

- `<span class="kb-new-rdot">` **删除**（模板 + 4 条 CSS）。
- `.kb-new-modes`：`display:flex; flex-direction:column; gap:8px`（两张卡之间是**间隙**不是线，保持）。
- `.kb-new-radio.is-card`：`position:relative`；`display:flex`；`align-items:flex-start`；
  `padding:12px 46px 12px 16px`；`border:0`；`border-radius:var(--mb-r-card,12px)`；
  `background:var(--mb-surface)`；
  `box-shadow:0 0 0 0.5px color-mix(in srgb, var(--mb-text) 9%, transparent)`；
  `transition: box-shadow 120ms`；`cursor:pointer`；`min-height:0`。
  - `:active`：`background: color-mix(in srgb, var(--mb-text) 6%, var(--mb-surface))`（**不换底色档位**，
    只为"点到了"；两张主题都成立）。
  - `:has(input:checked)`：`box-shadow: 0 0 0 1.5px color-mix(in srgb, var(--mb-tint) 60%, transparent)`；
    背景**保持 surface**（不加 tint 淡底）。
  - `:has(input:disabled)`：`cursor:default`；环回落 0.5px 9%；`rtitle` 转 `--mb-text-3`；
    **`rsub` 保持 `--mb-text-2` 不降**（v1.1，ux 红线：置灰卡的副标题 ≥4.5:1——"还没有已发布的流程"
    是指路信息，降了就看不见路）。
- `.kb-new-rtitle`：`font-size:15px`；`font-weight:500`；`line-height:1.33`；`color:var(--mb-text)`；
  选中时 `color: color-mix(in srgb, var(--mb-tint) 78%, var(--mb-text))`（文本级 tint，
  `:has(input:checked)` 派生，**权重不变** —— 避免选中瞬间换字重引起换行）。
- `.kb-new-rpick`（回显值）：`margin-top:3px`；`font-size:13.5px`；`line-height:1.35`；
  `white-space:nowrap; overflow:hidden; text-overflow:ellipsis`；默认 `color:var(--mb-text-3)`；`font-weight:400`。
  - `.is-on`（有值）：`color:var(--mb-text)`；`font-weight:500`。
  - 单行省略是**有意的**：流程名可以很长，卡片高度必须和另一张卡一致；全文在选择页里看。
- `.kb-new-rsub`：`margin-top:2px`；`font-size:12.5px`；`line-height:1.35`；`color:var(--mb-text-3)`。
- 卡高：12 + 20 + 3 + 18 + 2 + 17 + 12 = **84px**（两种状态同高）。
- `.kb-new-gopick`（› 的入口）：`position:absolute`；`right:-2px`；`top:50%`；`transform:translateY(-50%)`；
  `width:44px; height:44px`；`display:grid; place-items:center`；`border:0; padding:0`；
  `border-radius:10px`；`background:transparent`；`:active` → `var(--mb-press)`；
  `:focus-visible` → `outline:2px solid var(--mb-tint); outline-offset:-2px`。
  `right:-2px` 是**光学对齐**：箭头视觉右缘落在卡边内 16px，与下方设置行的箭头同一条竖线（差 <1px），
  44px 热区因此向卡外溢出 2px（卡外还有 16px 页边距，不会出屏）。
- `.kb-new-chev`（全页共用）：`width:6px; height:6px`；`border-top/border-right:1.5px solid color-mix(in srgb, var(--mb-text-2) 45%, transparent)`；
  `transform:rotate(45deg)`。**统一 45%**，删掉 `.kb-new-gopick .kb-new-chev` 的 55% 覆盖。

**选中态为什么不用 ✓**：本页 ✓ 已出现两次（选择页行尾、开关），再给卡一颗会把页面读成问卷；
"2 选 1 + 1.5px 染色描边 + 标题同色"在深浅两套里都是无歧义的。也不用圆点：圆点的问题不是"不够 iOS"，
而是它**逼出一条 48 的左缩进**，与卡内其它文字永远对不齐。

### 5.5 「建好之后」（原「更多设置」）：三行同构 + 右侧开关

```
[状态        待办 ›]
[项目        未选择 ›]        （仅全局面板）
[创建后立即开始      (开关)]
 未派活：卡先挂着，谁也不会被叫醒      ← #kbNewHint，贴在行下沿，不画线
```

- 容器 `.kb-new-card`：`border-radius:12px`；`background:var(--mb-surface)`；`box-shadow:0 0 0 0.5px color-mix(in srgb, var(--mb-text) 9%, transparent)`；`overflow:hidden`；`margin:0 16px 8px`。
- 行 `.kb-new-row`：`min-height:52px`；`padding:11px 16px`；`gap:12px`；`:active` → `var(--mb-press)`。
  `.kb-new-lab` 15/400 `--mb-text`；`.kb-new-val` 15/400 `--mb-text-2`，`.is-empty` → `--mb-text-3`；
  `.kb-new-chev` 同上（右缘在卡边内 16）。
- **行间 hairline 改成左缩进 16**（现在通栏，和卡片外缘的圆角撞在一起）：
  删 `.kb-new-card > * + * { border-top }`，改为给 `.kb-new-row` / `.kb-new-check` 加
  `position:relative` 与 `::before { content:''; position:absolute; left:16px; right:0; top:0; height:0.5px; background:var(--mb-hairline) }`，
  并 `.kb-new-card > :first-child::before { display:none }`。
  这样"勾选框行 → 说明小字"之间天然没有线（`p` 上没有 `::before`），不需要 `:not(:last-child)` 例外。
- **勾选框 → 开关**（`<input type=checkbox>` 不动，`.kb-new-box` + 内嵌 SVG 退役）：
  - `.kb-new-check`（同一条行语汇，不再有自己的卡皮）：`position:relative`；`display:flex`；`align-items:center`；
    `gap:12px`；`min-height:50px`；`padding:11px 16px 0`；`cursor:pointer`；`:focus-visible` 同 `.kb-new-row`。
  - `.kb-new-lab` 之后插入 `<span class="kb-new-sw" aria-hidden="true"></span>`，`.kb-new-lab { flex:1 1 auto; min-width:0 }`。
  - `.kb-new-sw`：`flex:0 0 auto`；`width:46px; height:28px`；`border-radius:999px`；

  - `.kb-new-sw::after`（旋钮）：`content:''`；`position:absolute`；`top:2px; left:2px`；`width:24px; height:24px`；
    `border-radius:50%`；`background:var(--mb-on-bubble)`；`transition:transform 180ms`。
  - `.kb-new-check.on .kb-new-sw`：`background:var(--mb-tint)`；`.on .kb-new-sw::after` → `transform:translateX(18px)`。
  - `[aria-disabled="true"] .kb-new-sw`：`opacity:0.4`（**label 一个像素都不降** —— 现值口径保留：那句话是唯一解释）。
  - `:has(input:focus-visible)` → `outline:2px solid var(--mb-tint); outline-offset:-2px`。

  **`color` 走文本级 tint**：`color-mix(in srgb, var(--mb-tint) 78%, var(--mb-text))`（浅 5.4:1 / 深 8.9:1，
  裸 tint 浅色压灰页只有 3.7:1，不达红线）。

### 5.6 底部主按钮

- `.kb-new-foot`：`flex:0 0 auto`；`padding:8px 16px calc(8px + env(safe-area-inset-bottom,0px))`；
  `background:var(--mb-page)`；**不画 hairline**（滚动内容在它上方被裁切，线会像断了一截）。
- `.kb-new-submit`：`min-height:50px`；`border:0`；`border-radius:var(--mb-r-card,12px)`；
  `background:var(--mb-btn-send)`；`color:var(--mb-on-bubble)`；`font-size:16px; font-weight:600`；
  `transition:background-color 120ms`；`:active { filter:brightness(0.94) }`。
- **文案随模式三态**（ux 决策 D2，JS 只改 `textContent`，本规格管的是"形不变"）：

| 条件 | 文案 |
|---|---|
| 流程模式 + 已选流程 + 状态≠想法 | 创建并发起流程 |
| 派给他 + 数字员工 + 勾了立即开始 | 创建并派活 |
| 其余（含开页默认） | 创建任务 |

  三句都 ≤7 字、几何与颜色恒定 —— 按钮"形"不变只有"话"变，不会引起布局跳动（文案刷新
  发生在 `paintKbNew` 重画内，宽度按内容自适应但都在 358px 内，不会换行）。
- 位置结论：**吸底**（页脚 flex 尾项，不是 `sticky`）—— 因为键盘适配要求整页高度跟着
  `--mb-vh` 缩，页脚必须是同一列 flex 的尾巴；`sticky` 在"高度会变"的容器里会抖，且和页脚重复两套。
- 高度 50 是 iOS 大按钮档（44 只够图标行；本页是"完成动作"，压手一点更像 App）。
- 提交中连带状态：顶栏 ‹ 同步 `disabled`（走既有 `.kb-l-navbtn:disabled { opacity:0.4 }`），
  整页禁返回（ux §3.3）；视觉上按钮保持蓝色、只换文案「创建中…」，返回箭头降 40% ——
  两处都是"这页正在干活"的同一次表达。**「创建中…」是唯一的忙碌线索，不能省**（ux 确认条件）。
- 可选加分项（P2，有余力再做）：文案左侧加 14px 白色转圈（`border:2px solid` 35% 白 + 顶边实白，
  `animation: spin .8s linear infinite`），`prefers-reduced-motion` 下换静态半透明白点。
  不做进度百分比 —— 弱网下它只会骗人。

### 5.7 键盘（布局级铁律，必改）

`.kb-new` 现在是 `position:fixed; inset:0` —— 键盘弹起时**布局视口不缩**，页脚那 66px 会被键盘
整个盖住，输入框也可能被挤到下半屏。改用 `.tc-sheet` 同款手法：

- `.kb-new`：删 `inset:0`，改 `top:0; left:0; right:0; height:var(--mb-vh,100%)`（`--mb-vh` = visualViewport 高度，
  由 `mobile.mjs` ④ 喂）。其余（`transform` / `transition` / `z-index:90` / `flex-direction:column`）不动。
- `.kb-new-body`：`flex:1 1 auto`；`min-height:0`；`overflow-y:auto`；`padding-bottom:8px`；
  `overscroll-behavior:contain`；`-webkit-overflow-scrolling:touch`。
- 结果：390×844 + 键盘 336 → 可视 508；导航 99 + 页脚 66 → 内容区 343，标题输入在内容区顶部（上半屏），
  页脚贴着键盘上沿。**不需要任何 JS 滚动补偿**。

## 6. 四态规范

### 6.1 选中态（执行方式卡）

| 态 | 视觉 |
|---|---|
| 未选 | 面 surface + 0.5px 9% 环；标题 15/500 `--mb-text`；值 13.5/400 `--mb-text-3`（「不派活」「未选择」）；解释 12.5 `--mb-text-3`；› `--mb-text-2` 45% |
| 已选 | 面 surface + **1.5px tint 60% 环**；标题 15/500 **文本级 tint**（78% tint 混 `--mb-text`）；值 13.5/**500 `--mb-text`**；解释不变；› 不变 |
| 不可选 | 面 surface + 0.5px 9% 环；标题 `--mb-text-3`；**解释保持 `--mb-text-2`（红线，不降）**；**不渲染 ›**；`cursor:default` |
| 按压 | 面 `color-mix(text 6%, surface)`；环不变 |

切换选中**不产生任何位移**（环走 box-shadow，字重与字号恒定）。

### 6.2 回显（`.kb-new-rpick`）

| 态 | 视觉 | 例 |
|---|---|---|
| 有值 | 13.5 / **500** / `--mb-text`，位置在标题正下方、解释之上 | 「王工」「开发完成 → 建 PR → 审阅 → 合并」 |
| 无值 | 13.5 / 400 / `--mb-text-3` | 「不派活」「未选择」 |
| 超长 | 单行 `nowrap + ellipsis`，右端不侵入 › 的 46px 保留区 | 「开发完成 → 建 PR → 审阅…」 |

要点：**"给了谁"必须比"怎么走"更亮**。现状是反的（解释在值上面，值最后一行灰字）。

> 与 ux 的一处分歧，已按视觉域裁决并确认（ux v1.1 回执采纳）：ux §3.2 写"回显有值染 tint"
> （v109 时代的规定，那时卡还没有环）。本规格改判为 `--mb-text`/500 —— 标题已染 tint，值再染
> tint 会让整卡全蓝、且 13.5px 的蓝字可读性不如黑/白；"找到了卡"→"读出人名"是两步，颜色不用
> 做两遍。额外收益：弱视用户放大看卡时，答案（人名）不再与模式标题抢注意力。
> 若后续要回退，是一行 CSS（`.kb-new-rpick.is-on { color: <文本级 tint> }`），零几何影响。

### 6.3 禁用

| 对象 | 规则 |
|---|---|
| 流程卡（无已发布流程） | 标题 `--mb-text-3`、解释 `--mb-text-2`（红线）；环回落静环；**不渲染 ›**；下方出「去发布 ›」（文本级 tint） |

| 开关（锁死在开） | `checked` + tint 轨道 40%，`cursor:default`；不额外画锁 |

### 6.4 主按钮四态

| 态 | 触发 | 视觉 |
|---|---|---|
| 可用 | 标题非空 | `--mb-btn-send` 底 + `--mb-on-bubble` 白字 16/600；`aria-disabled="false"`；文案按 §5.6 三态表 |

## 7. 双主题对照（需要人工核的两处）

1. **不选中卡的可见性**（现缺陷）：深色下未选卡面 = 页底（#000），只有 0.5px 环。本规格把未选卡

   若深色下环显得"发光"，降到 50%；浅色下若看不出，升到 70%。**只动这一个数，不动结构。**
3. **对比度红线实测**（ux §7-5/6，本规格 v1.1 已按此选档，验收用计算值抽查）：

- **toast（成功「已创建，{名}这就开始」）**：走全局 `.toast`（`max-width:min(440px,78vw)`），`.toast-text`
  本身 `overflow:auto` 不截断，中文可自然换行 —— 390 宽下约 304px/行，长名最多 3 行，**页面侧零改动**。
  唯一建议：给 `.toast-text` 补 `overflow-wrap:anywhere`，防长英文/无空格名把 toast 撑出屏（全局一行，
  不属于本页规格）。
- aria 层（卡组 `role=radiogroup`、`aria-label` 拼回显、`aria-describedby → #kbNewHint`）按 ux 交互规格
  §7 实施，视觉规格不约束。

## 11. 与 ux / 前端的接口（v1.1 对齐结论）

- 交互口径以《2026-11-06-移动端新建任务-交互规格》为准；本规格**不改任何可点区域与流程**：
  - 整张卡 = 选模式（label + radio，不变）；右侧 44×44 = 进选择页（`data-kb-gopick`，不变，热区 36→44）。
  - 开关行仍是"点整行切换"；开关只是同一个 `<input type=checkbox>` 换皮。
  - 说明小字 DOM 位置不变（卡内最后、`aria-live` 保留），只去线、缩距、升对比。
- **四处视觉域裁决，已写入规格、请 ux 知悉**（其 §3.7 线框与本规格一致）：
  1. 选中卡**不加"微 tint 底"**（线框里的"微底"按视觉域否决：深色下 5% tint 不可见、浅色下像

  3. 回显有值**不染 tint**，用 `--mb-text`/500（理由见 §6.2 注）；若 ux 坚持，一行 CSS 可回退。
  4. 「去发布 ›」与选中卡标题走**文本级 tint**（78% tint 混 `--mb-text`）——裸 tint 浅色不达 4.5:1 红线。
