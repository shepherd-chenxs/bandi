# 远程连接 · 轻量终端方案

> ⚠️ **2026-10-26 20:13 需求澄清后：本方案暂不采用，只作参考。** 用户的实际需求是
> 「钥匙照旧保管、给数字员工用」＋「人偶尔传个文件、敲几条命令」——不需要常驻终端/多标签/监控，
> 完整版（6–9 天 + vendored ssh2）不划算。轻量路线与取舍见对话记录；若最终选外置工具，本模块几乎不用动。

> 输入原话（转述）：「把远程连接这个模块做成一个简单版的 SSH 终端工具。你觉得怎么样？或者说 github 上有没有什么工具可以集成到班底里来」
> 状态：**方案，待拍板**。只有一件事必须你点头：是否接受把 `ssh2` vendored 进仓库（§10）。

## 0. 结论

值得做。但**不要搬一个成品进来**，只做三件：

1. **终端** —— 多标签、真 PTY、拖窗口能 resize。前端 xterm.js，后端 ssh2。
2. **文件** —— 同一条 SSH 连接上开 sftp 子系统：浏览 / 上传 / 下载 / 改名 / 删除 / 新建。
3. **监控** —— 同一条连接上定时 exec，读 `/proc`：CPU / 内存 / 磁盘 / 网络 / 负载。

一句话理由：**GitHub 上现成的都是"另一个产品"，不是"一个模块"**；而这三件的底层（xterm.js + ssh2）恰恰是它们共用的。自己写 1.2~1.8k 行，比集成一个第二平台小得多，还能直接复用现有的登记表、密钥、令牌和界面。

技术上有个硬结论（实测，见 §3）：**走系统 OpenSSH 拿不到可用的 PTY** —— stdin 是管道时远端 PTY 是 **0×0**，且永远收不到窗口变化。所以"完全零依赖"这条路在终端上走不通：要么接受一个尺寸定死、vim/htop 全糊的假终端，要么把 `ssh2`（纯 JS、MIT、约 1MB）vendored 进来。

## 2. 「简单版」的边界：P0 / P1 / 不做

**P0（这一版的目标）**

- 终端：多标签、PTY 尺寸跟容器走、resize、复制粘贴、字号、断线提示与重连、关标签即断开。
- 文件：路径栏、进入/上级、列表（名称/大小/时间/权限）、上传（含拖拽）、下载、新建目录、改名、删除、显示隐藏文件。
- 监控：CPU / 内存 / 交换 / 负载 / 磁盘 / 网络，2 秒一采样 + 最近 60 秒迷你曲线；面板收起时暂停采样。
- 横切：首次连接的主机指纹确认（TOFU）并写回登记表；会话上限与回收；权限（面板令牌不能开终端）。

**P1（这版之后再说）**

- 快捷命令 / 命令历史（同类客户端的快捷命令块）
- 终端搜索（Ctrl+F）、WebLinks、多标签恢复（刷新后恢复"上次开了哪几台"）
- 文件预览（文本/图片）、跨服务器传文件、传输队列
- 会话审计（谁在何时连了哪台）、只读分享

**明确不做**

- 端口转发 / 隧道 / 跳板机、代理、X11、ZMODEM、串口
- RDP / VNC / Telnet（那是另一个产品）
- 会话录制、多人共享、多用户权限体系
- 分屏、批量执行、密码登录（**可议**：现有设计明确"不收口令"，见 §10）
- 自带文件编辑器（要编辑就在终端里 vim）

## 3. 关键技术判断（有实测，不是拍脑袋）

### 3.1 系统 ssh 走管道：pty 0×0、resize 永远不会来

用本地假 sshd + Windows 自带 `ssh.exe`（OpenSSH_for_Windows_9.5p2）实测：

| 用法 | 服务端收到的 pty | 收到的 window-change |
| --- | --- | --- |
| `ssh -tt`（stdin 是管道，浏览器终端的唯一用法） | `cols=0, rows=0, term=xterm-256color` | 无 |
| `ssh -T`（不要 pty） | 没有 pty | 无 |
| `ssh -T host -- 'echo hi'`（exec） | 无 | 无 |

原因：OpenSSH 的 `pty-req` 窗口尺寸取自**本地 tty**；stdin 是管道就取不到，只能发 0×0。`window-change` 同样是本地 `SIGWINCH` 驱动的 —— 管道没有 tty，也就永远不会有这个信号。

唯一的绕法是连接时先把尺寸定死：`ssh -tt host 'stty rows 40 cols 120; exec $SHELL -l'`。这样首屏能看，但**之后拖窗口/开侧栏，远端永远不知道**；`vim`、`htop`、`top` 会按旧尺寸画。这就是"零依赖"在终端上的天花板。

> 顺带确认：现有「测」和 MCP 的 `ssh_run` 走 exec，完全不受影响 —— 只有交互式终端受影响。

### 3.2 ssh2（vendored）能补齐，而且能离线测

本地起 `ssh2.Server` 假服务 + `ssh2.Client` 实测（`ssh2@1.17.0`）：

| 能力 | 实测结果 |
| --- | --- |
| publickey 登录 | ✓（不用系统 ssh / sshd） |
| PTY shell 初始尺寸 | ✓ 服务端收到 `cols=120, rows=40` |
| 拖窗口 resize | ✓ `setWindow(50,170)` → 服务端收到 `window-change {rows:50, cols:170}` |
| 键盘输入 → 远端、远端输出 → 客户端 | ✓ 字节往返完整 |
| exec（监控采样用） | ✓ 同一条连接上开 exec 通道 |
| SFTP | ✓ 目录列表；返回**结构化属性**（size / mtime / mode），不用解析 `ls -l` |
| 去掉可选原生依赖（cpu-features / nan） | ✓ 仍然全通过（纯 JS 可跑） |
| ESM 里 `import ssh2 from '.../lib/index.js'` | ✓（默认导入，`utils.sftp` 常量可用） |

体积：`lib/` 655KB + 纯 JS 依赖（asn1 19KB / bcrypt-pbkdf 28KB / safer-buffer 41KB / tweetnacl 170KB）≈ **1MB**。MIT。

替代品为什么不行：Node 内置没有 PTY；`node-pty` 是原生模块（要编译/预编译包），和"装上就能跑、一个人能维护"相冲。`ssh2` 是纯 JS，还同时带 **Server** —— 正好用来写**不碰真机、不碰 `~/.ssh`** 的冒烟测试（`docs/审阅经验.md` 第一条就是这条纪律）。

### 3.3 前端：xterm.js

- `@xterm/xterm@6.0.0`（MIT）：`lib/xterm.mjs` 345KB（`export { Terminal }`）+ `css/xterm.css` 7KB，ESM 直接引，**不需要打包器**（`http.mjs:137` 已认 `.mjs` 的 MIME）。
- 加 `@xterm/addon-fit`（MIT，20KB）：把容器尺寸算成行列。
- ttyd / wetty / webssh2 / Termix 用的都是它；自己写 VT 解析不现实。
- 放 `apps/web/vendor/`，`index.html` 加一条 `<link>`。

### 3.4 传输：沿用 SSE + POST，不引 WebSocket

- 仓库已有结论是不引 WS（[形态决策 §5](../形态决策.md)：手写握手+分帧两百行易错，引 `ws` 又破零依赖）。终端没理由开这个口子。
- 一条**页面级 SSE** 多路复用所有终端输出，避开浏览器"同域 6 条连接"的上限（`/api/events` 已经占一条）；键盘/尺寸/上传走 POST。
- 输入每 16ms 批量、按序发；输出带 `seq`，断线重连按 ring buffer 补发。
- 背压：SSE `write()` 返回 false 就 `pause()` 对应 SSH 流，`drain` 再 `resume()` —— 客户端慢就让远端等，不堆内存。

### 3.5 主机指纹：顺手把旧洞补上

- `ssh2` 的 `hostHash:'sha256'` + `hostVerifier` 拿到主机钥匙哈希（hex），转成 OpenSSH 的 `SHA256:<base64>`，和登记表现有 `host_fingerprint` 字段对齐。
- 首次连接：弹窗显示指纹 + 「信任并记住」→ 写 `host_fingerprint` / `host_fingerprint_verified: true`。
- 之后每次连接比对，不一致就拒绝并说明（现在走 `StrictHostKeyChecking=accept-new`，首连是**静默信任**）。
- 连上后写 `last_checked` / `status`（现成字段，从没被写过），列表状态才不是摆设。

**结论**

- **没有一个能"直接嵌进班底"的现成终端模块。** 最接近的是 Termix —— 它是成品平台，不是模块；真要"集成"，等于在班底里再养一个平台（账号/主机台账/数据库/几百 MB），和这套"一个进程、一个人能维护"的形态冲突。
- 只想「网页里能连上」：ttyd 或 webssh2 当侧车 + iframe，1~2 天能出；但补不出文件面板和监控，且要自己管进程、端口、鉴权。
- 想要桌面客户端那种体验又不想开发：**单独跑一个 Termix**（Docker 或桌面版），班底当"派活的地方"、Termix 当"连机器的窗口"，两者并存 —— 不要往同一个安装包里塞。
- 许可证红线：AGPL（sshwifty）不进发行包；Guacamole 官方不支持 Windows；Tabby/Electerm/WindTerm 是客户端，嵌不进来。

## 6. 接口草图

```
POST   /api/ssh/sessions                    { alias }        → { sid }
                                           首次连接 → 409 { needTrust:true, fingerprint:"SHA256:..." }
POST   /api/ssh/servers/:alias/trust        { fingerprint }  → 记住主机指纹（写回登记表）
GET    /api/ssh/term/stream                                  → SSE：
             { type:"data",  sid, seq, data }        终端输出
             { type:"stats", sid, stats:{...} }      监控采样（2s）
             { type:"exit",  sid, reason }           断开/远端退出
POST   /api/ssh/sessions/:sid/input         { data }        键盘（按序、16ms 批量）
POST   /api/ssh/sessions/:sid/resize        { cols, rows }  容器尺寸变了
DELETE /api/ssh/sessions/:sid                              关标签/超时回收

GET    /api/ssh/sessions/:sid/files?path=/home/bandi        列表（结构化属性）
GET    /api/ssh/sessions/:sid/file?path=...                 下载（流式，带 Content-Disposition）
POST   /api/ssh/sessions/:sid/files?op=upload               上传（raw body 流式，不落临时文件）
POST   /api/ssh/sessions/:sid/files?op=mkdir|rename|delete|chmod   {}
```

错误沿用现有 E1xxx + 中文文案；会话 sid 用 128bit 随机；所有接口都在现有 `auth.guard` 之后。

**交互**

- 点登记行 = 连接并在右侧开标签；行内仍保留 测 / 改 / 删 / 引导。
- 标签：别名 + 状态点（灰未连 / 绿已连 / 红断开）；`×` 关闭（确认，会断开远端）；断开显示横幅 + 「重连」。
- 终端：字号（Ctrl+滚轮）、复制/粘贴（右键菜单 + 快捷键）、清屏、`Ctrl+F` 搜索（P1）；中文输入法走 xterm 的 composition 事件。
- 文件：双击目录进入；双击文件下载；上传支持按钮和拖拽；传输中显示进度；操作完自动刷新当前目录；「在终端打开此目录」往终端里发 `cd`。
- 监控：面板收起就停采样；靠近窗口边缘时 2s 一次太费就降到 5s（可配置）。
- 主题：跟随班底 light/dark；xterm 主题从现有 CSS 变量算出来，不另写一套色板。

## 8. 安全边界

- **终端 = 远端 RCE**：和现有接口同一道 `auth.guard`；POST 继续过 `guardWrite`（CSRF）；默认只听本机、非回环要令牌 —— 这些都已经有了，不改。
- **面板令牌不能开终端**：`POST /api/ssh/sessions*` 加进 `auth.mjs` 的 `PANEL_FORBIDDEN`（面板令牌是"能看不能管"，终端是管理动作）。
- **不落盘口令、不读私钥正文**：和现在一样，只把私钥路径交给 ssh2。
- **不记录击键**：只有内存 ring buffer（每会话 200KB），会话结束即释放；不做会话录制（P1 再说）。
- **上传/下载流式**，单文件上限和 `readRawBody` 默认一致（200MB），不落临时文件。
- **会话上限 + 空闲回收**：最多 8 条，页面关掉/断 SSE 10 分钟后回收，防一个前端 bug 把 sshd 打满。
- **退出清理**：控制面退出/重启时显式 `client.end()`；关标签 3 秒内远端 `who` 应该少一个人。

## 10. 代价、风险、要你拍板的一件事

**要拍板：依赖政策。**

| 方案 | 终端体验 | 代价 |
| --- | --- | --- |
| **A. 坚持零依赖（系统 ssh + 管道）** | 远端 PTY 0×0；只能连接时定死尺寸；拖窗口不跟随；vim/htop 糊；SFTP 要解析 `sftp -b` 的文本输出 | 0 新增代码体积；但"轻量终端"名不副实 |
| **B. vendored ssh2 + xterm（推荐）** | 真 PTY、resize、结构化 SFTP、离线可测 | 仓库多约 1.3MB 第三方 JS；`README` 的"零依赖"要改成"无 npm install，第三方库 vendor 在仓库内"；`NOTICE` 补 MIT 声明 |
| **C. 侧车（ttyd / webssh2）** | 终端体验最好 | 多一个进程/端口/认证；文件与监控仍要自己做；Windows 还要分发包二进制 |

我的建议是 **B**。理由：A 做出来用户第一眼就会失望（尺寸不对的终端比没有终端更糟）；C 只是把问题推给另一个进程，还补不出文件+监控。B 的 1MB 相对于安装包里的 `node.exe`（~80MB）可以忽略，而换回来的是"这个模块真的能用"。

**其余风险**

- vendored 代码的维护：锁版本，`vendor/README.md` 写清来源/版本/更新办法；升级用一次性脚本，不手工改。
- 体积细账：`ssh2/lib` 655KB + 纯 JS 依赖 258KB ≈ **0.9MB**（只带 lib 与 LICENSE，不带它的 test/examples）；xterm 345KB + fit 20KB。合计约 **1.3MB**。
- 老 sshd 只支持 `ssh-rsa` 等旧算法：ssh2 默认算法较新，需要时按服务器降级配置（做成登记表里一个可选项，P1）。
- Windows 作为**目标机**：SFTP 路径形如 `/C:/Users/...`，路径处理要按服务端返回的 realpath 走，别硬拼。
- 监控首版只承诺 Linux（`/proc`）；macOS / Windows 目标显示"暂不支持"，不做假数据。
- **密码登录**：现在设计明确"不收口令"，首版只支持密钥。桌面客户端用户常要密码登录 —— 要的话建议做成"一次性口令、不落盘、不写历史"的 P1，需你点头。
- 断点续传、大文件分块、ZMODEM、端口转发：不做。
