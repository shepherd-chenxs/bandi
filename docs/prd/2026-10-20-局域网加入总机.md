# 局域网加入总机 · PRD

> 版本：2026-10-20（简单 PRD）｜提出：用户 / 产品：Alice
> 前置阅读：`docs/形态决策.md`（托管控制面 ＋ 客户端出站节点、认领不做同步、单机看不见节点）

## 一、项目信息

| 项 | 内容 |
| --- | --- |
| Language | 中文 |
| Programming Language | 原生 JS（`apps/web/app.js` + `style.css`，无框架、无构建）+ Node 内置模块（`node:http`/`node:dgram`/`node:sqlite`/`node:crypto`，**零 npm 依赖**） |
| Project Name | `bandi-lan-join` |
| 生效方式 | 前端改动刷新即生效；服务端（含发现服务）改动需重启控制面；桌面壳改动需重新编译 |
| 本次范围 | 只做「加入入口」＋「节点定位（瘦客户端）」。路径映射、多总机、数据迁移、TLS 全部不做 |

**原始需求复述（用户已确认，不推翻）**

1. 一台新机器要能在局域网内连接到某台总机，成为它的一个节点。
2. **节点定位 = 瘦客户端**：加入之后，这台机器自己打开班底，看到的是**总机的面板**，不是它自己那套本地空库。
3. **加入动作发生在新机器上**：点「加入总机」→ 自动发现 → 选中 → 输邀请码 → 生效。总机侧现有的「添加设备」（发一次性邀请码 + 给一段 shell 命令）**保留**，两条路都能走。

---

## 二、一句话目标

**让一个不懂命令行的用户，在新机器上点四下（加入 → 选中总机 → 输码 → 完成），就能把这台机器变成某台总机的瘦客户端；同时让总机侧清楚地知道"面板权限给了谁、随时能收回来"。**

## 三、背景与现状

**通道已经有了，缺的只是入口与定位。**

| 已有（不要重写） | 位置 |
| --- | --- |
| 局域网开关：打开后监听 `0.0.0.0`、强制鉴权、点「重启」原地换监听 | `apps/web/app.js` 设备页「局域网」段、`netmode.mjs`、`POST /api/lan` / `POST /api/restart` |
| 总机发**一次性邀请码**（10 分钟、单次）＋ 一段可粘贴的 shell 命令 | `openJoinDialog()`、`POST /api/nodes/invites` |
| 新机器凭码换回**只属于自己的令牌**，写进该机 `config.json` | `node.mjs --join`、`POST /api/nodes/join` |
| 节点常驻：15s 心跳 + 长轮询领活（20s）+ 事件分块回传 + 反向停止 | `node.mjs`、`POST /api/nodes/:id/claim`、`/api/runs/:id/events` |
| 设备列表显示「在线/离线/排队 N」、节点详情只读、「忘掉」= 删节点 | `renderDeviceList()`、`DELETE /api/nodes/:id` |

**三个缺口：**

1. **入口在错的地方**：加入必须去新机器上跑 `node apps/server/src/node.mjs --join ...` —— 要装 Node、要会用命令行，普通人到不了。
2. **加入之后那台机器还是不认账**：桌面壳每次启动都**先起一个本机控制面**，窗口指向 `127.0.0.1:<port>` —— 于是用户看到的是本机空库，而不是总机面板。「瘦客户端」这件事今天完全没有实现。
3. **节点令牌看不了面板**：令牌只能碰「报到/心跳/领活/回执」四条路（`auth.mjs` 的 `nodeMayReach`），面板请求一律 403。要让瘦客户端成立，令牌必须扩权 —— 这是本 PRD 最需要拍板的一处。

## 四、用户故事

- 作为**刚买第二台电脑的人**，我想在新电脑上点几下就连上我旧电脑上的班底，以便不用在新电脑上重新建员工、重新配一遍。
- 作为**在新电脑上办公的人**，我想打开班底就看到**旧电脑那张面板**（员工、会话、项目一模一样），以便我知道活派给了谁、进度到哪了，而不是对着一个空荡荡的本地库发呆。
- 作为**把办公室公用机加入进来的总机主人**，我想明确选择"这台只用来干活、不许看我的面板"，以便同事坐在那台机器前也翻不到我的对话和项目。
- 作为**在新机器上已经用过一段时间班底的人**，我想在加入之前就被明确告之本机那些数据会怎样，并且能先导一份出来，以便不必担心"点一下全没了"。
- 作为**想反悔的人**，我想随时退出总机回到独立模式，以便本机原来的员工和会话原样回来。

### 决策 A · 令牌 scope 的产品取舍（本 PRD 的核心判断题之一）

**问题**：现状节点令牌只能干节点自己的四条路。瘦客户端要能看面板 → 必须扩权。而"能看面板"等于把总机面板开放给那台机器上的**任何本机进程**（令牌在 `config.json` 里，0600 只防别的用户，不防同一个用户下的任意程序）。更深一层：面板能派活 → 活会落到**别的机器**上去跑 → 等价于"在那台被信任的机器上间接执行代码"。

**结论：让用户选，但预选"两者都要"，并且面板权限≠操作员权限。**

| 选项（向导里显示） | 存在令牌上的 scope | 这台机器打开班底看到什么 |
| --- | --- | --- |
| **当入口，也能干活**（默认，预选） | `panel` + `compute` | 总机的面板；同时它自己装的 CLI 也能接活 |
| 只当算力 | `compute` | 一张说明页：「这台机器在给「台式机」干活，但没有查看面板的权限」，一个按钮「我以为该能看」→ 提示去找总机主人开权限 |
| 只当入口 | `panel` | 总机的面板；不接活（适合没装任何 CLI 的机器，或不想让它跑活的机器） |

三条硬规则（这是取舍，不能由实现随意改）：

1. **面板 scope = 操作员 减去五类管理动作**：发邀请码、删/改设备、改连接器与凭据、改模型路由、重启控制面与改局域网开关。这五类只有握着 `token` 文件的那台机器能做。理由：`panel` 是"看和用"，不是"管"；否则一台被翻的瘦客户端能拉更多机器进来、或把别人的连接器密钥翻出来。
2. **scope 只能由总机侧改，节点侧只读**。改完对下一次请求立即生效（每次请求按身份判，不缓存）。理由：能自升级的权限等于没有权限边界。
3. **判定按"令牌是谁"，不按"令牌怎么带的"**。`X-Bandi-Token` 头、Cookie、`?token=` 三路必须走同一套 scope 判断 —— 否则"面板令牌换个 Cookie 就变成操作员"。（现状 `auth.mjs` 只有 `operator` 能做 Cookie 交换，`panel` 令牌要新增这条路，新增时必须共用同一个判定点。）

**默认值的理由**：本需求的立意就是"新机器当瘦客户端"。若默认「只当算力」，用户点完四下还看不到面板，等于本次白做。风险用上面三条规则 + 「忘掉即吊销」+ 总机侧可见来对冲，而不是靠默认值保守。

### 决策 B · 本地数据怎么交代（核心判断题之二）

**口径一句话：加入**不**迁移、**不**合并、**不**删除 —— 本机那份数据留在原地，只是"打开班底不再显示它"。**

| 时点 | 交代方式 |
| --- | --- |
| 加入前（向导步骤 3） | 一张「这一步会改变什么」：列出本机现有 `N 个员工 / N 段会话 / N 个项目`，写清三句：**① 加入后打开班底看到的是「台式机」的面板；② 这台机器上的这些数据不会被上传、也不会被合并进去；③ 它们不会被删除，随时能退出总机回到它们。** 底部一颗「先导出一份」（P0-5） |
| 加入后首次进入面板 | 一条一次性横幅：「这是「台式机」的面板。这台机器原来的数据还在本机，没有上传、也没有删。设置 →「这台机器」里能看到它，也能导出。」按钮：知道了 |
| 加入后随时 | 设置 →「这台机器」常显：本机数据 `路径 / 大小 / 最后修改时间` ＋「导出」＋「退出总机」 |
| 退出后 | 本机库原样回来（不是恢复，是**从来没动过**），打开班底看到的就是它 |

**为什么提供导出、不提供导入**：导出是"给人一份安心"，零架构成本（`VACUUM INTO` 已有）；导入等于同步的一半，与「认领，不做同步」这条已定决策直接冲突，本次不做也**不要留钩子**。

### 决策 C · 一台机器只能属于一个总机（核心判断题之三）

| 情形 | 产品行为 |
| --- | --- |
| 未加入，点「加入总机」 | 正常进向导 |
| **已加入**，点「加入总机」 | 直接拦：`E1093：这台机器已经加入了「台式机」（192.168.1.9），先退出才能加入别的`，下面只给一颗「退出总机」。**不做"切换"**（切换=先退再加，但把两件事做成一个按钮会掩盖"中途失败会两边都不属于"的风险） |
| **退出总机** | 二次确认：正文写清「① 这台机器的算力不再提供给「台式机」；② 打开班底看到的是本机原来的数据；③ 要再加入需要新的邀请码。建议先在总机的设备页把它「忘掉」，否则那边会留一行永远离线的设备。」确认 → 删 `config.json` 里的 `controlPlane/token/scope`（**保留 `node.json` 的 `id`**，重新加入同一总机不会攒出第二台设备）→ 停节点进程 → 壳重启回本机模式 |
| 退出后本地库 | **能正常用**。加入期间我们从来没写过它 |
| 总机已经把这台机器「忘掉」，但本机还写着已加入 | 开壳时连不上/被拒 → 说明页给「退出总机，回到本机」＋「重试」。不自动清配置（自动清会在总机只是关机时误伤） |

## 六、交互与文案

### 6.1 入口

**设置 →「这台机器」**（新增一个分区，只在"本机有控制面"时显示）。它同时承担本 PRD 的三件事：

```
┌─ 这台机器 ────────────────────────────────────┐
│  状态      独立使用（本机数据）              │
│  本机数据  C:\Users\me\AppData\Roaming\bandi\bandi.db   42.1 MB
│            12 个员工 · 37 段会话 · 3 个项目    最后修改 10-19 18:20
│                                  [ 导出 ]  [ 加入总机 ]  │
└──────────────────────────────────────────────┘
```

已加入时这一块换成：

```
┌─ 这台机器 ────────────────────────────────────┐
│  状态      已加入「台式机」 · 192.168.1.9:8787   ● 在线
│  这台能     看面板 · 也能干活        （由总机决定，这里只读）
│  本机数据  …\bandi.db   12 个员工 …   [ 导出 ]  [ 退出总机 ]
└──────────────────────────────────────────────┘
```

> 左侧「运行时」页保持现状（总机视角的设备列表 ＋ 添加设备 ＋ 局域网开关）。**「加入」放在「这台机器」，因为它改变的是"我是谁"，不是"我管着谁"。**

### 6.2 向导（5 步，全部在一个对话框里推进，可回退）

**步骤 1 · 扫描**

```
┌─ 加入总机 ───────────────────────────────┐
│                                          │
│        ◌ 正在找局域网里的班底总机…         │
│                                          │
│   已经找了 3 秒 · 同一网络里的班底会自动应答  │
│                                          │
│              [ 手动填地址 ]   [ 取消 ]     │
└──────────────────────────────────────────┘
```
- 最多 4 秒；扫到一台且只有一台 → **不自动选中**，仍然列出让用户确认（有人家里两台机器都开着班底，自动选错比多点一下更糟）。

**步骤 2 · 候选列表（一台或多台）**

```
┌─ 加入总机 ───────────────────────────────┐
│  找到 2 台：                              │
│  ┌────────────────────────────────────┐  │
│  │ 🖥 办公机            （可加入）       │  │
│  │    DESKTOP-7K2P · 192.168.1.9:8787  │  │
│  │                                     │  │
│  │ 🖥 我的笔记本        （未开局域网）    │  │
│  │    LAPTOP-3QX1 · 192.168.1.23:8791  │  │
│  └────────────────────────────────────┘  │
│  [ 重新扫描 ]              [ 手动填地址 ] │
└──────────────────────────────────────────┘
```
**区分字段（必须三样都给）**：机器名（人起的，可能是"办公机"这种重名）＋ **主机名**（不重，`DESKTOP-7K2P`）＋ **IP:端口**。外加一枚状态标签：
- `（可加入）` → 可点；
- `（未开局域网）` → **置灰不可点**，副文案「去那台机器上：设置 → 运行时 → 打开『允许局域网内的机器加入』→ 点重启」；

## 七、边界与不做清单

**技术边界（架构必须遵守）**

1. **前端原生 JS，无框架无构建**：只动 `apps/web/app.js` 与 `style.css`。不引入 React/Vue/MUI/Vite/TS/组件库；新界面沿用现有 `dlg`/`toast`/`confirmDo`/`rich()` 那套。
2. **服务端零依赖**：发现服务只用 `node:dgram`；不新增任何 npm 包。
3. **明文 HTTP**：局域网内不做 TLS、不做证书、不做 pinning。因此 scope 的安全叙事是"同一台机器上的进程都算同一身份"，不假装能防同机进程。
4. **错误一律「码 + 中文」**：新增 `E1090/E1091/E1092/E1093/E1094`（本机/向导侧）、`E2050`（总机版本太旧）、`E4012`（授权已被总机撤销）、`E4031`（只有算力权限，不能看面板）。UI 不显示堆栈，`alert` 禁用。
5. **`/api/local/*` 只在回环可用**：监听非回环时一律 `E1094`。
6. **令牌判定按身份不按携带方式**：header/Cookie/query 三路共用同一个 scope 判定函数。
7. **加入过程不写本机 `bandi.db`**：节点进程只碰 `config.json`/`node.json`/`runtimes.json`（探测用，只读）。

**本次明确不做（别顺手做）**

| 不做 | 为什么 |
| --- | --- |
| **路径映射**（同一项目在两台机器上路径不同导致派活失败） | 用户明确本次不做。现状口径保留：`node.mjs` 的 `cwdOf()` 明确失败、**不悄悄换目录**，报错里已写清原因 |
| **多总机 / 总机切换** | 配置文件里地址是单值。切换 = 先退再加，做成一个按钮会掩盖"中途失败两边都不属于" |
| **跨网段 / mDNS / 服务发现协议** | 只做同网段 UDP 广播。跨网段走手填地址；mDNS 要引依赖（破零依赖）且 Windows 支持差 |
| **数据迁移 / 合并 / 导入** | 与「认领，不做同步」直接冲突。导出的 `.db` 只是给人一份安心，不接回来 |
| **TLS / HTTPS / 自签证书** | 局域网明文是既定前提。要加密走隧道（`deploy/README` 已有 Cloudflare / SSH 两条） |
| **账号体系 / 用户名密码** | `auth.mjs` 已三次论证不做。本次只扩 scope，不动身份模型 |
| **首次启动引导 / 欢迎页** | 单机用户不该看见"节点"这个概念（形态决策 §一）。加入入口只在设置里，不弹窗 |
| **节点侧的 scope 自升级** | 只能是总机侧改 |
| **共享一台机器给多个总机同时干活** | 单值配置的另一面 |

## 八、待确认问题（4 条，附建议默认值）

1. **面板 scope 到底该不该减掉那五类管理动作？**
   建议默认：**减**（发邀请码 / 删改设备 / 改连接器与凭据 / 改模型路由 / 重启与局域网开关）。代价是瘦客户端上不能"在新机器上一键把第三台机器加进来"，得回总机那台操作。若你觉得这个限制烦，可只保留「发邀请码」一项允许 —— 但那样一台被翻的瘦客户端就能继续扩散。

2. **默认选项要不要就是「当入口，也能干活」？**
   建议默认：**是**，因为这就是本次需求的立意。反方观点：默认给面板权限，等于默认把面板交给一个"可能会借给同事用"的机器。若你更看重保守，可改成默认「只当算力」+ 在总机侧一键给面板权限 —— 但那会让"点四下就能用"变成"点四下 + 回总机点一下"。

3. **加入前是否强制导出？**
   建议默认：**不强制，只推荐**（一颗「先导出一份」，可直接跳过）。强制导出会在"用户从没在本机用过班底"时挡路，而那正是最常见的情形。

4. **「只当入口」（能看面板、不接活）这个选项要不要留？**
   建议默认：**留**。它成本为零（scope 组合而已），覆盖"这台机器没装任何 CLI""不想让这台机器跑活"两种真实情形。若嫌三选一复杂，可收成两选一（只当算力 / 两者都要），把「只当入口」留到以后。

## 九、风险

| # | 风险 | 影响 | 处置 |
| --- | --- | --- | --- |
| R1 | **Windows 防火墙拦 UDP 8788** | 发现扫不到，用户以为"这功能不存在" | ① 步骤 3 的兜底文案**点名**防火墙；② 手填地址这条路必须能独立走通，不依赖 UDP；③ 首次扫描 4 秒就停，不让用户干等；④ 文档里给 `netsh advfirewall` 一条放行命令（不自动改防火墙 —— 静默改系统安全设置比功能不灵更糟） |
| R2 | **反向代理 / 域名访问后的令牌泄露面** | 瘦客户端首次要带令牌进窗口（`?token=`），若总机在反代后面，URL 会落进反代 access log；且 `BANDI_ORIGINS` 没配那条 origin 时会"能看不能动" | ① 令牌只在**首次导航**出现，随即换 Cookie 并 302 掉（沿用 `auth.mjs` 现有做法）；② 反代的 access log 属于部署方责任，写进 `deploy/README`；③ 用域名/反代访问时必须在 `BANDI_ORIGINS` 里加该 origin，否则写请求 403 —— 这一条在向导失败文案与文档里都点明 |
| R3 | **节点双跑**（自启一个 + 手动一个，或壳又拉一个） | 同一 `deviceId` 两个进程：心跳互盖、各领一半活、事件重复回传 | P1-4 单实例锁（数据目录锁文件）；锁被占时后起的那份**直接退出并说明**，不静默等待 |
| R4 | **panel scope 让同机任意进程等于半个操作员** | 那台机器上的恶意/失控程序能读对话、派活到别的机器 | 决策 A 的三条硬规则（减五类管理动作 / 只能总机侧改 / 判定按身份）＋ 总机设备页可见 scope ＋「忘掉即吊销」＋ 向导里明写风险，让用户为公用机主动选「只当算力」 |
| R5 | **总机与节点的版本错位** | 旧总机不认识 `scope` → 静默降级成"能看面板"或"完全不能看"，两种都坏 | `E2050` 明确拒绝并提示升级，**不静默降级**（P1-1） |
| R6 | **瘦客户端成了单点**：总机关机/断网，那台机器的班底就成了错误页 | 用户以为"软件坏了" | §6.3 说明页三出口（重试 / 换一台 / 退出回本机）＋ 文案写明"可能关机了"，而不是丢一句 network error |
| R7 | **退出总机后误以为数据丢了** | 支持成本 + 信任受损 | 退出确认里第②句就写"原来的数据一个没少"；退出后第一次打开给一条「已回到本机数据」的短提示 |

## 十、给架构的一句话

**新增的东西只有四块**：① 总机侧一个 UDP 8788 应答器（挂在 `netmode` 的开关后面）；② `apps/server/src/discover.mjs`（节点侧扫描）；③ 三到四个 `/api/local/*` 接口（探测地址 / 扫描 / 加入 / 退出）＋ 邀请码 join 的 `scope` 字段；④ 桌面壳启动时的一处分支（已加入且有 panel → 不起本地控制面、窗口指向总机）。**没有新表**（`nodes` 加一列 scope 即可）、**没有新依赖**、**不动既有节点协议**（心跳/领活/回执一行不改）。前端是 `app.js` 里新增一个「这台机器」分区 ＋ 一个五步对话框 ＋ 一张连不上时的说明页。
