# 局域网加入总机 · 增量 PRD 1

> 版本：2026-10-20 ｜ 前置阅读：`docs/prd/2026-10-20-局域网加入总机.md`（下称「原 PRD」）、`docs/形态决策.md`、`deploy/README.md`
> 本增量只写变更，不重写原文。原 PRD 未提及的条目全部照旧。

## 一、变更背景（两条用户原话）

1. 「加入向导的弹窗，得跟系统其它弹窗一个样子。」—— UI 规范问题：向导是裸 `document.createElement('dialog')`（`apps/web/app.js:2559`，`joinwiz-dlg`），没走项目对话框通用件（`app.js:439-453`：动态建的对话框必须调 `wireDialogHead(form)` 才有 `.dlg-head` 吸顶头 = 标题 + ×）。
2. 「这台机器不一定是要加入局域网，也需要加入云端服务器。」—— 产品口径问题：原 PRD 把「局域网」当成加入的前提，但形态决策的终局本来就是托管控制面，`deploy/README.md` 已验证「云端控制面 + 本机节点连出」。**总机 = 任何可达的班底控制面；局域网自动发现只是候选来源之一，不是前提。**

---

## 二、变更 1 · 向导弹窗接入系统统一弹窗组件

**目标**：向导与系统其它弹窗（如 `memberDlg`）视觉与交互一致；`joinwiz-*` 只保留内容层样式，弹窗外框一律复用系统 dialog 样式类。

**需求条目（P0）**

| # | 要求 |
| --- | --- |
| UI-1 | 向导改用 `<form method="dialog">` 包裹（回车提交 / × 关闭语义与其它弹窗一致），弹窗外框套系统 dialog 样式类 |
| UI-2 | 建完调 `wireDialogHead(form)`，得到 `.dlg-head` 吸顶头（标题 + 右上角 ×）；× 的 `type="button"` |
| UI-3 | 每一步切换时更新头部标题（如「加入总机」→「加入「办公机」」→「这台机器用来做什么」），标题仍由原步骤逻辑写 `<b>`，头部搬移逻辑不重复造 |
| UI-4 | `style.css` 里 `joinwiz-*` 清理：只保留步骤内容（列表、 radio、提示条等）样式，去掉自制的标题栏 / 关闭按钮样式 |

**验收标准**

1. 向导右上角有 ×，点 × 等价于取消（不落任何配置、不留半成品状态）。
2. Esc 行为与其它弹窗一致（关闭 = 取消）。
3. 向导内回车触发的语义与其它弹窗一致（表单提交，不会误触 ×）。
4. 从步骤 1 走到步骤 6，头部标题跟着步骤变，长内容滚动时头部吸顶不动。
5. 多步间来回（回退 / 重试）头部不重复、不出双标题（`wireDialogHead` 防重入生效）。

## 三、变更 2 · 「加入总机」不假设局域网——云端服务器也是加入目标

**目标**：产品口径从「加入局域网里的总机」改为「加入任何可达的总机（局域网 / 云端）」。发现仍是局域网能力，手填地址天然支持云端；修掉因此暴露的真 bug 与硬绑文案。

**已核实的技术事实（供架构师与工程师用）**

1. **真 bug**：`apps/server/src/local-mode.mjs:316` 用 `body.allowLan !== true` 判 `E1091`。云端控制面用 `BANDI_HOST=0.0.0.0` 显式监听（`explicit=true`），设置页那个「局域网」开关根本不显示、值为 false → **探测一台正常开放的云端总机会被误报「没打开局域网开关」**。
2. **传输层不用改**：`client-proxy.mjs:212` 已按协议选 `node:http`/`node:https`；`local-mode.mjs:274-278` 地址归一化已认 `https://`。云端 TLS 场景直接可用。
3. UDP 应答包（设计 §13.3）已有 `joinable` 字段；HTTP 探测（`/api/hello`）**没有**对应信号。
4. 文案把「局域网」焊死的位置：扫描页「正在找局域网里的班底总机…」、兜底页三条原因、`E1091` 文案、地址示例只有 `http://192.168.1.9:8787`。

### P0-A · 可加入与否由总机自己声明（修 E1091 误报）

| # | 要求 |
| --- | --- |
| A-1 | `/api/hello` 返回 `joinable` 布尔字段：**监听非回环 && 加入功能可用**（含 `scope` 能力）。UDP 应答包的 `joinable` 语义向它对齐 |
| A-2 | 节点侧探测不再读 `allowLan` 开关值来猜，只认 `joinable` |
| A-3 | `E1091` 文案改为中性、不提「局域网开关」；开关仍是局域网场景下控制 `joinable` 的总闸（开关关 → `joinable=false`），但节点侧不知道也不关心开关 |

**验收**：探测一台 `BANDI_HOST=0.0.0.0` 的云端总机 → 正常通过，不再报 E1091；本机模式（回环监听）总机 → `joinable=false`，E1091 触发；旧总机（无 `joinable` 字段）→ 走 `E2050` 版本太旧路径，不静默降级。

### P0-B · 文案去「局域网」硬绑定（全文案如下，直接可用）

**B-1 扫描页（步骤 1）副句**：

```
正在找同一网络里的班底总机…
已经找了 3 秒 · 同一网络里的班底会自动应答
总机在云端、或不在同一个网络时不会出现在这里 —— 可以直接填它的地址
```

**B-2 兜底页（步骤 3，三条原因 + 地址示例）**：

```
没找到总机。通常是这几种情况：
 · 那台电脑上的「允许局域网内的机器加入」没打开
 · 两台电脑不在同一个网络（一个连 Wi-Fi、一个插网线也算）
 · Windows 防火墙拦了发现用的端口（不影响手填地址）
 · 总机在云端（公网 / 域名）—— 自动发现只覆盖同一网络，这种情况直接填地址

可以直接填总机地址，局域网或云端都行：
 ┌────────────────────────────────────┐
 │ http://192.168.1.9:8787            │
 │ https://bandi.example.com          │
 └────────────────────────────────────┘
 局域网：地址在总机那台电脑上：设置 → 运行时 →「连接地址」
 云端：用部署时给你的域名 / IP（https:// 开头）
```

**B-3 探测失败文案（步骤 4）**：

- `E1091`：`这台班底没有对外开放加入（它可能只在本机使用）。去那台机器上确认，或问总机的主人`
- `E1092` 保持「连不上 …核对地址与端口」不变（本来就没提局域网），但把示例地址补成两种。
- `E1090`、`E2050` 不变。

**B-4 地址归一化报错**（`local-mode.mjs:266/272/275`）：示例补 `https://bandi.example.com`；`275` 行「局域网里就是 http」改为「云端部署用 https:// 开头的地址」。

**验收**：全局搜「局域网」在向导相关文案里只剩「允许局域网内的机器加入」（开关名，保留）与扫描页副句（描述发现这一事实）；兜底页四条原因、两种地址示例均出现；`E1091` 新文案不含「局域网」字样。

### P0-C · 「记住上次总机」从 P1-2 提级 P0

**理由**：云端没有发现，重连全靠这条记录；没有它，云端用户每次断线重连都要重新手填地址。

| # | 要求 |
| --- | --- |
| C-1 | 成功加入时记录 `instanceId + label + 地址`；下次打开向导，扫描页直接置顶显示「上次加入过：<label>（<地址>）」，一键选用 |
| C-2 | 选用上次记录后仍走完整探测 + **新邀请码**流程（记录只是省去填地址，不省鉴权） |
| C-3 | 存储位置（本机 localStorage vs 数据目录文件）由架构师定；产品只约束：① 只存一台（与「一个总机」边界一致）；② 退出总机时清除该记录；③ 记录里的总机探测不通时按 `E1092` 正常报错，不静默清掉 |

**验收**：加入云端总机 → 退出 → 再开向导，扫描页顶部出现「上次加入过」条目；点它 → 直接跳到探测/输码步，无需手填；退出总机后该条目消失；记录指向的总机关机时点它 → `E1092` 文案正常。

### P1-D · UDP 候选列表标签去局域网绑定

候选列表里「未开局域网」置灰标签改为「**未开放加入**」；副文案改为：「这台班底没有对外开放加入（可能只在本机使用）。若是局域网总机：去那台机器上打开『允许局域网内的机器加入』→ 点重启」——对云端显式监听但未开放的总机，不再指向那个开关。

**验收**：候选列表不再出现「未开局域网」字样；本机模式总机的候选行显示「未开放加入」；云端显式监听且开放的总机显示「可加入」可点。

## 四、不做清单（维持原边界 + 新增一条）

原 PRD §七全部照旧，另明确：

| 不做 | 为什么 |
| --- | --- |
| **因为云端就改跨网段扫描 / 互联网发现** | 云端 = 手填地址 + 上次记录（P0-C），够了。发现永远是「同一网络」的局域网能力 |

## 六、结论

一句话：**向导弹窗补上系统对话框规范（变更 1）；「总机」的口径放宽为「任何可达的班底控制面」，云端是手填 + 上次记录，局域网发现只是候选来源之一（变更 2）。** 最大的一个必须先修的是 `local-mode.mjs:316` 的 E1091 误报——它会让第一台正常部署的云端总机在向导里看起来是坏的。
