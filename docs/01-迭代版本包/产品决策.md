## v1.5（2026-10-31 ~ 11-18）

### 2026-11-17 · 手机壳跟面板主题

换原生壳后那三屏（登录 / 设备列表 / 兜底）写死浅色，面板一开深色就一深一浅两截。

- **定**：面板 `applyTheme` 把**解析后的深浅**（布尔）报给壳，壳存进 SessionStore（`panel.theme.dark`），原生屏按它铺；没报过（新装）跟系统。报布尔不报 light/dark/system 三态——「跟系统」网页已用 `prefers-color-scheme` 解析完，壳再猜只会猜错。
- **机制**：`configChanges=uiMode` 下自动重建不可靠，壳自己持配置上下文，视图/取色/窗口背景全从它解析；只在原生屏要露脸时换挡，面板露着时报话**只存不铺**。
- **代价（接受）**：面板开着改主题、再点「当前设备」撞上翻档时 WebView 重建，滚动位置与未发送输入丢失——一个 rare 路径，换其余全部时刻的连贯。

### 2026-11-16 · 生图服务退场，头像改「规范 + 会话侧出图」

- **撤**：服务端生图模块与 HTTP 路由（`imagegen` / `imageai`）、鉴权里 `/api/ai/*` 回环免令牌的特例、设置页「生图服务」卡片；`skills/bandi-avatar` 整份删档（通篇是「先确认通道 → 生图 → 裁水印」的工序手册，通道没了第一步就撞 404，留着比删掉更坏）。
- **现行**：头像走固定 prompt（现收录于 [bandi 产品设计说明书「7. UI 设计约定」](../00-项目总基线/00.2 总体设计/bandi产品设计说明书.md)），由对话侧的生图能力出图，产物与绑定路径不变。
- **代价（接受）**：平台不再有「本机一键生图」，风格从**服务保证**降为**规范保证**，也不再有平台侧用量闸。
- 动因未在本仓留痕（口头定的），这里只记退场后的口径与代价。

### 2026-11-16 · CLI 详情页撤销

点运行时名字进的那页要手填可执行路径、沙箱模式、「跑不了命令」清单——英文技术词对用户要求太高，而路径已能识别、档位已由出厂配置定。

- **撤**：整页，以及它独占的 `PUT` / `DELETE` 运行时、`POST .../runtimes/:id/probe` 三个接口与 route-policy 条目。
- **留**：列表上的识别 + 接入开关；`PATCH` 保留（启停、自愈测试手工改路径都走它）。

### 2026-11-16 · 额度功能退场

`quota.mjs` 删除，`server.mjs` 直连 `store.db` 那句也不在。SQL 收口时记的「换库代价 3 处」是当时的账，不是现状。生图与额度同批退场。

### 2026-11-12 · 群里成员之间 @ 也算派活

**起因（实报）**：群里 @马超 派活，人一动不动。查库 0 run、0 失败通知——不是跑挂，是从未被唤醒：派活只认「人发的消息」，成员自己的回话落库后没有任何扫 @ 的逻辑，而给统筹岗的合同却写着「在群里 @ 具体执行人接活」。

- **定**：成员的回话里 @ 到的成员会被唤醒。触发消息就是那条回话本身，不另造一条「替谁说话」的用户消息（否则同一句话界面上出现两遍）。
- **防环四条**（缺一条两个 agent 会聊到天亮）：跳数上限（人发 = 第 0 跳，默认最多再 2 跳）、不回打（刚叫醒你的人这轮 @ 他不算）、同批不互叫、只接力第一个被 @ 的人。
- **只入队不直接起跑**：接力发生在上一轮收尾那一刻会话还占着，交给 `drainGroupQueue` 做并发判定与补派——两套并发判定迟早打架。
- **代价（接受）**：agent 在回话里随手 @ 一串人就会真叫起一串人（各花一次钱），所以平台契约写死 @ 只有两种用法：真让他接活 / 真让他看。

### 2026-11-09 · 多机子系统彻底删除

用户拍板「根本没有存量机」，整套退场。

- **删**：邀请码加入、节点令牌（`bn_`）、报到/心跳/领活、节点任务派发、总机/分机切换、分机客户端进程（`node.mjs`）。
- **留**：本机软件商店安装通道，改名 `/api/local/tasks`（`nodeId` 恒 `'local'`）。
- **库**：`nodes` / `node_tokens` / `node_invites` / `node_jobs` / `node_paths` 五表 DROP，`node_tasks` 保留。

### 2026-11-07 · 本机不做账号分级，登录即全权

- **撤**：本地账号体系（三态登录页 / OTP / scrypt / 失败锁定）、换票链（`at_` / `rf_`）、引导头、角色与菜单权限整套、「最后一个管理员」那组保护。
- **为什么**：账号已经在中枢，本机再分一级没有理由；单兵作战，分级权限的存在前提（多人/多机协作时的可见性收敛）消失了。
- **现行**：认证在中枢，授权在本机，而本机的授权只有一个答案——登录即全权。
- **重议条件**：真出现「多人共用一台机器、某人只该看见自己的会话」。

### 2026-11-07 · 不做「认领 + allow 放行」的第二道闸

- **撤**：`bandi hub allow/revoke`、认领待批字段、对应的「没认过」语义（只剩「票过期」）。
- **为什么**：第二个中枢账号在登录页被挡住、文案指路一条 CLI 命令——用户不会为了登录去执行一条命令。
- **现行**：中枢验过票/密码 = 授权完成；第一张票建内置影子账号（防锁死锚不变），之后每个中枢账号各建自己的。
- **已知取舍（拍板接受）**：中枢被攻破 = 伪造票可进所有机器，防线只剩钉公钥一条。要改先想清楚这条。

### 2026-11-07 · 手机不做配对令牌，只走中枢登录

- **撤**：一次性邀请码/二维码、`bd_` 设备令牌、设备身份与几十条 `device: true` 白名单、设备表、配对路由、扫码落地页、桌面「手机连接」设置分节、vendored 二维码库。
- **为什么**：两套身份并存（一机一机的「门卡」 vs 跨机器的「身份证」）会让「我是谁」有两个答案；扫码进来的手机署名记到机器主人头上，跟「hub 唯一身份」拧着。
- **现行**：手机 = 中枢登录后的一台客户端（用户身份，登录即全权），窄屏形态由面板自己判，不再有第三种身份。
- **存量**：老库的手机表不再读写，旧设备 Cookie 认不出来（401）。

### 2026-11-07 · 手机壳换原生，但面板不原生重写

- **撤**：Tauri / WebView 版壳冻结退役。
- **起因**：反复弹的存密码窗是小米密码保险箱的系统悬浮窗，不尊重 View 层排除标志，App 层四刀全无效；换壳到原生让登录落在原生层，弹窗触发条件从根上消失，CSP / 键盘 / 返回键 / 安全区四类补丁也整体不需要。
- **否决的方案**：面板 UI 全面原生重写——几个月起步，且从此永久维护两份 UI。
- **现行**：原生壳（Kotlin，零第三方依赖），WebView 只在签票进门后承载**已登录**的面板；产品 UI 仍单一来源。

### 2026-11-07 · 不做协作中心 / 分公司

- **撤**：协作中心整套（后端路由与存储、前端分节、看板上「派到分公司 / 验收 / 撤销」那套派活 UI）。
- **为什么**：都是单兵作战，不需要相互协作了。
- **存量**：老库里的协作卡照常显示、可拖可删，不再产生新的。

### 2026-11-07 · 外网访问走中枢转发，隧道用 frp

- **定**：机器主动出站连中枢，中枢经 frps 把公网请求转回来；用户只做「装软件、登录」，不买域名、不开端口、不装客户端。
- **为什么不自写隧道**：自己那版只算得清帧协议（约 500 行），算不清重连、背压、SSE 长连接不断、限速、证书、审计——两周起步 + 半年补 bug。frp 这几样是成熟实现，且 Apache-2.0、活跃迭代。
- **为什么不做端到端加密**：手机壳加载的是中枢下发的远程页面，JS 能被换掉，Web 形态下做不到。文案只写「只转发、不落盘、日志只记元数据」。
- **现行**：中枢下发隧道配置（心跳可改派 / 撤销），客户端生成 `frpc.toml` 并管进程；隧道域名自动进 Host 守卫与写来源白名单，用户不用碰 `BANDI_ORIGINS`。
- **代价（接受）**：安装包每平台 +15~20 MB；流量过中枢，带宽成本在自己这侧；电脑休眠就是连不上。
- **重议条件**：要做按流量计费 / 多租户强隔离 / 端到端加密时换成自写隧道——只改隧道模块的三个动作，业务代码一行不动。

### 2026-11-05 · 大文件先不拆，但有到点就拆的条件

- **口径**：边界没稳就拆，划出来的线是凭想象划的、十有八九要重划——上一轮「服务端按域拆分」搬代码就漏改过路径。**常改恰恰是缓拆的理由，不是急拆的理由。**
- **到点就拆（不再议）**：仓库模块长出第二类消费者、或下一段功能落进「建 PR 写侧」→ 拆独立模块；工作流模板/实例再膨胀过 2000 行 → 先拆「视图」段。

### 2026-11-04 · 不代装运行时，只识别

- **撤**：界面「一键安装」整条链（确认框 / 任务排队 / 进度轮询 / 复制命令）、「按路径接入」弹窗、服务端安装任务分支、运行时对象上的 `install` 字段与生成函数。
- **为什么**：替用户跑安装命令的坑太多——npm 不在 GUI 进程 PATH、`spawn .cmd` EINVAL、装完路径对不上还得手动点识别。一键只省「敲一条命令」，而实时 PATH 探测已让**装完即见**。
- **Claude Code 专门评估过**：官方原生安装器技术上够得着，但官方没有可用镜像——最需要一键的场景（网络不通）恰恰会超时，最后还是降级成复制命令。安装一次性、识别常驻，不值得背这套维护面。
- **也别加定时扫描**：识别是页面加载时 stat-only，配实时 PATH 已够。
- **留**：相关契约按「无 UI 消费」保留（有登记，别当死代码删掉）。

### 2026-11-03 · 缺省对外监听

缺省从「只听回环」改成 `0.0.0.0`，回环只剩显式配置的调试形态。手机和远程客户端永远能连进来，让不让进由鉴权与开关管，不由监听地址管。

### 2026-11-01 · 端口固定 18787，绝不偷偷挪

- **推翻**：此前桌面壳「从 8787 往上自己挑」的做法。端口被证明不是壳的内部细节——进了配对链接、服务描述、局域网来源守卫；手机记住的是带端口的地址，换端口 = 已配对手机全断，而两个进程还会共用一个库（WAL 双写）。旧实现「认自己人」吃命令行，读不到就当外人 → 明明有自己人还换端口起第二个。
- **定**：固定 **18787**（高位，避开 8787 那一带），只做三选一——有活着的自己人就复用、空着就起、被别人占就报 ALIEN 退出，**绝不偷偷挪端口**；环境变量仍可显式覆盖。

### 2026-10-31 · 鉴权按请求现算，账号体系上线

- **推翻**：「只看监听地址决定要不要令牌」那条——改成按请求现算（四类来源同时成立才放行）。
- **账号体系已做**：浏览器面板走账号登录，令牌退为机器凭据，登录页上不再有令牌输入框（别按「填令牌」找入口）。
- 2026-11-07 又一轮：本地账号/角色菜单整套退场、登录即全权（见上）。

## v1.3（2026-10-28）

### 2026-10-28 · 降级：单机是主线，总机退为可选实验

- **结论**：把多机协同从产品主线降为可选实验。每台机器跑完整的单机版——**一台机器 = 一个完整实例 = 一份数据**；远程访问用**隧道**解决（tailscale / cloudflared / frp 三选一），中心只转发、不存状态、不派活。
- **判据**：状态在总机、文件在节点 → 总机每加一个功能，就多一个「节点上怎么用」的窟窿（项目工作区、路径、连接器/MCP、仓库、瘦客户端都踩过）。
- **处置（当时不删代码）**：节点协议保留但冻结，加入入口标「实验」并收进设置，单机功能与隧道前提不动。观察期 2–4 周，回退随时能开。
- **后续**：2026-11-09 观察期结论是彻底删除（见 v1.5）。

## v1.1（2026-10-20）

### 2026-10-22 · 前端拆 ES 模块，不换 React

真正的痛点是那个单文件前端（一个文件 345 KB / 7683 行），不是「没用框架」。要动就拆 ES 模块（浏览器原生支持、不用打包器，保住零依赖），收益接近而风险小得多。

- **已按这条拆完**：拆成入口 + `js/*.mjs`，仍是原生 ESM、无打包器。大单文件的问题已解决，结论（不换 React）不变。

## v0.9（2026-10-16，首个公开版本）

### 2026-10-18 · 数据落点收敛为单一默认

- **推翻**：此前「桌面版指用户目录、命令行仍默认仓库 `data/`」的折中——同一台机器两个库（命令行空库、桌面真实库），看错库是常事；「开发版不碰真实数据」根本没成立。
- **定**：默认只有本机用户目录，仓库 `data/` 只作显式沙盒。启动日志打出数据目录与库路径——「我在看哪个库」不该靠猜。
- **刻意不做**「写不进去就自动换家」的兜底：那会在权限抖动时悄悄换成空库，比启动失败糟。

### 2026-10-16 · 服务端不上 Cloudflare，只接 Tunnel

- **结论**：整台服务端不适合搬上 Workers——它是换了个运行时模型：`node:sqlite`（同步）、文件系统、子进程、挂起式长轮询、常驻定时器、能跑半小时的 CLI，Workers 这几样都没有或有限制。
- **能搬的（如果哪天真要托管）**：静态前端、队列与推送（Durable Object）、存储（D1，但同步改异步是重写）。
- **真正有用的**：Tunnel（不开端口、自带 TLS、零代码改动）与 R2 当备份落点。Cloudflare Access 能补「共享令牌不是账号体系」那个弱点。
- **执行端永远不该上云**：代码、凭据、CLI 会话都在用户机器上，控制面只存编排数据。

### 2026-10-15 · 技术选型复审

目标变了（本地工具 → 托管控制面 + 多机客户端），四层重过一遍。

- **不动，而且是资产**：执行端适配层（各 CLI + 统一事件词汇）、服务端 `node:http` + SSE（零依赖）。
- **存储继续用 `node:sqlite`，但先收口**：数据落点可配且默认到用户目录；SQL 收口到 store 一处；实验特性记录在案，暂不换库。换 Postgres 解决不了任何一条，只会把代价放大。
- **客户端装配选 Tauri + 内嵌 Node**（已有壳、Rust 侧写得少；Electron 体积接近上限）。
- **控制面 ↔ 节点不引 WebSocket**：Node 没有内置 WS 服务端，自己实现握手+分帧是两百行易错代码，引依赖又破「零依赖」。用挂起式长轮询 + 事件批量上报，纯 `node:http` 就够。
- **前端不换 React / 框架**，见 v1.1。

### 2026-10-15 · 形态三件与边界

**不是 web 还是桌面——是控制面放哪、执行面怎么连上来。** 定三件：控制面托管；客户端出站连接；单机零外部依赖（同一份代码，单机时控制面就地跑，用户看不见「节点」这个概念）。

- **权威边界（最要紧的一条）**：workspace / 任务队列 / 审计在托管；代码、私钥与 CLI 凭据、文件路径是否存在——**只在本机**。对外一句话：代码和密钥一个字节都不离开你的机器。
- **单机 → 团队：认领，不做同步**。第一次登录 = 把本地 workspace 导上去，本机那份降为副本，一次性、单向、不回头。为什么不做双向同步：冲突解决是这类产品里最贵、最容易做错的部分，认领把这个问题整个删掉。
- **不做什么**：浏览器当执行器、SSH 优先的远程执行（降为一种传输兜底）、控制面 ↔ 节点的双向同步、P2P/NAT 打洞、30s 轮询为主、单机要登录才能用。

### 2026-10-15 · 实施落地

- **消重复**：删掉第二套前端，壳改薄壳不打包界面资源、窗口直接指向本地控制面。
- **事件流落库 + 断线只补缺口**：新表 append-only，SSE 带 id、服务端读 `Last-Event-ID` 只补缺口（此前全量重放会把回话重复追加）；跨重启可回放；清账给被中断的运行补终止事件。
- **节点最小切片**：报到 + 心跳 + 掉线可判（心跳 15 秒，45 秒收不到判离线，容忍一次丢包）。身份认文件不认主机名（主机名会改、会重名，认它就会攒僵尸设备）。
- **节点领活**：长轮询挂 20 秒；事件批量回传，响应带回 `stop` 作反向控制通道；回执走与本机同一个收尾函数；离线排队是队列的默认状态；掉线清扫按「有没有动静」分放回队列 / 判中断。踩过的坑：长轮询要盯 `res.destroyed`（请求体读完恒为 true 的 `req.destroyed` 不能用，`close` 事件不触发），空批次也要回 `stop`。
- **部署实测**（一台 Ubuntu 小机）：无 root、无 Node、无 git，Node 装用户目录、代码 tar + scp、数据放代码目录之外；零依赖跑通控制面，SSH 隧道与公网直连都通，跨机节点报到与掉线过期都验证。
