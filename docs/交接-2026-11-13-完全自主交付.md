> 状态：**Phase 1 已落地、冒烟全过**。本文是「做完留档」，具体口径见

## 一、这次要解决的问题

用户拍板：**完全自主、人不拍板**。例如让数字员工自迭代班底项目、检查设计漏洞，
项目经理（PM）组织讨论 → 定方案 → 施工 → 最后把结果汇报给雇主；人不逐步点「通过」。

引擎原本已有「非 `manual` 节点跑完自动 `decide('通过')` → 自动派下一步」的能力，
所以**没有另写一套流程引擎**。这次补的是：PM 能起「由流程执行」的卡、一条无人工闸且按岗位点名的
自主模板、实例终态/受阻自动写信箱汇报、契约口径与验收冒烟。

## 二、已完成

1. **建卡通道**：`apps/server/src/routes/agent-cards.mjs` 接收 `flowTemplateId`；
   单卡 `startNow` 与批量 `needsStart` 都把「由流程执行」算作一种执行方式——否则 PM 立的卡
   建完停在待办，不会真起流程实例。卡上记 `flowTemplateId` / `flowRunId`。
   （基线提交 `d2c17c1` 已加字段；本次修的是「建完即起」。）
2. **自主模板**：新增 `apps/server/src/self-delivery.mjs`，模板 id
   `bandi-self-delivery`，服务启动时由 `server.mjs` 调 `ensureSelfDeliveryTemplate()` 播种并发布。
   7 步：PM 需求澄清 → 架构师方案 → 研发设计评审（找漏洞）→ 研发施工 → 测试自测 →
   `pr-create` 动作节点 → PM 汇报 → `end`。**全节点无 `manual`**，按 `roleKey` 点岗位，
   不含 `pr-merge` / 部署节点。播种幂等；用户接管（清 `builtIn`）后不再覆盖。
3. **按岗位指派**：`apps/server/src/workflows.mjs` 的 `assigneeFor(node)` 在 `personaId` 之外支持
   `roleKey`——按岗位找一个该岗位员工；没配到人仍到站即「已阻塞」，不按技能偷偷挑人。
4. **自动汇报信箱**：`workflow_templates.autonomous = 1` 的实例，终态（`done` / `terminated`）
   收口在 `settleRun()`；任务级 `[受阻]` / 失败 / 停止生成由 `onAgentRunFinished` 触发；
   平台侧卡住（没岗位、未知动作、动作抛错 / `finishActionTask(ok:false)` 自报失败、
   派活准备/派活失败、额度闸）也在各自挂点汇报；动作失败统一收口，不重复写状态或刷屏。
   写一条 `kind='workflow.delivery.report'`，code 分别 `WF_DONE` / `WF_STOPPED` /
   `WF_FAILED` / `WF_BLOCKED`，`dedupeKey = wf:<实例id>:<状态>`。完成态把 PM 最后一步的
   交付汇报正文与 PR 链接带给雇主；实例 id 放 detail 与 dedupeKey，
   **不占 `notices.runId`**（那个字段是「哪一轮 agent 执行」）。前端 `inbox.mjs` 显示为「自主交付报告」。
5. **PM 提示**：`dispatch.mjs` 的 `pmCardBrief` 注入自主交付建卡卡例，告诉 PM 用
   `flowTemplateId: 'bandi-self-delivery'`，不要逐节点手工点通过。
6. **存储迁移**：`store/db.mjs` 的 `SCHEMA_VERSION` 9→10，新增
   `workflow_templates.autonomous INTEGER DEFAULT 0`（旧库存量模板都是 0 = 普通流程）。
   `store/workflows.mjs` 的 `upsertWorkflowTemplate` / `renameWorkflowTemplate` 保留该列，
   新增 `setTemplateAutonomous()`；`ensureSelfDeliveryTemplate()` 每次启动给旧库里
   `builtIn` 且该列为 0 的内建自主模板补 1。SQL 只留在 `store/`。
7. **文档**：`docs/契约.md` 第四节补「自主交付」段落与部署补充说明，第五节「只认点名」补
   `roleKey` 口径；新增 `docs/design/2026-11-13-完全自主交付-设计.md`；本文。
   `tools/check-doc-drift.mjs` 把本文作为时间点快照登记，否则全量门禁的文档对账会红。
8. **冒烟**：新增 `apps/server/src/smoke-self-delivery.mjs` 并登记 `tools/run-smokes.mjs`。
   临时数据目录 + 临时库 + 同进程临时端口，不碰真实库、不烧模型、不联网。
   覆盖一个实测修掉的坑：派活准备段（工单会话/经办人已离职）抛错时，原实现会让任务
   永远停「进行中」且不汇报；现已把整个准备段纳入同一失败收口。

## 三、怎么触发

PM 运行钥匙（`X-Bandi-Run-Token`）走批量建卡口：

```http
POST /api/agent/cards/batch
X-Bandi: 1
X-Bandi-Run-Token: <该轮 PM 的运行钥匙>
Content-Type: application/json

{
  "cards": [{
    "title": "自迭代班底、查设计漏洞",
    "description": "范围 / 验收标准",
    "projectId": "<项目 id>",
    "flowTemplateId": "bandi-self-delivery",
    "status": "todo"
  }]
}
```

卡必须挂项目；建完即起流程实例。到站按岗位派活，非 `manual` 节点跑完自动放行，
平台 `pr-create` 动作节点建 PR，PM 最后写汇报；实例收尾/受阻另写一条信箱报告给雇主。

## 五、红线（别越）

- **不自动合并 PR、不部署、不对外发布、不花钱**；「部署永远要人下令」「验收权不下放」没改。
  自主模板里没有 `pr-merge` / 部署节点，交付物是 PR + 报告，合并/上线由雇主择时。
- 普通流程（`autonomous=0`）一行行为没变；`manual` 节点仍要人放行，信箱只接原来那些 kind。
- 运行钥匙**未**放开 `workflow.decide` / `workflow.start`；自主靠「无 `manual` + 自动流转」，
  不是给 agent 拍板权限。
- 只认点名：`personaId` 点人，自主模板用 `roleKey` 点岗位；**仍不按技能路由**。
- 不做多 agent 自由圆桌；跨步骤交接靠文档落盘，没新造 step 输出 → step 输入管道。

## 六、迁移 / 环境

- 老库打开一次自动加列：存量 `autonomous` 都是 0（普通流程）；内建
  `bandi-self-delivery` 由启动播种补 1。用户手动接管过的模板（清了 `builtIn`）不动它。
- 服务起来后工作台 → 工作流可看实例；信箱角标出「自主交付报告」。
- 冒烟自身隔离：`BANDI_DATA` / `BANDI_DB` 指临时目录，`BANDI_PORT` 默认 8851
  （可用 `SMOKE_PORT` 改）；环境变量必须在 import `store.mjs` / `config.mjs` **之前**设好，
  否则 `config.mjs` 模块加载时已冻住默认端口，会撞到正在跑的 18787 真服务。
- 运行钥匙是进程内 Map：E2E 冒烟必须同进程 import `server.mjs`，另起子进程签的钥匙验不过。
