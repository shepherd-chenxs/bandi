| 项 | 值 |
|---|---|
| 版本 | **v0.2**（重写，作废 v0.1） |
| 作者 | 主理人口述 + 李俊整理 |
| 状态 | 已拍板，待实现 |
| 需求来源 | 用户原话，见第一节（原话钉死指代，不再靠猜） |

## 〇、v0.1 为什么作废

v0.1 把「项目档案」默认建在了「项目面板」**插件**上 —— 两个撞名的东西没有先钉死指代，源头理解就偏了。实际是两回事：

- **项目模块**（左侧「项目」）：**通用工作区**。装修、写书、软件研发都能用它，不该绑任何软件研发专属的概念。
- **「项目面板」插件**：只做软件研发专属的事。

分工判据（主理人拍板）：**一个功能是否以软件仓库为前提 —— 是，归研发面板；不是，归项目模块。**

## 一、定位（用户原话）

> "项目这个功能就相当于建一个工作区。"
> "项目面板可以改名叫研发面板，专门软件研发项目做的插件。这两个定位应该是比较准确的吧。"

由此：**项目模块 = 通用工作区；研发面板 = 软件研发专属插件。两者不合并、互相不越界。**

## 二、改动清单（三项）

### 改动 1：插件改名「研发面板」

- 插件 `project-panel` 的展示名改为**「研发面板」**，定位文案改为"软件研发项目专属"。
- **只改展示名，不动插件 id / 目录名**（`project-panel` 保持，避免动引用链）。
- 涉及两份 manifest：`plugins/project-panel/manifest.json` 和 `apps/server/catalog/plugins/project-panel/manifest.json`；以及前端凡按「项目面板」字样渲染的地方（grep 全仓确认）。

### 改动 2：项目模块的「项目档案」撤掉「迭代版本数」

- 项目详情的档案区回归**四项**：干什么（简介）/ 项目经理 / 成员 / 开始时间（原起止展示保持现状）。
- 「迭代版本数」是软件研发专属概念（以仓库 `status.yaml` 为前提），按判据归研发面板，通用工作区不再展示。
- 后端 `version_count` 字段保留（研发面板的数据源），只撤项目档案 UI 里这一行。

### 改动 3：研发面板范围收敛

- 研发面板保持**只读** + 版本清单展示不变。
- v0.1 计划的"往插件里加项目档案区（五项）"**正式撤销** —— 档案属于项目模块，不进插件。

## 三、验收标准

| # | 标准 |
|---|---|
| A1 | 项目详情档案区只显示四项（干什么/项目经理/成员/开始时间），无「迭代版本数」一行 |
| A2 | 插件列表与详情里显示「研发面板」，旧名「项目面板」在 UI 上不再出现 |
| A3 | 研发面板的版本清单功能不回归（选已纳管项目仍能看到版本与版本数） |
| A4 | smoke 同步：`smoke-project-tasks.mjs` 的档案五项断言改四项；`smoke-project-profile.mjs` 版本数断言口径对齐（档案不再断言版本数展示，`version_count` 后端字段断言保留）；`smoke-status.mjs` 的 version_count 断言保留 |

## 四、不做什么（防止被当成遗漏）

- 不合并「项目模块」与「研发面板」。
- 不给通用项目（非仓库）添加任何版本 / 仓库概念。
- 研发面板不做任何写操作（部署、发布、改档案一律员工在会话里干）。
- 本版不做档案字段的可视化编辑改版（现有"改了自动存"机制保持）。
