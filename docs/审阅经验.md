# 审阅经验

> **这是判据台账**：哪些 PR 不该合、哪种验证不算数、哪些坑踩过。
> 谁读它：值班的 agent（仓库值班开审前先读一遍）。
> 谁来写：每次判断出一个**新的**判据就追加一条 —— 现象 → 判据 → 处置 → 来源。
> 规矩：**写具体**（指到文件、命令、行号），别写口号；与代码冲突时以代码为准，并把冲突改掉。

## 怎么追加

```markdown
## <一句话结论>
- **现象**：你看到什么。
- **判据**：凭什么这么判（指到文件 / 命令 / 既有决策）。
- **处置**：以后遇到怎么办（回复怎么说 / 打什么标签 / 直接建议关闭）。
- **来源**：哪次 PR、issue，或哪天踩的。
```

准入线：**只写已经能落到具体动作上的**。想不清怎么处置的，先放着，别把台账写成一堆感想。

---

## 1. 测试不许依赖开发者本机状态

- **现象**：`smoke-ssh.mjs` 断言本机 `~/.bandi/servers.yaml` 里有某台机器、还比对磁盘上的 `~/.ssh/*.pub`；
  ② 段无条件把真登记表拷进临时目录。换台机器（CI / 新同事）必挂，而且是在"拷贝"那一步 ENOENT 崩掉。
- **判据**：用例的输入必须是**它自己造的**（fixture）；只有它自己控制的路径才允许断言。
  真连 / 真机那类要么显式 opt-in（环境变量），要么不进 CI。
- **处置**：新用例里出现读 `os.homedir()`、`~/.bandi`、`~/.ssh`、真实 `data/` 下既有文件 → 打回，要求自带 fixture。
- **来源**：2026-10-16 交接存档里的拦路石；2026-10-17 改成 fixture ＋ `BANDI_SSH_LIVE=<别名>` 可选真连。

## 2. 零依赖是硬约束：出现 `package.json` 一律打回

- **现象**：PR 里加 `package.json` / 锁文件 / `node_modules`。
- **判据**：本仓库**一个 `package.json` 都没有**（[docs/架构.md](架构.md) 技术选型）——"零依赖、一个人能维护"是选型原则，不是巧合。
- **处置**：`tools/check-pr.mjs` 直接失败；要破例必须人拍板，并在 PR 里写明为什么。
- **来源**：2026-10-17 建 PR 闸门时定的第一条。

## 3. 地址白名单：新增任何外部域名都要说明来路

- **现象**：diff 里新增 `https://api.xxx-relay.com/v1`、改 `base_url`、catalog 里多一条连接器。
- **判据**：这个项目只在白名单里的地址上跑（白名单在 [`tools/check-pr.mjs`](../tools/check-pr.mjs)）；
  中转站 / 网关属于"往产品里引流"的高风险改动。
- **处置**：CI 失败 ＋ 评论里问"这个域名是谁的、为什么必须它"；答不上来就建议关闭。
- **来源**：2026-10-17，用户明确担心"第三方中转站被塞进产品"。

## 4. 看被删掉的行，比看新增的更重要

- **现象**：PR 号称"加了个校验"，diff 里同时删掉了几条断言 / 白名单项 / 边界判断。
- **判据**：删除往往才是真正的行为改变；[`tools/check-pr.mjs`](../tools/check-pr.mjs) 对"删 `check(...)` 断言"与"删整个用例"直接失败。
- **处置**：逐条问"这条为什么删"；答不上来打回。要整体重写用例的话，在 PR 里写明理由（那要人拍板）。
- **来源**：2026-10-17。

## 5. 文档与代码不一致 = 缺陷，不只是笔误

- **现象**：契约 / README 写着"部署永远要人下令"，而代码里 `manual` 一次都没设 —— 跑完自动流转。
- **判据**：**宣称的行为**与**实际行为**不一致，读文档的人（包括 agent）会照着错的做。
- **处置**：当 bug 处理：要么改代码、要么改文档，并在评论里指出哪一处对不上。
- **来源**：2026-10-17 收拾流程 / 契约那一轮（内建模板部署节点补 `manual: true`）。

## 6. "我测过了"不算证据

- **现象**：PR 描述写"本地测试通过""应该没问题"。
- **判据**：契约里的数字纪律（[契约](契约.md)「七、纪律」）：**命令 ＋ 完整输出 ＋ 基准**才算。
- **处置**：要求贴命令与输出；或者自己跑一遍，把输出贴在评论里。
- **来源**：契约既有条款，2026-10-17 写进来备查。

## 7. 改 CI 让检查变松 = 一票否决

- **现象**：PR 顺手改了 `.github/workflows/`（少跑一个用例、加 `continue-on-error`、把检查清单缩短）。
- **判据**：闸门是整个仓库的底线；它被改松之后没人会注意。
- **处置**：`tools/check-pr.mjs` 会标"需要人看"；评论里明确写出改了哪一段、为什么。
- **来源**：2026-10-17。

## 8. 不许只动文档就宣称修了 bug

- **现象**：issue 说"某功能坏了"，PR 只改了 README 的措辞，还写着 `fixes #N`。
- **判据**：文档改动不改变行为；`fixes #N` 必须能被复现验证。
- **处置**：打回，要求给出可复现的验证（命令 ＋ 输出）。
- **来源**：2026-10-17。

## 9. 平台行为以代码为准，别照信历史文档

- **现象**：`契约详解.md`（历史材料）说"内建模板的节点各自带 `skill`，按技能派人"——现行引擎早就改成只认点名了。
- **判据**：凡是描述**平台行为**的文本，真源在代码；历史文档里的路径 / 字段 / 编号可能整段过期（那份通篇用旧五类编号）。
- **处置**：拿不准就去读代码（`workflows.mjs`、`server.mjs`）或跑一次冒烟；发现文档与代码冲突，按第 5 条处理。
- **来源**：2026-10-16 收拾技能与契约（删掉 `契约详解.md`，契约改成"只留一份、随平台走"）。

## 10. **本地绿了不算绿**：门禁里不许出现"只在本机存在"的路径

- **现象**：`.github/workflows/pr.yml` 的 JSON 检查**硬编码了一份文件清单**，其中
  `.agents/plugins/marketplace.json` 在 `.gitignore` 里、一个文件都没被跟踪 → 本地有这个文件（本地全绿）、
  CI 的干净 checkout 里没有 → 闸门在 CI 上**必红 ENOENT**。（2026-10-17 第一个真 PR #1 抓到的，
  甚至不是人抓的，是跑起来之后红的。）
- **判据**：门禁 / 冒烟里引用的**每一个路径**，都必须能在干净 checkout 里找到。
  凡是"本机恰好有"的东西（数据目录、`.agents/`、`node_modules/`、`~/.bandi`），一律不能进判据。
- **处置**：用 `git ls-files` 枚举被跟踪的文件（本地与 CI 同一份集合），不要手写路径清单；
  真需要本机状态时，先 `if (Test-Path)` 否则跳过并在日志里说一句"跳过，因为本机没有"。
  顺带：本地跑 CI 里那段 PowerShell 时，**别在留了临时文件的目录里跑**，要在一个干净 clone 里验一遍。
- **来源**：2026-10-17，张坤（数字员工）跑"给 main 加分支保护"时把闸门跑红了才暴露；
  同一天修（`pr.yml` 改成 `git ls-files '*.json'`）。


## 附：红线（一票否决）

撞上任何一条，不用往下判，直接建议打回或关闭。

| 现象 | 为什么 |
| --- | --- |
| 出现 `package.json` / 锁文件 / `node_modules` | 本仓库零依赖是硬约束；引依赖要人拍板 |
| 新增第三方地址：中转站、网关、`base_url` 被改写、catalog 多一条连接器 | 最怕的就是"第三方中转站被塞进产品" |
| 冒烟用例被删、`check(...)` 断言被删、用例被跳过 | 测试被放松 = 后面的改动没人挡 |
| 改 `.github/workflows/` 让检查变少/变弱 | 闸门自己被人拆了 |
| 仓库里出现凭据：密钥、token、口令、私钥正文 | 泄漏不可逆 |
| 文档 / 注释宣称的行为与代码不一致 | 踩过：契约写着"部署要人下令"，代码里没有那个开关 |
| 只改文档却号称修了 bug | 典型"看起来做了事" |

**黄线**（要人拍板，值班的不下结论）：改鉴权 / 沙箱默认值 / 监听地址 / 数据目录与迁移 / 发布流程 / 版本号；大重构；动 `store.mjs` 的 SQL；一次改几十个文件。

## 附：三类回复模板

**① 值得做（要排期）**

> 看过了，这个值得做。我确认到的事实：<命令 ＋ 输出>。它排到 <版本 / 里程碑>，动手时在 issue 里同步。

**② 不值得做（必须说清判据）**

> 谢谢提议。这个不做，理由是 <一条具体判据，最好指到架构或既有决策>。
> <如果确实需要，给一条替代路径>

**③ 广告 / 引流（统一模板，只回一次，然后关）**

> 感谢关注，日后会出相关合作方案，敬请期待。

**打标签，不拉黑名单**：`needs-info`（缺信息）、`needs-work`（质量不够）、`wontfix`（不做）。
理由写进评论里 —— 黑名单没有审计、无法申诉，公开仓库里还会变成公关问题。
