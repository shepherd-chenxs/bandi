## 七、别重复踩的坑（都是真实事故）

1. 从 `messages` 判落款会虚高 —— `persistReply()` 会剥掉 `[完成]`，必须读 `runs.claim`。
2. `agentEnv()` 是 `{...process.env}`，`BANDI_DATA` / `BANDI_DB` 会一路传给 codex CLI；
   员工跑 `run-smokes.mjs` 时冒烟另起的 server 实例继承同一个临时库，启动 `reapStaleRuns()`
   会把**正在跑的 run 判死**。回归实例靠 `BANDI_SKIP_REAP=1` 跳过（真实 18787 不设，行为不变）。
3. `waitRunDone()` 只看 `status` 会读到 reap 留下的中间态（`failed|interrupted`），
   而 `finishRun()` 后真落款是 `failed|silent` —— 指纹必须带 `claim`。
4. **`COALESCE` 没坏**（11-22 实证题 4/5 最终是 `silent`），别再去改 `finishRun()`。
5. 模型额度墙（`stream disconnected ... Sign up for free ...`）是外部资源，代码修不了；
   报告用 `infraError` 只记事实。
6. 员工写 `test-clean.mjs` 之类的临时验证脚本是正常行为；旧复原逻辑看到 `??` 就 `exit 1`
   会把已算完的判分连同报告一起丢掉。
7. 平台防循环闸掐断**没有结构化字段**（`runs.error` 是空的），只在 `run_events` 留一条
   `type:'text'`；`8fc80b9` 已认那句固定文案，别再靠 `runs.error` 找它。
8. 中断回归会留下员工脏改动 —— 接手先 `git status` 再复原，别带着脏树跑下一题。
